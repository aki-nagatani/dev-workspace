# InBox 処理の例示

## 例

### 例1: URL形式（既存ノートへの追記）

**入力**: InBoxに `2026-01-27.md` があり、内容が `https://azukiazusa.dev/blog/new-design-tool-pencil`

**既存ノート**: Knowledge保存先ディレクトリ内の`Pencil.md`が既に存在し、以下のような構造になっている：

```markdown
# Pencil

## Knowledge
Pencilは、AIがUIデザインを生成できるデザインツール...

## 使い方
### Pencil(アプリ) x Claude Code(CLI)
1. 公式サイトからアプリをインストール
...

## 参照
- [Pencil公式サイト](https://www.pencil.dev/)
```

**処理**:

1. URL形式であることを認識
2. URLの内容を取得して分析
3. 内容を分析してジャンル、Knowledge（知識）、キーワードを抽出
   - ジャンル: 「Pencil」
   - Knowledge: インストール手順、プロンプトでのデザイン生成方法、MCPでのコード書き出し手順など、実際に活用できる知識
4. 既存ノート（Knowledge保存先ディレクトリ内の`Pencil.md`）を発見
5. **既存ノートの内容を完全に読み込む**
6. **既存ノートを最新状態へ集約**（§4）:
   - 「使い方」に追記可能な**新規の使い方**はそのセクションへ追加
   - 既存記載と**同一トピックで新情報が優先**される場合（手順改訂・設定変更など）は該当箇所を**上書き**
   - 「インストールとセットアップ」サブセクションを「使い方」内に追加（既存構造に合わせる）
   - 参照セクションに新しい Articles リンクを追加
7. フロントマターの`updated`フィールドを`2026-01-27`に更新
8. タグやリンクを付与（既存のタグは維持）
9. 処理した項目をInBoxノートから削除
10. **適用可能性の検討**（`## 適用可能性` → 開発プロジェクト / 仕事（本職）の2サブセクション）:
    - 例（開発）: Pencil をフロントエンドプロトタイプに活用できる可能性
    - 例（仕事）: 該当なし（UI デザインツール記事で Work 業務への直接接続が薄い場合）

**追記後の例**:

```markdown
## 使い方

### インストールとセットアップ
- MacOSとLinuxのみ対応（現時点）
- メールアドレス登録と確認コードでのアクティベーションが必要
...

### Pencil(アプリ) x Claude Code(CLI)
[既存の内容を維持]

### プロンプトでデザインを生成
- キャンバス左下の「Design with Claude Code」チャット欄からデザイン指示を入力
- 例: 「Create a login form with email and password fields, and a submit button.」
...

### Pencil MCPでコードを書き出す
- Pencilインストール時にClaude Codeに自動でPencil MCPが追加される
...
```

### 例2: WEBクリップ形式（既存ノートへの追記）

**入力**: InBoxに `2026-01-26.md` があり、内容が：

```markdown
---
url: https://example.com/python-decorator
title: Pythonデコレータの使い方
---

# Pythonデコレータの使い方

デコレータは関数を拡張するための機能です...
```

**既存ノート**: `Notes/Knowledge/Python.md` が既に存在し、以下のような構造になっている：

```markdown
# Python

## Knowledge
Pythonは高水準プログラミング言語...

## 基本的な構文
[既存の内容]
```

**処理**:

1. WEBクリップ形式であることを認識
2. フロントマターからURLとタイトルを抽出
3. 本文内容を分析してジャンル、Knowledge（知識）、キーワードを抽出
   - ジャンル: 「Python」
   - Knowledge: デコレータの使い方、実用的なパターン、ベストプラクティスなど
4. 既存ノート（Knowledge保存先ディレクトリ内の`Python.md`）を発見
5. **既存ノートの内容を完全に読み込む**
6. **既存の文章構造に統合する形で追記**:
   - 「基本的な構文」セクションの後に「デコレータ」という新しいセクションを追加
   - または、既存の「高度な機能」セクションがあれば、そこにデコレータの知識を追加
   - 参照セクションに新しいURLを追加
7. フロントマターの`updated`フィールドを更新
8. タグやリンクを付与（既存のタグは維持）
9. 処理した項目をInBoxノートから削除

### 例3: 手入力メモ形式（既存ノートへの追記）

**入力**: InBoxに `2026-01-26.md` があり、内容が：

```markdown
Cursorのショートカットキーについて

- Cmd+K: インライン編集
- Cmd+L: チャット開始
- Cmd+I: インライン補完
```

**既存ノート**: `Notes/Knowledge/Cursor.md` が既に存在し、以下のような構造になっている：

```markdown
# Cursor

## Knowledge
CursorはAI駆動のコードエディタ...

## 使い方
[既存の使い方の内容]
```

**処理**:

1. 手入力メモ形式であることを認識（フロントマターなし、URLなし）
2. 本文内容を直接分析
3. 内容を分析してジャンル、Knowledge（知識）、キーワードを抽出
   - ジャンル: 「Cursor」
   - Knowledge: ショートカットキーの使い方、効率的な操作方法など
4. 既存ノート（Knowledge保存先ディレクトリ内の`Cursor.md`）を発見
5. **既存ノートの内容を完全に読み込む**
6. **既存の文章構造に統合する形で追記**:
   - 「使い方」セクションが既にあるため、そのセクション内に「ショートカットキー」というサブセクションを追加
   - または、既存の「ショートカットキー」セクションがあれば、そこに新しいショートカットキーの知識を追加
   - 参照セクションは省略（手入力メモのため）
7. フロントマターの`updated`フィールドを更新
8. タグやリンクを付与（既存のタグは維持）
9. 処理した項目をInBoxノートから削除

### 例4: PDF形式（新規ノート作成）

**入力**: InBoxに `Python入門ガイド.pdf` というPDFファイルが配置されている

**処理**:

1. PDF形式であることを認識（`.pdf`拡張子のファイル）
2. Pythonの`pypdf`または`pdfplumber`ライブラリを使用してPDFからテキストを抽出
   - 例: `pypdf`を使用する場合

     ```python
     from pypdf import PdfReader
     reader = PdfReader("Python入門ガイド.pdf")
     text = ""
     for page in reader.pages:
         text += page.extract_text()
     ```

   - 例: `pdfplumber`を使用する場合

     ```python
     import pdfplumber
     with pdfplumber.open("Python入門ガイド.pdf") as pdf:
         text = ""
         for page in pdf.pages:
             text += page.extract_text()
     ```

3. 抽出したテキストを分析してジャンル、Knowledge（知識）、キーワードを抽出
   - ジャンル: 「Python」
   - Knowledge: Pythonの基本的な構文、実用的なコード例、ベストプラクティスなど
4. 既存ノート（Knowledge保存先ディレクトリ内の`Python.md`）を検索
   - **既存ノートが見つかった場合**: 既存ノートに追記（例2と同様の処理）
   - **既存ノートが見つからなかった場合**: 新規ノートを作成
5. **新規ノート作成の場合**:
   - Knowledge保存先ディレクトリ内に`Python.md`を新規作成
   - 抽出したKnowledgeを構造化して記述
   - フロントマターに`created`フィールドと`source`フィールドを追加
   - タグやリンクを付与
6. **PDFファイルの保存**:
   - Knowledgeノートと同じディレクトリに`attachments`サブディレクトリを作成（存在しない場合）
   - PDFファイルを`attachments`ディレクトリにコピーして保存（例: `attachments/Python入門ガイド.pdf`）
   - ノートの「参照」セクションにPDFファイルへのWikiリンクを追加（例: `[[attachments/Python入門ガイド.pdf]]`）
7. InBoxディレクトリ内のPDFファイルを削除
8. 処理結果を報告
9. **適用可能性の検討**（開発 / 仕事の2サブセクション）:
   - 例（開発）: Python 知識を FishTrack / MyPokedex の品質向上に活用
   - 例（仕事）: 該当なし、または Work ナレッジへの転用案

### 例5: 適用可能性の提案例（Docker記事の場合）

**処理した内容**: Dockerで開発して、AWSで本番運用する方法についての記事

**適用可能性**:

```markdown
## 適用可能性

### 開発プロジェクト

- **現状**: ローカル・本番とも Docker Compose + EC2、DB は RDS
- **検討**: ECS 移行でスケール・デプロイ自動化。マイグレーションを一時 ECS タスク化して API 停止を避ける案
- **注意**: Terraform / CI の更新コスト

### 仕事（本職）

- 該当なし（インフラ記事で PL 業務・Work/ 運用への直接接続が薄い場合の例）
```

### 例6: 適用可能性の提案例（非コーディング・ハーネス記事の場合）

**処理した内容**: MCP で Slack / Confluence 等を横断する業務エージェント向け Markdown ハーネス

```markdown

### 仕事（本職）

- **注意**: 重要ゲートは Markdown だけに頼らず、社内ルール・承認フローは人間側で維持

### 例7: 釣り関連ボイスメモ（音声 → 釣行メモ追記）

**入力**: InBox に `2026-06-14_三島湖.m4a`（iPhone ボイスメモ）

**処理**:

1. 音声形式と認識。`personal-tools` で `python -m src.whisper_transcribe ... -l ja -m small` を実行
2. 文字起こしに「三島湖」「バス」「ジグ」「2尾」等 → **釣り関連ボイスメモ**と判定（**この時点では `釣行メモ.md` を Read しない**）
3. **釣り関連確定後**、`Fishing/釣行メモ.md` を Read。**先頭「聞き取り補正」を先に適用**し、そこに無い語は同一フィールドの過去エントリからルアー名・リグ名の表記を参照して、末尾に既存体裁に合わせて追記:

   ```markdown
   ## 2026-06-14 — 三島湖

   ### 条件（三島湖）

   - **水質**: （文字起こしより）

   ### 状況（三島湖）

   - **サイトフィッシング**（文字起こしより）

   ### 釣果（三島湖）

   - **2尾**（サイズは文字起こしどおり。不明は（要確認））

   ### 使用ルアー（三島湖）

   - **ジグ**: **（製品名）**
   ```

   **使用ルアー節**に釣果・バイト・釣り方は書かない。追記後は **`check_trip_memo_lure_sections.py`** で当該行を検査（上記「使用ルアー節の分離」）。

   続き:

1. 音声を `Fishing/attachments/` にコピー（**釣行メモにはリンクしない**）
2. Articles に文字起こし全文を `2026-06-14_sanmiko-voice-memo.md` として保存
3. Knowledge 化はスキップ。InBox の `.m4a` を削除
4. **適用可能性**: **省略**（釣行メモ経路）
5. **次のアクション**: **`/trip-memo-import`** を促す（このターンでは import しない）

### 例8: 領域が一意に決まらないボイスメモ（ユーザー確認で中断）

**入力**: InBox に `memo.m4a`（仕事と開発が混在し、主領域が決まらない）

**処理**:

1. 文字起こしまで実施
2. 領域判定で**一意に決まらない**と判断 → **ユーザーに報告**:
   - 文字起こし抜粋
   - 「主領域が一意に決まらないため、保存先の指示をお願いします」
   - 候補（`Work/`、`DevProject/specifications/`、`Fishing/`、Knowledge、Articles のみ、保留 等）
3. **正本反映・InBox 削除は行わず中断**
4. ユーザーが方針を指示したら、別実行で続行

### 例8b: 本職ボイスメモ（Work へ自動反映）

**入力**: InBox に `1on1-memo.m4a`（メンバー面談のメモ）

**処理**:

1. 文字起こし → **本職（仕事）**と判定
2. **`work-folder-update` SKILL を Read** し、該当メンバーノートまたは `Work/定例・報告/` へ反映
3. Articles に文字起こし全文
4. InBox の `.m4a` を削除（釣行メモ経路ではないため **適用可能性** も実施）

### 例9: 文字起こし済みボイスメモ（`voice_` 始まり Markdown）

**入力**: InBox に `voice_20260615003619.md`（端末文字起こし済み）

```markdown
# 2026/06/15 0:36:18

----
ららららら
```

**処理**:

1. **形式 6** と判定。**whisper は実行しない**
2. **1 行目** `2026/06/15 0:36:18` を録音日時として保持（釣行メモ見出し日付 **`2026-06-15`** の根拠）
3. `----` 以降 **「ららららら」** を文字起こし全文として **1.4.1** へ（釣り関連でなければ例8と同様にユーザー確認で中断）
4. 釣り関連と確定した場合 → **`釣行メモ.md` Read** のうえ追記・Articles 保存・InBox の `.md` 削除
