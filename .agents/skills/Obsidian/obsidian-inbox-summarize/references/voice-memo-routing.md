# 1.4.1 ボイスメモの振り分け（文字起こし後・必須）

SKILL.md「1.4.1」の詳細。文字起こしテキストが確定した後にだけ読む。

**1.4 の whisper 出力**、または **形式 6（`voice_` 始まり Markdown）から抽出した文字起こしテキスト**が、**個人のボイスメモ**（釣行記録・独り言・現場メモ等。記事 URL や PDF ではない）と判断できるとき、**領域（ドメイン）**で経路を分ける。

**釣り関連の判定（いずれかで釣行記録とみなす）**:

- 釣行・釣果・ヒット・バイト・場所（湖・ダム・池・河川・フィールド名）・ルアー・ジグ・ワーム・竿・リール・ライン・水位・水質・天候・サイズ（cm）・尾数 等が**主題**
- ファイル名・InBox 付随メモに釣り・バス・釣行等の語がある場合は**補助**（本文の主題を優先）

**本職（仕事）の判定（いずれかで Work 正本へ）**:

- DTS・クライアント・案件・メンバー・1on1・定例・課題・人事考課・社内手続き・稼働・体制 等が**主題**

**副業開発の判定（いずれかで DevProject 正本へ）**:

- FishTrack / MyPokedex / おたよりナビ / FaiNavi / dev-workspace の機能・設計・バグ・運用・仕様判断 等が**主題**

| 分類 | 後続処理 |
| --- | --- |
| **釣り関連ボイスメモ** | **`Fishing/釣行メモ.md` に追記**（下記）。あわせて Articles に文字起こし全文を保存。Knowledge 化は**原則スキップ**（釣行メモが正本）。**完了報告の `## 適用可能性` は不要** |
| **本職（仕事）ボイスメモ** | **`work-folder-update` SKILL を Read** し `Work/` 配下の適切な正本へ反映。Articles に文字起こし全文。該当する Knowledge があれば §4 で集約も可 |
| **副業開発ボイスメモ** | **`specification-update` SKILL**（仕様変更時）等に従い `DevProject/` へ反映。Articles に全文。汎用技術部分は Knowledge へ |
| **汎用知識ボイスメモ**（上記いずれにも主として該当しない） | **Articles + Knowledge** 経路（1.5 以降）＋ §「ドメイン別正本への反映」で他領域の有無を再確認 |
| **領域が一意に決まらないボイスメモ** | **ユーザーに判断を仰ぐ**（下記）。正本反映・InBox 削除は判断まで進めない |
| **ボイスメモでない音声**（講義・インタビュー・ポッドキャスト等、記事相当の長尺） | 従来どおり **Articles + Knowledge** 経路＋**ドメイン別正本への反映** |

**`釣行メモ.md` の Read タイミング（トークン削減・必須）**:

- **`Fishing/釣行メモ.md` の Read は、当該 InBox 項目が釣り関連ボイスメモと確定した後のみ**行う（上表 **釣り関連** 経路に入ってから。手順は **文字起こしテキスト確定 → 振り分け判定 → Read**。**`voice_` 始まり `.md` は whisper 前に Read しない**）。
- **禁止**: InBox 棚卸し直後・**文字起こしテキスト確定前**・振り分け判定前の **先読み**（釣り以外のボイスメモが混在するときのトークン浪費を避ける）。
- **釣り関連以外**・**ユーザー確認で中断**の経路では **`釣行メモ.md` を Read しない**（**本職・開発**経路では `Work/`・`DevProject/` の Read は **`work-folder-update` / `specification-update` 等**に従う）。
- **例外（InBox 処理外）**: チャットでの**ユーザー訂正**（既存エントリのルアー名・サイズ等の修正）は本 SKILL の振り分け対象外。該当 Articles と同期するときのみ **必要箇所**を Read する。

**領域が一意に決まらないボイスメモ — ユーザーへの確認（必須）**:

1. 文字起こし全文（または先頭〜数百字の抜粋）と、領域が一意に決まらない旨を報告
2. 保存先の候補を提示（例: `Work/` 配下、`DevProject/specifications/`、`Fishing/`、Knowledge ジャンル、Articles のみ、処理しない）
3. **ユーザーの指示があるまで** 正本反映・InBox 削除に進まない
4. ユーザーが方針を指示したら、**別依頼または同一 SKILL の再実行**で続行する

**旧称「釣り関連以外のボイスメモ」**: 上表の **本職・副業開発・汎用知識** に該当すれば**自動反映**。本節の確認は **領域が一意に決まらない** ときのみ。

**`Fishing/釣行メモ.md` への追記ルール**:

1. **釣り関連と確定した後**、追記・Articles 化の**直前に Read** し、既存の見出し・**箇条書き体裁**・日付昇順（古→新）を把握する。**先頭「聞き取り補正」と**、過去エントリのルアー名・リグ名・技法用語の表記を参照する（下記「釣り系専門用語」。**末尾の Trip だけ読んで補正節を飛ばさない**）
2. **追記位置は常に末尾**（ファイル先頭の説明「新規は末尾に追記」に従う）
3. **Trip 単位（必須）**: **1 つの `##` ＝ FishTrack の 1 Trip**。同日に複数のフィールド／エリアで釣行したら **`##` を分ける**（複数エリアを 1 見出しにまとめない）。
   横断振り返りは **各 Trip の `### 振り返り` に分けて書き、横断用の `##` は作らない**。詳細は `釣行メモ.md` 先頭「記載単位（FishTrack Trip 対応）」を正とする
4. **見出し**: `## YYYY-MM-DD — {フィールド名}（{エリア名}）`（日付・場所は文字起こしから抽出。**形式 6** のとき **1 行目の録音日時を日付根拠として優先**。フィールド／エリア名は FishTrack 登録名に揃える。不明な項目は `（要確認）`）
5. **本文**: 既存エントリに合わせた `### 条件` / `### 状況` / `### 釣果` / `### 使用ルアー` 等。
   **Markdown 表は使わない**（`- **項目名**: 内容` の箇条書き。`釣行メモ.md` 先頭・**`trip-memo-import` SKILL** 参照）。
   **`### 条件` に `- **場所**:`・`- **釣行時間**:` は書かない**（FishTrack の Field／Area・Trip 日時が正。`##` 見出しで場所は表す）。**水位バッチ取得対象** Field（例: 戸面原ダム）では **`- **水位**:` も書かない**（`WaterLevelHistory` が正）。非対象 Field（例: 佐久間ダム）のみ記載可。
   **`### 使用ルアー`**: 下記「**使用ルアー節の分離（必須）**」を**追記直後に必ず**満たす（製品名・カラー・リグ種別のみ。正本は `釣行メモ.md` 先頭「使用ルアー（FishTrack ルアー紐づけ）」）。
   **当該 Trip に属する内容のみ**をその `##` 内に書く。**「ボイスメモ（時刻）」等の入力経路メタは書かない**（釣行の事実・所感のみ）
6. **釣り系専門用語**: 下記「釣り系専門用語（過去の釣行メモを参照）」に従う。**聞き取り補正節に一致する語は、過去 Trip より先にその補正を使う**
7. **文字起こしの事実を優先**し、推測で数値・尾数を補完しない。聞き取れない箇所は `（聞き取り不明）`
8. **出典の扱い**: 文字起こし全文は **Articles** に保存する。**`釣行メモ.md` には `### 参照` を書かない**（Articles リンク・`attachments` リンクは FishTrack `Trip.memo` 同期に不適切）。音声は必要なら `Fishing/attachments/` にコピーするが、釣行メモ本文からはリンクしない
9. **`fishtrack-meta`**: **書かない**（`<!-- fishtrack-meta: … -->` は **釣行メモのフィールド解決／Trip 同期インポート**が付与。`釣行メモ.md` 先頭「記載単位」参照）
10. **markdownlint**: `釣行メモ.md` 更新後も **0 件**まで整える（`markdown-editing` / `markdownlint-fix`）
11. **追記後の FishTrack 取り込み（必須・案内のみ）**:
    釣行メモへ追記して完了した報告では、**`## 次のアクション`** を **`/trip-memo-import`** にする。
    対象は今回追記した `##` 見出し。
    **このターンでは resolve / import を実行しない**
    （実行は **`trip-memo-import` SKILL**。ユーザーが依頼したときだけ）。
    InBox に残りがあっても、次の InBox 処理より先に取り込みを促す。
    ユーザー訂正だけで本文を直したときも、未取り込みなら同じ案内にする。

**釣り系専門用語（過去の釣行メモを参照・必須）**:

釣り関連ボイスメモと**確定した後**、`釣行メモ.md` / Articles に反映する**直前に**、**`Fishing/釣行メモ.md` を Read**する（追記ルール 1 の Read と**同一回で可**。体裁把握に加え、用語照合まで行う）。**確定前の Read は禁止**（上記「Read タイミング」）。

- **目的**: whisper の誤認識を減らす（ルアー名・リグ名・技法用語・フィールド固有名が崩れやすい）
- **参照優先度**: **先頭「聞き取り補正」の一致** → **同一フィールド**（湖・ダム名等）の過去エントリ → 直近の他フィールドエントリ → 未登場語は推測で置換しない
- **聞き取り補正の適用**: 節に書いた聞き取り文字列が文字起こしにあるとき、補正後を釣行メモと Articles の読みの両方で使う。**条件がある行は、その条件のときだけ**。一致しない語へは広げない
- **採用基準**: 補正節に無く、文字起こしの音・文脈が過去エントリの表記と**整合**するなら、過去釣行メモの表記を採用する（**釣行メモ追記と Articles の文字起こし整理の両方**で同一表記）
- **判断不能**: 補正節にも過去にも例が無く確信が持てない語は、文字起こしどおり残すか `（要確認）` とする。**別商品名・別技法名への当て込みは禁止**
  - **「も」や同一 Trip の既存ルアーだけでは同一製品としない**（例: 「スティーズブラーも」を朝の **STEEZ クアッドフォーゼ**へ当て込まない。未登場なら文字起こしどおり／要確認）
- **ユーザー訂正**: チャットで訂正があった場合は **釣行メモ本文と該当 Articles の読みを同一セッションで同期**する。**同じ言い間違いが再発しうる聞き取り**（場所の音、定型句）は、先頭「聞き取り補正」へ**追加または上書き**する。その Trip だけの数値・日付・一回限りの事実は節に載せない。**ある回のルアーを製品名へ特定しただけでは載せない**（同じ聞き取りが常にその製品だとユーザーが言ったときだけ載せる）。**ユーザーが指摘していない推測は載せない**

**使用ルアー節の分離（必須）**:

`### 使用ルアー` は **`trip_lure_usage` 用の製品リスト**。**釣果・バイト・バラシ・サイズ・サイトの釣り方**は書かない（`### 状況`・`### 釣果`・`### 振り返り` へ）。

- **書くもの**: `- **製品名**`、`- **リグ**: **製品** — **カラー**` 等（**1 ルアー 1 行**）
- **書かないもの**: `キャッチ`・`バイト`・`バラシ`・`ヒット`・釣果の `cm`／`mm`・`尾`・`サイトで`・`浮かせ`・`反応なし`・`ロスト`・リグ名だけで製品不明の行（製品が分かるまで行を追加しない）
- **書いてよいもの**: 製品名そのもののサイズ（例: **Gimmy 3.5インチ**、**Flick Shake 4.8"**）。検査は `cm`／`mm` を単語境界で見る（`Gimmy` の `mm` を釣果と誤らない）
- **悪い例 / 良い例**: `釣行メモ.md` 先頭「使用ルアー」内の**結果混在**の例を Read してから追記する
- **追記直後の検査（省略禁止）**:

  ```powershell
  python d:\OneDrive\git_work\dev-workspace\scripts\check_trip_memo_lure_sections.py `
    "D:\OneDrive\アプリ\remotely-save\Obsidian\Fishing\釣行メモ.md" `
    --min-line <今回追記した使用ルアー節の先頭行> `
    --max-line <同節の末尾行>
  ```

  **exit 1** なら節を直してから InBox 削除・報告へ進まない。ファイル全体に既存遺留違反があっても、**今回触った節は 0 件**が必須。
