# CursorLog の典型原因と違反事例

本ファイルは `obsidian-cursor-log` SKILL の補足。手順の正本は SKILL 本体（「作業フローと報告前ゲート」「🚨 同時書き込み対策」「🚨 エントリ追記の必須手順」）にある。ここには、なぜ記録漏れや重複が起きるかと、過去の違反事例だけを置く。

## 記録漏れの典型原因（対策の観点）

- **会話要約（summarize）**や長文の打ち切りのあと、「報告直前の自己チェック（CursorLog 更新したか？）」が文脈から消え、次の応答でコード変更が未記録のままになる。
- **「完了」や成果報告の文面**を**先に**心の中・下書きで作り、**CursorLog 追記を同じ最終返答の後回し**にする（**順序の逆転**。SKILL「作業フローと報告前ゲート」で禁止）。
- 実装に集中し、**SKILL を参照せず**に **`StrReplace` / `Write` 等の連打**で終える。
- **チェックリストとツール名の不一致**: ルール文面が旧ツール名だけだと、**自分の操作が「ログ対象」だと結びつかず**漏れる。**`StrReplace` / `Write` / `Delete` / `EditNotebook`** を対象とすること（dev-workspace **myrules**「作業ログ」も同趣旨）。
- **対策**: 各プロジェクトの **AGENTS.md** に「コード変更完了時は CursorLog」を短く載せる。**報告の直前**に必ず Obsidian 側を更新する。成果を**ユーザーに文で述べ始める前**に、**同一応答内で** log 用 `Write` / `StrReplace` を**済ませる**（前ゲート）。

## エントリ重複の典型原因（対策の観点）

- **会話要約（summarize）・スレッド継続**直後、要約の「未記録の CursorLog」指示だけを見て、**前ターンですでに追記済みの同一作業**をもう一度 `##` ごと複製する。
- **同一チャット内の二重完了**: 中間ステップ（コミットのみ等）と最終報告の両方で、別時刻の `##` を立てて**同じ作業名・同じ変更ファイル**を再記録する。
- **親子 SKILL の二重指示**: 例として **`FishTrack_commit`（コミット後）** と **`FishTrack_pull-request`（PR・CI 後）** の両方が CursorLog を要求し、**1 依頼で 2 エントリ**になる（親 SKILL 側で **1 エントリに統合**する）。
- **`StrReplace` の非一意アンカー**: ファイル内に**同一ブロックが 2 つ**ある状態で置換すると、片方だけ更新されたり、意図せず複製が残る。新規エントリは**原則ファイル末尾への追記のみ**。
- **対策**: 追記前に当日ログを **Read** し、**「エントリ追記の必須手順（重複防止）」** を実施する。既存エントリへ追記・更新で足りるなら **新しい `##` を立てない**。

## 他エージェントのログ消失の典型原因（同時書き込み）

**複数の Cursor エージェント／チャットが同じ `YYYY-MM-DD.md` を同時に更新する**と、後続の書き込みが先行エントリを消すことがある。

- **既存日次ファイルへの `Write` 全文置換**: 作業開始時に Read した内容＋自エントリで**ファイル全体を上書き**すると、その間に他エージェントが追記した `##` が消える（**最大の原因**）。
- **古い末尾を `old_string` にした `StrReplace`**: 追記の数分〜数十分前に読んだ末尾をアンカーにすると、他エージェントが末尾を変えたあとも「たまたま一致する中間ブロック」を置換して壊す、または失敗して再試行せずに `Write` へ逃げて消す。
- **IDE タブ／会話内の古いバッファを正とする**: ディスク上の最新ではなく、開いているタブや前ターンの Read 結果だけを信じる。
- **対策の正本**: SKILL の「🚨 同時書き込み対策（複数エージェント）」（省略禁止）。

## 記録漏れが起きやすい状況

- **会話要約・スレッド切替**直後（直前セッションのファイル変更を思い出す）
- 実装に集中し SKILL を開かず次依頼へ進む
- **マルチルート**でコード倉庫だけ更新し Obsidian vault を忘れる
- **日付跨ぎの当日初回ログ**で Q0（`obsidian-cursor-monthly-report`）を飛ばし `YYYY-MM-DD.md` だけ新規作成する（2026-07-16 事例）

## 違反事例

### 違反事例（2026-07-16・月次日報）

- **事象**: `2026-07-16.md` を新規作成したが、前日 `2026-07-15` の月次日報節を `2026-07 日報.md` に追記しなかった
- **対策**: Q0 ゲートと `obsidian-cursor-monthly-report` SKILL を独立正本化（2026-07-18）

### 違反事例（2026-04・要約）

- **事象**: コード変更後、最終返答に CursorLog 追記が先立たない（「CursorLogは更新しました」も欠落）
- **主因**: 完了文を先に考える / マルチルートで Obsidian を忘れる / 要約直後に Q1〜Q3 が起動しない

### 違反事例（2026-10-16・次のアクション）

- **事象**: 作業完了の報告が、残作業を本文に書いたあと `CursorLogは更新しました` で終わった。見出し `## 次のアクション` が無かった
- **主因**: 「残作業・課題」の行を節の代わりにした。Git 操作を書かない制約を、節ごと省く理由にした
- **対策**: Q7。送信直前に残作業の有無を見て、残るときは末尾へ 1 件だけ書く
