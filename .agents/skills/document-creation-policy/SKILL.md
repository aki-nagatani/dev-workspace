# ドキュメント作成規律（document-creation-policy）

**myrules**「ドキュメント作成規律」と同一趣旨。**チェックリスト・例外・違反時対応の正本は本 SKILL**。

## 絶対ルール

**🚨 ユーザーからの明示的な指示がない限り、いかなるドキュメントも新規作成してはならない。**

## 発火条件

- **`Write` ツール**（または同等）で **新規** `.md` / `.txt` / `.rst` 等を作成しようとするとき
- 分析・調査結果を**ファイルに書き出そう**とするとき
- 「ドキュメント化した方がよい」と判断したとき（**先にユーザー確認**）

## 基本原則

- 指示がなければ**勝手に作成しない**
- 作成した方がよいと思っても**ユーザーに判断を仰ぐ**
- **明示的指示または承認**がある場合のみ新規作成

## ツール使用前の必須チェックリスト

`Write` 等で**新規**ドキュメントを作る前に、**すべて**満たすこと。

- [ ] ユーザーが**明示的に**作成を指示したか？（「分析して」だけでは不十分）
- [ ] 指示がなければ**確認を取ったか**？（承認「はい」「作成して」等）
- [ ] 本 SKILL と **myrules**「ドキュメント作成規律」を再確認したか？

**未充足ならドキュメント作成ツールを使わない。**

## 分析結果の提示方法

- **会話内で提示**（ファイルを作らない）
- ドキュメント化が必要なら**ユーザーに確認**
- 「ドキュメント化して」と明示されるまで **`Write` で新規 `.md` 等を作らない**

## 違反時の対応

- 違反に気づいたら**即削除**しユーザーに謝罪
- 本 SKILL を再読する

## 例外（新規作成が許可される場合）

- ユーザーが「ドキュメントを作成して」「ドキュメント化して」等と**明示**した
- ユーザーが「はい」「作成して」等で**承認**した
- **既存ドキュメントの更新**（ユーザー指示または **myrules「ドキュメント更新規律」**・`specification-update` 等に基づく）
- **ワークフロー正本**として必要な **`SKILL.md` / `AGENTS.md` の新規・更新**（myrules「ユーザー指摘に基づく SKILL の育成」）
- **CursorLog 追記**（`obsidian-cursor-log` SKILL。新規日付ファイルの作成を含む）
- **実装に伴う**テスト・ソース（`.py` / `.js` 等）— 本 SKILL の対象外

## 本 SKILL の対象外

- **既存仕様書・計画書の更新**: `specification-update` / `integrated-schedule-update`
- **ソースコード・テストコード**の新規作成
- **コミットメッセージ用一時ファイル**: `temp-file-management` SKILL（`temp/` 配下）

## 関連

- **myrules**: 「ドキュメント更新規律」「ドキュメント配置方針」（Obsidian 集約）
- **markdownlint**: 許可された Markdown 編集後は `markdownlint-fix` SKILL
