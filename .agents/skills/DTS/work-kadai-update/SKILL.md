# work-kadai-update（Work/課題.md 更新）

**`Work/課題.md`** の目的は、**現時点における継続・未解決の業務課題**を一覧し、**常に最新の状況**で管理することである（目標設定そのものではない）。\
体制・プロジェクト上の未決事項（旧 `Work/体制・プロジェクト/課題.md`）も本ノートに集約済み。

**目標設定**（**`mokuhyo-draft`**）は、**あくまで**この正本に載った**現時点の課題**を**参考**にして目標を検討する。**課題の正本更新は本 SKILL**、**管理シートへの目標下書きは `mokuhyo-draft`**（本 SKILL「**mokuhyo-draft との連携**」）。

myrules を厳守する（**スクリプト一括置換禁止**・**報告前 CursorLog**）。

**最初の作業**: 本ファイルを **Read** する。続けて正本 **`Work/課題.md`** を **Read** する（**空でも確認**）。

要約は同ディレクトリの **`AGENTS.md`** と整合させる。

## 使用タイミング（発火）

- **`Work/課題.md`** の**追記・更新・削除**・**カテゴリ整理**を依頼されたとき
- **管理シート**の**達成状況コメント**から**未解決課題を洗い出して**正本へ反映するとき（**53期以前を含む**）
- **`mokuhyo-draft`** 作業中に、チャットで確定した課題・打ち手を正本へ戻すとき（**報告前**）
- **体制メモ**・会議・顧客 FB 等から**新規課題**を登録するとき

## ノート構造（正本の書き方）

| 要素 | ルール |
| --- | --- |
| **1 課題** | 見出し **`### {カテゴリ}-{連番} {タイトル}`**（例: `財務-01 売上高の維持とターゲット達成`）。**タイトル**は未解決テーマの**短い名詞句**（要員名・領域名は必要時のみ）。連番は **2 桁ゼロ埋め**。**カテゴリ内で通し** |
| **ID プレフィックス** | 一覧の `##` に合わせる。`稼働・労務`→**`稼働労務`**、`体制・人員`→**`体制`**（`・` は付けない）。他は見出しと同じ（`財務`・`CS`・`育成`） |
| **一覧** | `## 課題一覧` の下に **カテゴリ**の `##`（財務・CS 等）→ その下に `### {カテゴリ}-…` |
| **カテゴリ** | 課題が**属する分野**（一覧の `##` 見出しと **カテゴリ** 行が一致） |
| **状態** | **未着手**／**対応中**のみ正本に載せる。**解決済み**は**ブロックごと載せない**（判明したら**削除**。「完了」だけ残さない） |
| **最新** | 本文は**いまの未解決状態**と**今後の打ち手**のみ。必要な経緯は**本文**に書く。過去の達成済み細目は載せない |
| **出所** | **正本には書かない**（管理シート・旧メモ等の抽出元はエージェントが Read するだけ） |
| **最終更新** | 各ブロックに **`YYYY-MM-DD`**（内容を直した日） |
| **四半期・半期（過去の事実）** | 本文・状況の**既出事実**では **`◯◯期` を付ける**（例: `54期4Q`）。`4Q` のみは**禁止** |
| **実施時期（打ち手）** | **`今後の打ち手`** に**具体的な実施時期・頻度**（`55期1Q`、`月次`、`半期ごと` 等）を**書かない**。**ユーザー指示があるときのみ**追記 |

### 同一テーマの統合（必須）

| ルール | 内容 |
| --- | --- |
| **1 テーマ = 1 ブロック** | **同一課題テーマ**は原則**1件**。**例外**: **次期案件L・次期L育成**は**要員ごとに1ブロック**（**タイトル**に氏名を明記） |
| **統合時** | 残す **`### {カテゴリ}-{連番}`** は**1つ**（**同一カテゴリ内**で通常は**最小連番**）。他ブロックは**削除**し内容を統合先へ移す |
| **連番** | **カテゴリごと**に削除で空いた番号は**再利用しない**（参照の安定のため） |
| **本文** | 統合後は**最新状況**に書き直す（メンバー別・施策別の小見出しは可） |

## 1 課題ブロックの項目

各 **`### {カテゴリ}-{連番}`** に、少なくとも **内容**（本文）を書く。

| 項目（見出し例） | 用途 |
| --- | --- |
| **状態** | 未着手／対応中（**解決済みは載せない**） |
| **カテゴリ** | 属する分野（`## 財務` 等と一致） |
| **今後の打ち手** | **何をするか**のみ（測定・証跡を意識可）。**いつ・どの頻度で**は**ユーザー指示まで載せない** |

## 管理シートからの課題抽出

**`人事考課_管理シート.md`** の**対象期より前**の各期について、**目標**・**達成状況コメント(本人)**（必要なら補助者コメント）を Read し、**未解決・継続**のみ追記する。

| ルール | 内容 |
| --- | --- |
| **遡る範囲** | **53期以前を含む**（**N−1 期**に加え、より古い期も可） |
| **載せるもの** | 未達・施策未実施・体制上の未決・「来期も〜」と残した**打ち手が必要な**事項 |
| **載せないもの** | **解決済み**（達成・課題解消・打ち手完了と読み取れるもの）。**根拠のない**一般論 |
| **重複** | 既存 **`### {カテゴリ}-…`** と同一テーマなら**新規ブロックを増やさず**、既存を**最新状況に更新**（本 SKILL「同一テーマの統合」） |
| **管理シート編集** | **対象期より前は Read のみ**（**`mokuhyo-draft`** の前期変更禁止と同趣旨）。抽出は**Read**、反映先は **`課題.md` のみ** |

**手順（推奨）**:

1. 対象メンバー（例: 長谷　晃英）の **`### {期} {氏名}`** を期ごとに Read する。
2. **達成状況コメント(本人)** で未達・継続・来期意向を拾う。
3. 既存課題と突合し、**新規**か**更新**かを決める。
4. **`StrReplace` / `Write`** で **1 ブロック単位**追記・更新。
5. 一覧注記（`## 課題一覧` 直下の括弧書き）を必要なら更新。

## 適宜更新（必須）

**`課題.md` は Read 専用にしない。** 作業中に確定した内容を**報告前**に正本へ戻す。

| 更新タイミング（例） | 記載する内容 |
| --- | --- |
| **チャットで課題・打ち手を示した直後** | 新規 **`### {カテゴリ}-{連番} {タイトル}`** または既存の **内容・打ち手・タイトル** の更新 |
| **ユーザーの採用・修正・却下後** | 打ち手・タイトルの確定／整理 |
| **達成状況から抽出した直後** | **本文**（最新状況・打ち手）。**解決済みは追記しない** |
| **課題が解消したと判断できるとき** | 当該ブロックを**削除**（ユーザー指示または達成状況で明確な場合） |

**連番**: 新規は**当該カテゴリ**の既存最大 **+1**（2 桁ゼロ埋め）。**既存 `### {カテゴリ}-…` の ID は変えない**（内容のみ更新）。**他カテゴリへ移す**ときはユーザー判断または統合手順に従い**新 ID を付与**する。

**編集**: **`StrReplace` / `Write`** で **1 課題ブロック単位**（**`replace_all` 禁止**）。**`課題.md` を触ったら** **`markdownlint-fix` SKILL** で**同一ファイル内**を解消。

## 編集（エージェント）— 禁止

| 禁止 |
| --- |
| **根拠のない**課題の大量追加 |
| **解決済み**の新規追記、または **状態: 完了** だけ残す |
| **管理シートの 12 項目**をそのまま貼り付けて増殖 |
| **管理シート**の**対象期より前**の本文を本 SKILL の名義で改変 |
| **`replace_all`** で `課題.md` 全体を機械置換 |
| ユーザーが**採用しない**と明示したテーマを、打ち手だけ残し続ける |
| **`今後の打ち手`**に、ユーザー未指示の**実施時期・頻度**（`◯期1Q`、`月次`、`週次`、`半期ごと` 等）を**エージェントが創作**すること |

## mokuhyo-draft との連携

**優先順位**: **`課題.md` は現時点の課題管理が主目的**。目標設定は**副次的に**正本を参照する（正本を目標用の下書き置き場にしない）。

| 役割 | SKILL |
| --- | --- |
| **現時点の課題の管理**（正本の更新・抽出） | **本 SKILL**（`work-kadai-update`） |
| **管理シートの目標下書き**（課題を**参考**に検討） | **`mokuhyo-draft`** |

**`mokuhyo-draft` 実施時（エージェント）**:

1. **`課題.md`** を **Read**（**`work-kadai-update`**「作業冒頭」と同趣旨）。
2. 枝番ごとに **課題 ID → 枝番・打ち手** の対応を**チャットで必ず**示す（課題がある場合）。**正本 `課題.md` には枝番紐づけを書かない**。
3. 目標に**新規課題**を持ち込むときは根拠を示し、**同一セッションで本 SKILL に従い `課題.md` を更新**。
4. **報告前**に、チャットと **`### {カテゴリ}-…`** が矛盾していないか確認する。

**管理シート本文**に **財務-01** 等の課題 ID は**書かない**（本人提出物として自然な文にする）。
