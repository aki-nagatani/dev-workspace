# quality-analysis

Always respond in Japanese when using this skill.

## 発火条件

- ユーザーが **品質分析**、**IT結果**、**ST結果**、**バグ票**、**障害管理台帳**、**障害表**、**品質レポート** を依頼したとき
- 雛形 Excel・規模の数値・テストケース数・障害管理台帳を渡したとき（**テキスト入力も含む**）
- **`Work/MY案件/`** 配下の品質分析フォルダ、または **`品質分析.md`** の作成・更新を依頼したとき

## 必須の最初アクション

**`SKILL.md` と `template.md` を Read ツールで全文読む**。Work 配下を編集する前に **`work-folder-update` SKILL** も Read する。

## 要点

- **作業フォルダ**はユーザー指定を正とする。型は `Work/MY案件/{案件フォルダ}/品質分析/`
- **成果物は Markdown**（作業フォルダ内の `品質分析.md`）。顧客提出の **Excel は書かない**
- **雛形と共通情報は一度登録したら次回案件でも使う**。呼び出しごとに再入力させない
- **構成**は納品済み過去結果を踏襲。見出し・表の形を合わせ、数値・考察は写さない
- **基準値ブロック**は混在時のみ案件ごと＋全体。混在しなければ1つ。前案件の分割見出しはコピーしない
- **分野（代理店）**: WEB と Excel設計書。案件により片方または両方。分析は対象分野ごとに実施する
- **過去の品質分析結果**も案件フォルダの `品質分析.md` に残す。比較は過去 MD を参照。考察は写さない。
  **納品済み・連携済み**は正式版としてそのまま転記（要約・言い換え禁止）
- **追加観点の案**は `template.md` に残す（未採用）。障害表に無い情報は採用不可。分析するなら障害表のフォーマット変更が先。
  過去案件との比較は雛形の節（案ではない）
- 共通の正本は **`template.md`** と `Work/MY案件/_共通/品質分析/`
- **雛形は大枠のみ**。構成は納品済み過去結果。前案件の文言・数値・結論は写し替えない
- **入力の取り方**: 規模とテストケース数はユーザーが渡す。障害関連は障害管理台帳（障害表）から取得する。Excel が置けないときはチャットへテキスト
- **入力は随時**。無い欄は `（未入力）`。推測で埋めない。**`0` は未入力ではない**。規模・テストケース数を計算しない。テキスト入力を不足扱いしない
- **実行しながら本 SKILL / template.md を更新**する
- 完了後は **`obsidian-cursor-log`**。MD 編集後は **`markdownlint-fix`**

手順の正本は **`SKILL.md`**。
