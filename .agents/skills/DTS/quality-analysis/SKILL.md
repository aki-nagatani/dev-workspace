# quality-analysis（IT/ST 品質分析）

申込書・代理店など DTS 本職案件の **IT / ST 結果**を分析し、**エージェント成果物は Markdown** とする。
顧客提出の最終成果物は **Excel**（ユーザーが MD から転記）。エージェントは **Excel を書かない**。

**最初の作業**: 本ファイルと [template.md](template.md) を **Read** する。Work 配下を編集する前に **`work-folder-update` SKILL** も **Read** する。

## 発火

- ユーザーが **品質分析**、**IT結果**、**ST結果**、**バグ票**、**障害管理台帳**、**障害表**、**品質レポート** を依頼したとき
- 雛形 Excel・規模の数値・テストケース数・障害管理台帳をチャットへ貼った／パスを示したとき（**テキスト入力も含む**）
- **`Work/MY案件/`** 配下の品質分析フォルダ、または既存の **`品質分析.md`** の追記・修正を依頼したとき

## 原則

- **推測で数値・判定・考察を埋めない**。根拠がない欄は **`（未入力）`**。
  **`0` は未入力ではない**。規模の件数などが 0 なら `0` と書く。
- **雛形と共通情報は一度登録したら次回案件でも使う**。呼び出しごとに再入力させない。
- **構成の正は納品済みの過去結果**。見出し・節の並び・表の形は、当該プロジェクトの直近正式
  `品質分析.md`（無ければ納品 Excel）をベースにする。前案件の**結論・文言・数値は写さない**。
  分野の有無と、混在時の基準値ブロック本数だけ案件に合わせる。
- **雛形は大枠のみ**。大枠の中身は上記の過去構成。独自の節（例: 独立した「この後取るべきアクション」）を足さない。
- **前案件の文言を理解せず使わない**（過去の品質分析で指摘された失敗）。意味が取れない見出しはユーザーに確認する。
- **入力は随時**。揃うまで待たず、来た分だけ MD を更新し、足りないものを明示する。
- **実行しながら本 SKILL を更新する**。手順・大枠・判断基準が変わったら同一セッションで本ファイルを直す。
- **機密**: Work は社外秘。外部検索・外部ツールへ結果・障害内容を送らない。Excel 読み取りはローカルのみ。
- **追加観点の案**: [template.md](template.md) に残す。**未採用**。成果物の標準構成に入れない。
  追加観点の情報は **障害表だけ**。障害表に無い情報の案は採用できない。
  分析したいときは **障害表のフォーマット変更が先行**。ユーザーが採用を明示し、かつ必要な列があるときだけ昇格する。
  **(3) 過去案件との比較**は雛形の節であり案ではない。
- **基準値ブロックの本数**: 1つの分析に複数案件が混在するときだけ、案件ごと＋全体。
  混在しなければ **全体 1 つ**。前案件の分割見出しをコピーしない。詳細は [template.md](template.md)。
- **過去の品質分析結果**: Excel／スクショだけで終わらせない。**当該案件フォルダの `品質分析.md` に残す**。
  今回案件の「過去案件との比較」は、その過去 MD を参照する。数値の転記は可。考察文は今回へコピーしない。
- **納品済みの過去結果**: 連携・納品済みの品質分析 Excel は**正式版**。MD 化は**転記**であり、再分析ではない。
  セルの数値・分類・考察文を**そのまま**残す。要約・言い換え・「スクショの文言」等のメタ注記は付けない。
  空セルは空のまま（`（なし）` で埋めない）。読めない欄だけ `（未入力）`。`0` は `0`。

## 入力の取り方（運用）

| 情報 | 取り方 |
| --- | --- |
| **規模**（KSLOC / SLOC、マスタ、IF、画面数、帳票数、バッチ、推定FP） | ユーザーが**資源から計算して渡す**。**対象分野ごと**。エージェントは計算しない（KSLOC も SLOC から出さない） |
| **テストケース数** | ユーザーが渡す（**対象分野ごと**、IT / ST 別）。エージェントは台帳や資源から計算しない |
| **障害関連**（障害件数、発生原因、障害No、原因の一例など） | **障害管理台帳**（**障害表**ともいう）から取得する。**対象分野ごと**（台帳が分かれていなくても分野が分かること）。台帳に無い値は `（未入力）` |
| **対象分野** | 代理店は WEB / Excel設計書。案件の対象（片方または両方）を対象表に書く |
| **基準値の形・原因分類** | 共通雛形。[template.md](template.md) に大枠登録済み。**算式**（予測値・下限・上限）だけ未登録ならそれだけ受領 |
| **過去案件との比較** | 過去案件フォルダの `品質分析.md`。無ければ受領した Excel／スクショ／テキストから **同一セッションで MD 化する**（納品済みなら**そのまま転記**）。今回の障害表から他案件は取らない。考察は写さない |

### 入力の形態（Excel とテキスト）

セキュリティの都合で **Excel を Work / Cursor に置けない**ことがある。その場合は **チャットへテキストで渡す**。テキストは Excel と同等の入力として扱う。

| 形態 | 扱い |
| --- | --- |
| **Excel をフォルダへ置ける** | 共通雛形は `_共通/品質分析/`、案件の台帳は作業フォルダ。`.xlsx` は openpyxl、`.xls` は xlrd で stdout のみ読む |
| **置けない** | 表・CSV 相当・箇条書きをチャットへ貼る。ファイル配置を再要求しない |
| **規模の数値・テストケース数** | テキストで十分 |

テキストから必要な数値・分類だけを `品質分析.md` / `template.md` へ載せる。台帳の全文を Work に複製しない。

## 正本

| 用途 | パス |
| --- | --- |
| **作業フォルダ（案件固有）** | ユーザー指定を正とする。型は `Work/MY案件/{案件フォルダ}/品質分析/` |
| **MD 成果物** | 作業フォルダ内の `品質分析.md`。**過去案件も同じ型**（Excel のまま残さない） |
| **共通雛形 Excel** | 置けるときだけ `Work/MY案件/_共通/品質分析/`。置けないときはチャットのテキスト。抽出結果は [template.md](template.md) |
| **共通大枠・分類・集計ルール** | [template.md](template.md) |
| **案件固有の入力** | 規模の数値、**テストケース数**、**障害管理台帳**（**障害表**）。Excel またはテキスト。置けない場合はチャットへ。雛形の再配置は求めない |
| **顧客提出 Excel** | ユーザーが作成。エージェントは Read のみ |
| **本 SKILL** | `dev-workspace/.agents/skills/DTS/quality-analysis/SKILL.md` |

案件が複数あるときは **案件フォルダを分ける**（1ノートに混ぜない）。1ノートが長すぎるときだけ分割（**`ノート分割の基準.md`**）。
**正本は作業フォルダの1箇所**。別パスに置いていた MD は移して旧ファイルを削除する。

## 作業フロー

### 0. ゲート

1. 本 SKILL を Read する。続けて [template.md](template.md) を Read する。
2. Work を編集するなら **`work-folder-update`** を Read する。
3. 作業フォルダが指定されていれば配下を一覧する。既存の **`品質分析.md`** があれば Read する（無い初回だけ `Write`）。
4. 雛形の**大枠**は [template.md](template.md) に登録済み。再提出させない。
   **算式**（予測値・下限・上限）だけ未登録ならそれだけ求める。ファイル配置は必須ではない。

### 1. 入力の棚卸し

セッション内の入力を次で分類する。無いものは **不足** と記録し、分析を止めない。

| 種別 | 例 | 必須度 |
| --- | --- | --- |
| **雛形（共通）** | 品質分析 Excel のシート構成、またはそのテキスト／スクショ | **大枠は登録済み**。算式だけ未登録ならそれだけ受領 |
| **共通情報** | 分類、集計ルール、指標の定義、書き方 | 来たら template.md に残す。次回も使う |
| **対象の特定（案件）** | 申込書／代理店、案件名、**対象分野**（WEB / Excel設計書 / 両方）、対象工程（IT/ST）、期間 | 案件ごと |
| **規模（案件）** | KSLOC / SLOC、マスタ、IF、画面数、帳票数、バッチ、推定FP。ユーザーが資源から計算して渡す。**対象分野ごと** | 案件ごと |
| **テストケース数（案件）** | IT / ST 別。ユーザーが渡す。**対象分野ごと** | 案件ごと |
| **障害管理台帳（案件）** | 障害表。Excel またはテキスト。障害件数・発生原因などはここから取得。**対象分野が分かること** | 案件ごと |
| **基準値の算式（共通）** | 予測値・下限・上限の算式 | 未登録のときだけ受領。template.md に残す。大枠は登録済みなので再提出させない |
| **補足（案件）** | WBS、体制、既知の事情、顧客指摘 | 考察の根拠。推測で補わない |

Excel を置けるときは **Read ツールではセルが読めない**。`.xlsx` は **openpyxl**、`.xls` は **xlrd** で **stdout のみ**読む。
読み取りスクリプトで **`.md` を生成・上書きしない**（myrules「ファイル修正と差分確認」）。
テキスト入力のときは貼られた内容を正とし、ファイルの再提出を求めない。

**対象の特定が来たとき**（プロジェクト名・案件名）:

- 成果物の H1 を `品質分析（{プロジェクト}・{案件名}）` にする
- 「対象」表と「入力状況」の対象行を即更新する
- 対象分野が来たら対象表に書き、MD は **対象分野の節だけ**置く（対象外は作らない）
- 「未確定・次インプット」から案件名確認を外す
- 他ノートにある終了予定・担当などは **既知事情** として対象に書く。テスト結果からの推測はしない
- **案件名は SKILL に書かない**（今回限りの値）

**過去の品質分析（Excel／スクショ／テキスト）が来たとき**:

- 当該案件の作業フォルダ `Work/MY案件/{案件フォルダ}/品質分析/品質分析.md` へ残す。フォルダが無ければ新設する
- **納品済み・連携済み**なら正式版。セルの数値・分類・考察文を**そのまま転記**する。
  要約・言い換え・エージェントの再考察はしない。空セルは空。読めない欄だけ `（未入力）`。**`0` は `0`**
- 未納品の下書きや欠けたスクショだけのときは、読めた範囲だけ転記し、欠けは `（未入力）`
- 障害表の全文は複製しない（システム品質シートに載っている障害No・件数・一例は転記する）
- 今作業中の別案件へ、過去の考察文をコピーしない
- 今作業中の比較表は、過去 MD を参照（wikilink）し、必要な数値だけ転記してよい

**作業フォルダが指定されたとき**:

- そのパスを正本とする。型は `Work/MY案件/{案件フォルダ}/品質分析/`
- 配下を一覧し、**案件固有**の規模の数値・テストケース数・障害管理台帳があれば読む。空でもフォルダ確定として MD の対象表を更新する
- MD は作業フォルダへ置く。別場所にあれば移し、旧ファイルは削除する
- 雛形が無いことを理由に、共通雛形の再提出を求めない
- Excel が置けない旨があれば、テキスト入力で足りるとし、ファイル配置を次インプットに書かない

### 2. 雛形から大枠を取る（未登録のときだけ）

1. 置けるときだけ、Excel を **共通フォルダ** `Work/MY案件/_共通/品質分析/` へ置く（またはパスを [template.md](template.md) に記録する）。置けないときはチャットのテキストを正とする。
2. シート名、見出し、表の軸（基準値、発生原因など）を拾う。
3. **[template.md](template.md) の大枠・分類を実物に合わせて更新**する。登録状態を「登録済み」にする。
4. 前案件の**数値・考察文は成果物へコピーしない**。
5. 意味不明の見出し・指標はユーザーに確認し、確認待ちを MD の「未確定」に書く。
6. 以降の案件では本節を飛ばし、template.md の大枠を使う。

### 3. 分析して MD を更新する

成果物は [template.md](template.md) の **過去結果の構成**に沿う。空の項は推測しない。

1. **規模・○テスト項目設定率・○障害発生率と考察** — 規模とテストケース数はユーザー渡し。
   障害件数は障害表。行数から／機能数から、IT / ST。
   **ブロック本数**は [template.md](template.md) のルール（混在しなければ1つ）。
   **分野ごと**に実施する（対象分野が2つなら2分析）。
2. **(2) 障害要因** — IT / ST の表と **＜分析結果＞**。再発防止・次の打ち手もここに書く。
   分類は template.md の7分類。独立した「この後取るべきアクション」節は置かない。
3. **(3) 過去案件との比較** — 過去案件の `品質分析.md`。無い欄は `（未入力）`。考察は今回分だけ書く。

- 基準値が無い間は判定欄を **`（未入力）`**。考察はデータが無い間は書かない。
- **数値は入力どおり**。集計する場合は計算過程を短く残す。
- **表を優先**。長文は考察・＜分析結果＞に限る。
- **IT と ST は分けて集計**し、必要なら合計行を置く。混在させない。
- 考察は **今回のデータから言えることだけ**。一般論や前案件の定型句は書かない。

### 4. 不足と次インプットを残す

MD 末尾の **「未確定・次インプット」** を、その時点の不足だけに更新する。
**雛形が登録済みなら、雛形の再提出は次インプットに書かない。**
Excel を置けないときは、次インプットを **テキスト** とし、ファイル配置を求めない。
ユーザーへの報告でも、**次に欲しい入力を多くても3件**に絞る。

### 5. SKILL の更新（同一セッション）

次に当てはまる指摘・気づきは **チャットだけで終えない**。

- 大枠（見出し・表・工程の切り方）が実雛形と違った → **template.md を更新**
- 集計ルール（対象外障害、再オープンの数え方等）が確定した → **template.md に残す**
- 追加観点の案の採用可否・障害表列の有無が確定した → **template.md の案一覧を更新**（列が無ければ採用しない）
- エージェントの漏れ・誤解を誘う手順があった
- ユーザーが「こう進めてほしい」と今後にも効く指示をした

今回限りの数値・案件名だけの修正は SKILL / template.md に書かない。

### 6. 検証とログ

1. **`markdownlint-fix`** で成果物 MD の lint を解消する。
2. 本人の次アクションが動いたら **`Work/Todo.md`** を更新する。
3. **`obsidian-cursor-log`** を報告前に追記する。

## 大枠

内容の正は [template.md](template.md) の **過去結果の構成**（規模・設定率・発生率、(2) 障害要因、(3) 過去比較）。
案件ごとの見出しも同ファイルを正とする。基準値ブロック本数は混在時のみ複数。

## Excel 転記（ユーザー作業）

- エージェントは **顧客提出 Excel を作成・編集しない**。
- MD の表は、列名を雛形に近づけ、コピーしやすい形にする。
- グラフは MD では表＋短い説明に留め、Excel 側で作る前提とする。

## 禁止

- 登録済みの雛形・共通情報を、呼び出しのたびに再提出させる
- 未入力欄をそれらしい数値・判定で埋める
- 前案件 Excel の考察文をほぼそのまま使う
- 入力が揃うまで成果物を作らず待つ
- 品質分析 Excel をスクリプトで生成する
- 障害内容を外部 AI・Web 検索に貼る
- 規模（KSLOC / SLOC / マスタ / IF / 画面数 / 帳票数 / バッチ / 推定FP）を資源からエージェントが計算する
- テストケース数を障害管理台帳や資源からエージェントが計算する
- 障害管理台帳に無い件数を別資料から推測する（規模・テストケース数のユーザー渡しと過去比較を除く）
- 混在しない案件で、サブ案件＋全体の複数基準値ブロックを作る
- 対象分野を混ぜて1本の分析にする
- 両方対象なのに片方の分野だけで完了する
- 対象外の分野の節を作る
- 過去の品質分析結果を Excel／スクショのままにして、MD を作らない
- 納品済みの過去結果を要約・言い換え・再考察して MD 化する
- 前案件の分割見出し・数値・考察を次案件へコピーする
- 追加観点の案を、障害表に無い情報や別資料で埋めて成果物に載せる
- 納品済み過去結果と違う見出し構成で新規成果物を作る（分野の有無・混在ブロック本数の差は除く）
- 独立した「この後取るべきアクション」節を足す（打ち手は＜分析結果＞へ）
- ユーザーの採用前に、追加観点の案を標準構成へ昇格する
- 障害表に列が無い観点を、フォーマット変更なしで分析対象にする
- Excel を置けないと分かっているのに、ファイル配置だけを次インプットにする
- テキスト入力を不足扱いして Excel の再提出を求める
