# ojt-development-plan-manager-comment（OJT育成計画・上長振り返りコメント）

新人OJT育成計画の四半期振り返りについて、上長である長谷のコメントを作成する。
**正本は Markdown**。Excel は正本ではない（Write しない。確定後の転記 Todo も載せない）。
ユーザーが本人・OJTトレーナー記載の入力として Excel を渡したときは Read し、セル文言を正本ノートへ写す（言い換えない）。
欄名はノートの `上長フォローコメント` / `PLコメント` / `担当課長フォローコメント` に合わせる。

月報の上長フォローは **`ojt-monthly-report-manager-comment`**。本 SKILL と混同しない。

## 月報 SKILL との切り分け

| | 月報 | 本 SKILL |
| --- | --- | --- |
| 周期 | 対象月 | 対象四半期（2Q / 3Q / 4Q） |
| 正本 | `{年度}_{氏名}_月報.md` | `2026_古川_育成計画.md`（Excel ではない） |
| 欄 | `### 上長フォローコメント` | 短期育成計画の各ブロック（年間目標ごと） |
| ねぎらい | 欄が1箇所のため先頭に書いてよい | ブロックが複数あるため、各項目に「お疲れさまでした」等は書かない |
| 月報上長フォロー | その月の正本 | 当該ブロックに関係する判断・原則は**参考・引用してよい**。全文貼付とねぎらい先頭の転用はしない |
| 字数目安 | 200〜300文字 | ブロックあたり 120〜250文字 |

担当部長・事業部長／部長のフォローは書かない（ユーザーが明示したときだけ）。

## 最初の作業

1. Work配下を編集する場合は、先に `work-folder-update` SKILLを全文Readする。
2. **対象メンバー**と**対象四半期**を確定する。欠けていれば確認してから書く。
3. 反映先正本をReadする（下記「反映先」）。
4. 対象四半期に含まれる月の月報管理ノートをReadする（根拠。
   上長フォローは当該ブロックに関係する判断・原則を参考・引用してよい。
   月報の本人振り返り・トレーナー文はコピー元にしない）。
5. 対象四半期の本人振り返り、達成度・評価理由、OJTトレーナーコメント、既存の上長コメントを確認する。
6. 同一ノートの過去四半期、必要なら前年度の育成計画ノートから
   `上長フォローコメント` / `PLコメント` / `担当課長フォローコメント` の本文だけをReadし、
   長谷の文体・語尾を参考にする。
   **月報の `### 上長フォローコメント` はですます・語尾の主参考であり、当該ブロックに関係する判断・原則は引用してよい。**
   ねぎらい先頭と月報全文の貼り付けはしない。
   城本2025の「認識相違ありません」だけの短文は退職年の特例であり、通常の型にしない。

## 四半期の範囲

特段の指定がなければ DTS 年度で次とする。ユーザーが別定義を明示したらそれに従う。

- **2Q**: 7月〜9月
- **3Q**: 10月〜12月
- **4Q**: 1月〜3月

育成計画ノートに 1Q 振り返り欄が無い前提。1Q を指定されたら確認する。

## コメントの作成方針

- 達成度・本人振り返り・トレーナー文の要約だけで終わらせない。
- 本人の評価理由・振り返りの事実を言い換えて書き始めない（読み手が既に読んでいる）。
  事実は、上長の判断や次の役割に接続する根拠として一行以内に留める。
- **月報上長フォローの当該四半期の核**（配属・参画時期など上長判断）は、関係するブロックへ**1回だけ**書く。
  本人・トレーナーの研修進捗の前倒しと、実務参画の前倒しを混同しない。各項目へ繰り返さない。
- 次四半期・配属・役割、または品質・工程の原則につながる期待を1点に絞る。
- OJTトレーナーの見立てと**矛盾させない**。ただし**同じ方向のコメントにしてはならない**
  （下記「トレーナーとの視点分担」）。
- 課題だけの指摘にせず、前向きな到達像を必ず含める。
- 根拠のない実績・評価・約束・達成度％を創作しない。
- **ねぎらいは月報と分ける。** 月報は上長コメントが1箇所のため、先頭にねぎらいを書いてよい。
  育成計画はブロックが複数あるため、各項目の先頭に「お疲れさまでした」等のねぎらい定型を置かない。
  本人欄の事実を短く言い換えて「成長の認知」としない。
- やわらかい表現で、本人に語り掛ける口調にする。命令的・評価的に断定しすぎない。
- 参考対象は過去の上長コメント（育成計画）と月報の上長フォロー。
  過去の育成計画コメントとトレーナー文は無変更で複写しない。
  **月報の上長フォローは、当該ブロックに関係する判断・原則を参考にして引用してよい。**
  月報全文の貼り付けと、ねぎらい先頭の転用はしない。
  月報の本人振り返り・トレーナー文は上長コメントへ引用しない。
  同四半期のトレーナーコメントは**重複回避の突合対象**であり、論点のコピー元ではない。
- 長谷の通常のです・ます調。ブロックあたりおおむね120〜250文字。
  実績が薄いブロックを引き伸ばさない。内容のまとまりに応じて改行・空行を入れ、読みやすくする。

## トレーナーとの視点分担（必須）

短期育成計画にはトレーナーコメントと上長コメントが並ぶ。読み手に同じ話が二度出ないよう、**レイヤを分ける**。

- **先に**対象四半期・当該ブロックの OJTトレーナーコメントを読み、論点・助言・到達像・言い回しを列挙する。
- 上長コメントではそれを**繰り返さない**。同じ結論の言い換え
  （「大事だ」「意識して」「一つずつ」「質問して」等）での重ね書きも禁止。
- **発展は可**: トレーナーが触れた論点を、同じ文で終わらせず、上長として一段深い原則に進めてよい。
- **トレーナー側の典型**: 研修の進め方、スキルの身につけ方、成果物の目的、日々の姿勢、質問の仕方。
- **上長側の典型**: 配属・参画時期の判断、案件での役割、期待の置き方、現場での立ち位置、品質・工程の原則。
- 各項目に「お疲れさまでした」等のねぎらい定型は書かない。
  本人振り返りの事実の言い換えも書かない。事実は判断の根拠として一行以内。
- 矛盾する指示は出さない。足りない点は上長レイヤで補う（育成手順の復唱ではない）。

## 根拠不足のとき

次が対象四半期で空なら、コメントを創作せず不足を報告する。

- 当該ブロックの四半期実績または評価理由・進捗状況
- 新入社員の振り返り（ブロックにある場合）
- OJTトレーナーコメント（ブロックにある場合）

ユーザーがチャットまたは Excel で根拠を渡したら、それを正としてノートへ書いてからコメントを書く。
課題未設定の空ブロックにはコメントを書かない。

## 生成後の自己レビュー

反映前に、作成したコメントを次の観点で自己レビューし、必要なら書き直す。

- 育成計画・月報の本人記載・OJTトレーナーコメントと矛盾していないか。
- **同四半期のトレーナーと並べて読み、同じ結論・同じ助言が二度出ていないか**
  （出ていれば上長側を別視点にするか、一段深い原則へ発展させる）。
- 本人振り返りとトレーナーを伏せても、上長として配属・役割・期待、
  または品質・工程の原則の話になっているか。事実の復唱で始まっていないか。
- 次への期待がやわらかく伝わるか。各項目に「お疲れさまでした」等のねぎらい定型が無いこと。
- 月報の上長フォローのうち、当該ブロックに関係する判断・原則を落としていないか
  （引用してよい。全文貼付・ねぎらい先頭の転用はしていないか）。
- AIが生成した定型文ではなく、長谷が本人に語り掛けて書いた自然なコメントに見えるか。
- 抽象的な称賛、過度に整い過ぎた表現、同型の文末の連続がないか。

## 反映先

- **正本（現行・2026 古川）**:
  `Work/社内業務/2026新人OJT/2026_古川_育成計画.md`
- コメントを作成した場合は、このノートの**短期育成計画の当該ブロックごと**に対象四半期の上長欄を更新する。
- 見出しはノート既存に合わせる。無ければ対象四半期の直下へ `上長フォローコメント` を追加する。
- ユーザーが「全体1本」と明示したときだけ、ブロック横断の1本にまとめてよい。
- **Excel は正本ではない。** Write しない。転記 Todo も載せない。
  ユーザーが本人・トレーナー記載の入力として Excel を渡したときは Read し、正本へ写す。
  上長コメントの根拠は本ノート・月報ノートと、ユーザーが渡した内容に限定する。
- 達成度％・評価理由・本人振り返り・トレーナー文は、ユーザー指示なく書き換えない。
- 短期計画の達成基準は Excel 列で BC=0.25、BD=0.5、BE=0.75、BF=1.0。
  難易度が逆転していないか、写したあと必ず確認する。
- 短期計画のシート下部コメント行は OJTトレーナー記入。
  「したい」等の文体から新入社員と推測しない。
- 他メンバーの育成計画コメントを依頼されたときは、同フォルダの `{年度}_{氏名}_育成計画.md` を正本とする（Excel ではない）。

## 確定

- ユーザーが「確定」と明示したら、当該四半期の上長コメントは**本ノート上の確定稿**とする。
  正本の短期計画導入または未記入欄に **`YYYY-MM-DD 確定稿`** を残す（日付は JST 当日）。
  以後その四半期の文面は、ユーザー指示なく書き換えない。
- Excel 転記用の Todo は載せない。

## 検証と報告

- コメントの根拠となった育成計画・月報の記載と矛盾しないことを確認する。
- 管理ノートを更新した場合は、markdownlintを実行して同一ファイルのエラーを解消する。
- ファイルを変更した場合は、`obsidian-cursor-log` SKILLに従ってCursorLogを更新する。
- 報告では、対象メンバー、対象四半期、文案または反映先、確認結果を簡潔に示す。
