# 仕事の次のアクション

本SKILLは本職候補の抽出・着手可否・Asana・出力詳細の正本である。
`/next-action-work` の本職専用フローと、`/next-action` が本職を候補化するときの両方で適用する。
副業・趣味・個人開発を候補から除外し、Obsidian `Work/` と業務に関するCursorLog、
当チャットで確定した本職情報、および **Asana MCP（読み取り）** から、次の一手と配下へのリマインドを示す。

## 対象と対象外

### 対象

- 株式会社DTSにおける本職のタスク、期限、顧客案件、定例、メンバー対応、社内手続き
- `Work/Todo.md` の未完了（単発）
- `Work/Todo-定例作業.md` の未完了（繰り返し。週次・月次・3ヶ月次・年次等）
- `Work/社内手続き/PL作業TODO.md` の定義・未写し分（写し済みなら `Todo-定例作業.md` を正とする）
- `Work/課題.md` の継続課題と、案件・顧客対応・定例に記録された期限やブロッカー
- 当チャットおよび直近CursorLogにある、本職に関する未解消の合意・残作業
- **Asana MCP** の未完了（自分担当は着手候補。配下で期限が迫るものはリマインド）

### 対象外

- FishTrack、FaiNavi、MyPokedex等の副業・趣味・個人開発
- `/next-action-nowork`（本 SKILL は開かない。正本は `next-action-nowork`）
- `DevProject/` の計画・仕様・タスク
- コミット、プッシュ、デプロイ、PR、マージ
- Git作業ツリーや未コミット差分に関する案内
- 進捗会議・定例会など、**時間が来たら始まる出席・参加**（候補にしない。開催の正本は `Work/定例・報告/定例会.md`）
- `Todo.md` の **`### 単発タスク（期限未設定）`** にある `⚠️ 期限設定待ち` のタスク（期限を設定するまで候補にしない）

## 調査手順

原則としてコードやWork正本の業務内容は変更しない。ただし、`/next-action-work` が
呼び出された場合は、候補抽出より先に、Workの単発・繰り返しTodoについて
着手可能日・前タスクの状態を再判定する。
**`work-todo-update` SKILL「着手不可解除の横断スキャン」**の **A（フル）** に従う。
着手可能日 **`YYYY-MM-DD` ≤ JST 今日**かつ前タスク充足の行、または着手可能日が指定されず前タスクだけが条件である行は、
同一対象回の前タスクがすべて完了した時点で `🚫 着手不可` を外してから候補判定する。
（**当日期限・当日着手可能日だけに grep しない**）。**A は JST 各日1回**（同日2回目以降の `/next-action-work` では A 省略可）。
前提条件（メール受信・「面談実施後」などを含む）の確認有無にかかわらず解除し、
確認待ちにはしない。タスクの追加・完了・期限変更、前タスク完了や
前提条件の充足記録は、別途ユーザーが明示した場合だけ行う。
`/next-action` が本職を候補化するときも、本節の手順で候補抽出と解除判定を行う。

1. 当チャットの本職に関する未完了事項、期限、依頼、判断待ちを確認する。
2. 当日または直近のCursorLogから、本職に関する「残作業・課題」とエントリ本文を確認する。
3. `Work/Todo.md` を読み、`⚠️ 期限設定待ち` を除く単発の未完了・期限超過・当日・今週を確認する。
4. `Work/Todo-定例作業.md` を読み、繰り返しの**未完了の対象月チェック行**（`[ ]`）と
   `Work/Todo.md` の単発タスクの
   期限超過・当日・今週を確認する。`[x]` の対象月は候補にしない。親の定義は参照する。
   候補にした親タスクに **`作業内容`** があれば、出力用にその箇条書き・手順を取得する。
   **作業内容の全行・全項目を保持する。要約・言い換え・省略をせず、記号や補足を含めて出力する。**
   期限超過の抽出は、特定カテゴリや当日期限の行に絞らず、両Todoの全未完了行を
   横断して先に行う。期限超過群を確定してから、当日締切・今週・未来期限を確認する。
   候補抽出より先に、**`work-todo-update` SKILL「着手不可解除の横断スキャン」**の **A（フル）** を実施する
   （その JST 日に未実施なら。全未完了チェック行・着手可能日 **≤ 今日**・前タスク **同一対象月／対象日で全件完了**を照合。当日行だけに絞らない）。
   着手可能日が指定されない場合は、同一対象回の前タスクがすべて完了していれば候補にする。
   解除後に前提条件・「面談実施後」などの情報が残る行も、確認せず候補にする。
   **`🚫 着手不可`** が残る行と、`⚠️ 期限設定待ち` の行は候補にしない。前タスク未完了の行は前タスク側を候補にする。
   着手可能日が未来なら日付で候補にしない。前提条件の未確認は候補から除外しない。
   着手推奨日があり、今日がそれより前なら**優先度を落とす**（候補から除外しない）。
   期限超過（期限が今日より前）は、着手可能日が今日以前で実行可能なら最優先で候補化する。
   出すときは「期限超過」と明記する。推奨日前でも、この優先順位を下げない。
   出席は候補にしない。
   表示対象は各親タスクの未完了の対象月チェック行3つ。
   候補は、まず実行可能な期限超過、次に当日締切、その後に今週の順で確認する。
5. `Work/社内手続き/PL作業TODO.md` は定義・写し方。
   未写しの当月未済が残っていれば候補に含める（Excel 単独を正本にしない）。
6. 必要に応じて `Work/課題.md`、案件・顧客対応・定例の関連ノートを確認し、依存関係とブロッカーを確かめる。
7. **Asana MCP** を読む（下記「Asana（MCP）」）。未接続なら理由1行でスキップし、Work 源は続ける。
8. 情報源の違いで優先順位を決めず、まず実行可能な期限超過を最優先で抽出する。
   その後、期限、依存関係、影響範囲、リスク、ユーザーの明示したゴールで同順位の候補を比較する。

## 優先順位の決め方

次の順で候補を絞る。期限超過の最優先は、情報源、カテゴリ、定例／単発の別、
当日締切タスクの影響度によって崩さない。

1. **期限超過（期限 < JST の今日）の実行可能な未完了タスク**を最優先にする。
   着手可能日が今日以前で、`🚫 着手不可` に該当しないものに限る。
   前提条件の未確認は候補化・実施の確認待ち理由にしない。
   当日締切・今週・未来期限のタスクより先に並べる。
   期限超過が1件でもある場合、当日締切・今週・未来期限だけのタスクを
   期限超過タスクより上位に置かない。期限超過群は超過日数、依存関係、
   影響範囲、リスクで並べ、件数によって候補から外さない。
2. 当日締切、または業務停止につながる実行可能なブロッカーを解消する。
   `🚫 着手不可` が残る行は候補にしない。着手可能日到来後は、前提条件の未確認にかかわらず候補にする。
3. 今週までの未完了から、**着手推奨日が無い、または今日が着手推奨日以降**のものを優先する。
   後続の作業や関係者を待たせるものを先にする。
4. 継続課題は、現時点で具体的に着手できる一手がある場合だけ候補にする。
5. **着手推奨日前**（期限超過でない）は優先度を落とす。上位で件数が埋まるなら出さない。
   出すなら前提に「推奨前」と書く。
6. 期限・依存・影響の根拠が不足する候補は、推測と明記するか、確認事項として示す。

期限超過が複数ある場合は、超過日数、依存関係、影響範囲、リスクで比較する。

同じ内容が複数の情報源に現れるときは、重複候補にせず、もっとも具体的な期限・前提を統合して1件にする。
チャット、Todo、CursorLog、Asana の内容が矛盾するときは自動で採用せず、矛盾点と確認すべき事項を明記する。

## Asana（MCP）

`/next-action-work` のたびに **読む**。Asana へタスク作成・更新・コメントはしない。
手順の正本は本節。禁止情報は `Work/体制・プロジェクト/申込書・代理店_プロジェクトルール.md` の Asana 使用ルール。

### 接続

- 名前空間は `plugin-asana-asana`。`ready` でなければ Connect を案内し、Asana はスキップする。
- 出力にスキップ理由を **1行**。Work の Todo・課題は続ける。
- **`search_tasks` は使わない**（Premium 専用で `payment_required` になる）。

### 期限窓（JST）

Todo の「今週」とは別。Asana はリマインドのため次を対象にする。

- **期限超過**（`due_on` が今日より前）
- **今日から7日以内**（`due_on` が今日〜今日+7）
- `due_on` が無い未完了は対象外

Asanaで `due_on` が設定されている場合は、タスク名に含まれる期限表記より
`due_on` を優先して期限を判定する。タスク名の期限表記（例: 「10/30期限」）と
`due_on` が相違するときは、`due_on` を期限として採用する。相違自体は確認事項にしない。
候補の期限・期限窓の判定・当日締切の判定はすべて `due_on` で行う。

Asanaの本人担当「交通費精算」タスクは、毎月20日から着手可能とする。
ただし交通費精算は `Work/Todo-定例作業.md` の **D-2** を正本とするため、
Asana側の同名・類似タスクは候補へ出さない。期限・着手可否の判定と報告はD-2だけで行う。

### 取得手順

1. JST の今日をターミナルで取る（`datetime-jst`）。
2. `get_my_tasks`（`completed_since` は `now`。自分担当の未完了）。
3. `get_projects`（`archived=false`、必要ならページング）。
4. 未完了があるプロジェクトごとに `get_tasks`。
   `completed_since` は **UTC の ISO datetime**（`YYYY-MM-DDTHH:mm:ssZ`）。
   `get_tasks` に `now` は使えない。
   `opt_fields` は `name,assignee,assignee.name,due_on,completed`。
5. プロジェクトが0件なら `get_teams` のあと、業務チームで `get_projects` を足す。
   名前が「の最初のチーム」で終わる個人サンドボックスは対象外。
6. 期限窓で絞る。ユーザー向け文面に **GID を出さない**（名前で示す）。

### 振り分け

- **担当が自分（長谷）**: `## 推奨` の着手候補。Todo と重複なら1件にまとめる。
  ただし交通費精算はD-2の正本管理を優先し、Asana側の重複タスクは候補にしない。
- **担当が配下**: `## リマインド`。作業本体は担当者。長谷は期限を伝える。
  配下の正本は `Work/体制・プロジェクト/所属・役割・プロジェクト概要.md` の内訳と
  `Work/メンバー情報/`。プロパーと客員を含む。休職中の鈴木美玖は配下。離任の寺崎は対象外。
  Asana の `assignee.name` が配下のフルネームまたは姓と一致するときだけ出す。
- **配下ではない他者**: リマインドしない。
  確定の非配下（Asana 表示名）: 三橋愛理、田中英嗣、Hideki Saito。
- **担当未設定**: リマインドしない。
- 同じ名前・担当・期限は1件にまとめる。

### 禁止

- チャットへ GID を出さない
- タスク本文・添付を長く貼らない（名前・期限・担当・プロジェクト名まで）
- Asana への書き込み（作成・更新・コメント・完了）

## 出力

実行可能な本職候補は**すべて**示し、件数上限を設けない。期限超過・当日・今週・将来の順に並べる。
期限が早い候補を後ろへ回したり、実行可能な候補を件数だけで漏らしたりしない。

```markdown
## 推奨

### 1. {タスク名}

- 根拠: `Work/Todo.md` / `Work/Todo-定例作業.md` の期限、Asana（自分担当）、
  CursorLog・チャット上の依頼など
- 実施内容: 親タスクに **`作業内容`** がある場合は、記載された全行・全項目をそのまま記載する。
  要約・言い換え・省略は禁止。箇条書き、手順、記号、括弧内の補足も落とさず、
  チャットでは原文の構造を保って列挙する。作業内容の記載がない場合だけ
  「詳細手順の記載なし」と明示する。
- チャットの参照先表示: `ms-excel:` URIやMarkdownリンクは使わない。`Todo-定例作業.md` の
  Excel起動用リンクは維持しつつ、チャットには同じUNCフルパスをインラインコードで表示する。
- 契約状況一覧: A系の候補で契約状況一覧を更新・参照する場合は、次のフルパスを当該候補へ必ず記載する。
  `\\fs-idc.ad.dts.co.jp\事業部門_48\1530_第三金融事業部\25 保険第五\07_契約管理\契約状況一覧 -3課.xlsx`
- 外注発注状況確認: A-7a／A-7b、A-8a／A-8b、A-9a／A-9bの候補では、
  次のフルパスを当該候補へ必ず記載する。
  `\\fs-idc.ad.dts.co.jp\事業部門_48\1530_第三金融事業部\25 保険第五\03 外注管理\02 外注発注状況確認\外注発注状況確認.xlsx`
- 採算管理シート: A-4の候補では、`Todo-定例作業.md` の
  次のフルパスを当該候補へ必ず記載する。
  `\\fs-idc.ad.dts.co.jp\事業部門_48\1530_第三金融事業部\25 保険第五\02 着地見込\55期\採算管理シート`
- 優先理由: 期限、依存関係、影響範囲、リスクのいずれかを記載する。
- 前提・注意: 判断待ち、確認先、作業開始前に必要な情報があれば記載する。
```

他者のうち **配下** の Asana で期限窓に入る未完了があるとき、推奨の3件とは別に次を出す。
配下でない担当・担当未設定は出さない。該当が無ければ節を出さない。
15件を超えるときは先頭15件と残り件数。

```markdown
## リマインド（Asana・配下）

- {担当名} / {タスク名} / 期限 YYYY-MM-DD（当日 | 超過n日 | 残りn日） / {プロジェクト名}
```

Workの正本を編集していない場合、CursorLogは更新しない。解除を実施した場合は、
通常のWork編集と同じく `obsidian-cursor-log` を更新する。具体的な更新や実装を始める依頼に変わった場合は、
`work-folder-update` を先にReadし、対象に応じて `work-todo-update`、`work-kadai-update`、`quality-analysis`、`mokuhyo-*` 等を併用する。
