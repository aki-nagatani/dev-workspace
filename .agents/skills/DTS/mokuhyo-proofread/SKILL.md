# mokuhyo-proofread（目標管理シート・校閲）

**`人事考課_管理シート.md`** の**最新の期**（`## ◯◯期` のうち**期番号が最大**の節）について、**当該期の全メンバー**（すべての `### {期} {氏名}`）の記載を**校閲**する。

**本文（本人・補助者が書いた既存文）は変更しない**。指摘・修正案は、該当 **`#####` 直下の本文の直後**に **`<改善案>` ブロック**として**のみ**追記する。

**`mokuhyo-draft`**（下書き作成）・**`mokuhyo-excel-to-markdown`**（Excel 同期）とは**別 SKILL**。本 SKILL は**校閲と改善案の追記**のみを担う。

myrules を厳守する（**スクリプト一括置換禁止**・**報告前 CursorLog**・**Markdown は編集ツールでブロック単位**）。

**最初の作業**: 本ファイル（`dev-workspace/.agents/skills/DTS/mokuhyo-proofread/SKILL.md`）を **Read** し、手順に従う。

要約は同ディレクトリの **`AGENTS.md`** と整合させる。

## 使用タイミング（発火）

- **目標管理シートの校閲**・**校正**・**レビュー**を依頼されたとき
- **上期目標提出前**の**誤字脱字・表現**・**チェックポイント**の確認
- **`@人事考課_管理シート.md`** を指定し、**最新期・全員**の文案を見てほしいとき

## 対象範囲（必須）

### 最新期の決め方

1. 管理シート内の **`## {数字}期`** 見出しを列挙する。
2. **期番号（数字）が最大**の節を **対象期**とする（例: `## 55期` があれば **55 期**）。
3. ユーザーが **別の期を明示**したときのみ、その期を対象期とする。

### メンバー・枝番

- 対象期の **`### {期} {氏名}`** を**すべて**校閲する（**1 人だけ**に限定しない）。
- 各メンバー配下の **`#### {期} {氏名} {枝番}`** ブロックごとに、下記「校閲対象の `#####`」を走査する。

### 対象期より前は触らない

| 許可 | 禁止 |
| --- | --- |
| 対象期の **`## {対象期}`** からファイル末尾（または次の `##` 直前）までの **`<改善案>` 追記** | **対象期より前**の `##` 配下の**一切**の編集（誤字修正・`<改善案>` 追記を含む） |
| 前期以前を **Read** して**本人の文体・用語**の参考にする | **`replace_all`** で管理シート全体を置換 |

**編集境界**: `old_string` には **`## {対象期}`** または当該 **`##### … — {対象期} …`** を含め、前期の見出しだけでは置換しない。

## 校閲対象の `#####`（本文があるもの）

**`#####` 直下に本文が 1 行以上ある項目**を校閲する。空欄のみの項目は**指摘不要**（空欄そのものは **`mokuhyo-draft`** の未記入扱い。本 SKILL で本文を埋めない）。

**優先（目標設定の 12 項目）** — 見出し名は次のいずれかを含むもの:

1. 通期目標
2. 上期目標
3. 下期目標
4. 通期達成基準（ターゲット）
5. 通期達成基準（ミニマム）
6. 上期達成基準（ターゲット）
7. 上期達成基準（ミニマム）
8. 下期達成基準（ターゲット）
9. 下期達成基準（ミニマム）
10. チャレンジ度
11. ウェイト
12. 設定理由（本人）

**その他** — 本文がある場合のみ:

- 設定時コメント(補助・１次調整者)
- 上期／下期達成状況コメント(本人)・(補助・１次評価者)

**触らない（本文を変えず、通常は `<改善案>` も付けない）**:

- **`###` 直下**のメンバー・等級・社員番号
- **`####` 直下**の目標ジャンル（変更提案は**ユーザー確認**後に別 SKILL）

## 校閲観点

### 1. 誤字脱字・表記（最優先）

- 漢字の誤り、送り仮名、重複、脱字
- 全角／半角の**明らかな不統一**（**同一メンバー内**で読みにくい場合のみ。メンバー間の統一は**しない**）
- 句読点・改行の**著しい欠落**（意味が取りにくいとき）

**本人・当該メンバーの過去期**に既にある表記（例: 「行なう」「同上」）は**そのまま尊重**し、会社標準への寄せだけを理由に直さない。

### 2. 表現（必要最小限）

- 一文が**極端に長い**・**主語述語が不明**で第三者が読めない

**禁止**: 文体の好みだけでの言い換え、ですます調への統一、メンバー間での言い回し揃え。

### 3. 曖昧な表現・基準の不明確さ・矛盾（必須確認）

**枝番ごと**に、目標・達成基準・設定理由を**セットで読み**、次の 3 点を**必ず**確認する（該当時は `<改善案>`。\
**改善理由**に「曖昧」「基準不明確」「矛盾」のいずれかを明示する）。

#### 3.1 曖昧な表現

第三者が**同じ解釈に収束しない**語句・構文がないか。

| 典型例 | 補足 |
| --- | --- |
| 「意識する」「努める」「貢献する」「向上を図る」**のみ**で終わる目標・達成基準 | **ポイント 3** の NG 例と同趣旨 |
| 「心がける」「適宜」「随時」「可能な限り」「〜等」だけで**頻度・期限が定まらない** | 行動はあるが測定不能 |
| 「状態となる」「できるようになる」「独力で推進できる」**のみ**（何をもって達成とするか不明） | 判定基準・証跡を達成基準側に要否を検討 |
| 「同上」で**参照先が特定できない**（通期／上期／下期・ターゲット／ミニマムのどれか不明） | 読み手が迷うときのみ指摘（当該メンバーの**過去期の同上の用法**は尊重） |

#### 3.2 基準が明確ではない

**達成基準（ターゲット／ミニマム）**および**行動を含む目標文**について、期末・期中に**第三者が判定できるか**。

| 確認項目 | 不足例 |
| --- | --- |
| **数量** | 件数・％・人数・時間・金額のいずれかが無い（または集計母数が不明） |
| **頻度・期限** | 週次・月次・○月末まで等が無い |
| **対象範囲** | 「担当案件」「チーム内」等の範囲定義が無い |
| **提出物・証跡** | 管理表・議事録・レビュー記録等が無い（設定理由にだけ書いてある場合も要検討） |
| **ターゲットとミニマムの差** | 両者が実質同内容・差が読み取れない |
| **通期・上期・下期の対応** | 上期のみ具体で通期が「同上」のみ等、**半期ごとの判定基準**が欠ける（空欄の下期は未記入扱いで**空欄自体は指摘しない**） |

**ポイント 3**（測れる形）・**セルフチェック「測定できるか」「証跡が残るか」**と重なるが、本節は**文言の曖昧さではなく判定不能**に焦点を当てる。

#### 3.3 矛盾

**同一枝番内**または**通期・上期・下期の対応**で、記載が**両立しない**箇所がないか。

| 種類 | 例 |
| --- | --- |
| **数値の加算・整合** | 上期＋下期の売上・利益等が通期ミニマム／ターゲットと**明らかに不一致**（利益率前提の積み上げ含む） |
| **目標と達成基準** | 目標は「品質分析」、達成基準は「品質管理」など**用語・スコープの食い違い** |
| **上期と通期の水準** | 上期目標の到達像と通期目標の到達像が**逆転**している（意図的な段階設計は尊重し、**誤記・コピー漏れ**に見えるとき指摘） |
| **設定理由と達成基準** | 設定理由に「レビュー」「記録」とあるが達成基準に**無い**（またはその逆） |
| **ターゲットとミニマム** | ミニマムの方がターゲットより**厳しい**・要求水準が逆 |

**数値の正誤**（会社公表 KPI との一致）は主目的としないが、**計算上の矛盾**は本節で指摘する。\
**`（仮: …）`・`（要確認: …）`** は未確定の明示として残し、確定値の創作はしない。

### 4. 目標設定チェックポイント（方針整合）

作業開始時に **`目標設定チェックポイント.md` を Read** し、次を**確認**する（**すべてを本文に書き換えない**。該当時のみ `<改善案>` で示す）。

| 参照節 | 確認内容（要約） |
| --- | --- |
| **ポイント 1** | 結果指標だけで終わっていないか。**行動・プロセス**が書かれているか |
| **ポイント 2** | 目標全体から組織・チーム目標との**紐づけ**が読み取れるか（**管理シートへの組織目標名の明記は不要**。因果が不明なときのみ `<改善案>`） |
| **ポイント 3** | 達成基準が**測れる形**か（件数・頻度・期限・提出物）。「意識する」「貢献する」**のみ**は NG |
| **セルフチェック 5 項目** | 上位目標・行動目標・測定・証跡・**等級相応**（`###` 直下の **G1〜G4** と照合） |
| **目標設定例（G4）** | G4 の参考（**G4 以外は等級に合わせた期待水準**で判断。例文のコピー提案はしない） |

## 尊重する原則（必須）

1. **各メンバーが記載した文章を尊重**する。第三者に「AI が書いた」と悟られる**メタ文**を `<改善案>` にも書かない。
2. **メンバー間で表現を統一しない**（語尾・見出し記号・「同上」の使い方等は**個人の過去文に合わせる**）。
3. **必要以上の改変をしない**。誤字と**方針上の明確な不足**以外は、**指摘しない**か **チャットで一言**に留める。
4. **本文は直接編集しない**（**`<改善案>` ブロックの追記・削除**のみ可）。

## `<改善案>` の書式（必須）

### 追記位置

- 当該 **`#####` の本文**（空行を挟んでもよい）の**直後**、**次の `#####` または `####` の直前**に置く。
- **既存本文の行は 1 文字も変えない**。

### ブロック形式

指摘がある項目**のみ**付ける。問題なしの項目に**空の `<改善案>` は付けない**。

```markdown
（既存の本人本文 — 変更禁止）

<改善案>
（ここに修正案の全文、または差し替えたい段落のみ）
改善理由：（なぜ直すか。誤字／表現／チェックポイントのどれかを明示）
</改善案>
```

- 開始タグは **`<改善案>`**、終了は **`</改善案>`**（半角）とする。
- **コールアウト**・**`【校閲・改善案】` 見出し行**・索引節は**付けない**（元の書式のみ）。
- **`改善理由：`** はブロック内の**最後**に 1 行以上で書く（複数理由は箇条書き可）。
- **改善理由**には、可能なら **指摘種別**（**曖昧**／**基準不明確**／**矛盾**／誤字／表現）と、\
  **`目標設定チェックポイント.md` のどの観点か**（例: 「ポイント3・測定可能性」）を短く添える。

### 再校閲時

- 同一 `#####` に**既に `<改善案>` がある**場合は、**古いブロックを削除してから**新しい 1 ブロックに置き換える（**二重付け禁止**）。
- ユーザーが **改善案を本文へ取り込んだ**と明示したときは、**`<改善案>` ブロックを削除**する（**本文の更新**は **`mokuhyo-draft`** または**ユーザー本人**が行う。本 SKILL は**取り込み代行をしない**）。

### 改善案の見つけ方（管理シート上）

- **管理シートに `### 校閲・改善案一覧` 等の索引節は設けない**。
- **検索**: `<改善案>`（Obsidian／エディタの全体検索）。
- **一覧**: 校閲完了時の**チャット報告**（メンバー別・枝番・項目名。§5）。

## 作業フロー

### 0. 前提確認

- 対象期・全メンバー一覧を確定する（`###` を列挙）。
- **`目標設定チェックポイント.md`** を **Read** する。

### 1. Read

- 対象期節を**通読**（メンバーごと・枝番ごと）。
- 必要に応じ、**同一メンバーの N−1 期**の同項目を **Read**（文体・用語の尊重用）。

### 2. 校閲（メモ）

- **枝番単位**で通期／上期／下期の目標・達成基準・設定理由を**横断して**読み、\
  **曖昧な表現**・**基準の不明確さ**・**矛盾**の有無を先にメモする（上記 **§3**）。
- 続けてメンバー × 枝番 × `#####` ごとに、誤字脱字・表現・**§4 チェックポイント**をメモする。
- **指摘なし**の項目はメモに「問題なし」とし、ファイルには何も追記しない。

### 3. 反映（`<改善案>` のみ）

- **1 ブロックずつ** `StrReplace` / `Write` で追記（**`replace_all` 禁止**）。
- 各ブロックは **§「ブロック形式」** のとおり（**`<改善案>` … `改善理由：` … `</改善案>`** のみ）。
- 追記順序の推奨: **ファイル末尾のメンバーから逆順**、または **枝番・項目の出現順**（衝突を避ける）。

### 4. 検証

- 対象期以外に diff がないことを確認する。
- **既存本文**が変わっていないことを確認する。
- **`markdownlint-fix` SKILL** に従い、**`人事考課_管理シート.md`** の lint を解消する。

### 5. 報告（チャット）

| 項目 | 内容 |
| --- | --- |
| 対象期・メンバー数・枝番数 | 実施範囲 |
| 改善案の見方 | 検索 **`<改善案>`**（索引節・コールアウトは管理シートに設けない） |
| サマリ | `<改善案>` を付けた **項目数**、主な指摘カテゴリ（誤字／表現／**曖昧**／**基準不明確**／**矛盾**／チェックポイント） |
| メンバー別 | 指摘があったメンバー名と**枝番・項目名**の一覧（**全文の再掲は不要**） |
| 問題なし | 全項目問題なしのメンバーがいれば明記 |

**管理シートに書かないもの**: 「AI 校閲済み」等のメタ見出し・**`### 校閲・改善案一覧`** 等の索引節・ログ節の新設（**CursorLog** に記録する）。

### 6. CSV 同期（必須）

**`人事考課_管理シート.md`** を更新した**同一セッション**では、**`mokuhyo-kanri-sheet-csv` SKILL** に従い **`人事考課_管理シート.csv`** を**必ず**更新する（**`<改善案>` は CSV に含めない**が、**`.md` 変更後のミラー再生成は省略しない**）。

### 7. CursorLog

- **`obsidian-cursor-log` SKILL** に従い追記する。

## 禁止事項

- **対象期の本文**（`<改善案>` 以外）の**追加・削除・置換**
- **対象期より前**の期の編集
- **メンバー間の文体統一**・**大幅な言い換え**・**目標内容の独断的な差し替え**
- **数値・KPI の確定値の創作**（仮値ラベルの削除を含む）
- **目標ジャンル**の無断変更
- **スクリプト**による一括置換・一括生成
- **`<改善案>` なし**でのチャットのみ指摘で終了（ユーザーが「ファイルには書かずチャットのみ」と**明示**した場合を除く）
- **`mokuhyo-draft` と混同**して下書きを新規作成すること（依頼が校閲のみのとき）

## ユーザー明示時の例外

| 指示 | 対応 |
| --- | --- |
| 「チャットだけでよい」 | `<改善案>` は付けず、チャットに要約のみ |
| 「○期だけ」 | 指定期为対象期 |
| 「○さんだけ」 | 当該 `###` のみ（**対象期は最新期のまま**） |
| 「改善案を本文に反映して」 | **本 SKILL では実行しない**。`mokuhyo-draft` または本人編集に委ね、`<改善案>` 削除のみ依頼に応じて可 |
| 「改善案をすべて削除」 | 対象期の `<改善案>` … `</改善案>` ブロックのみ削除 |
