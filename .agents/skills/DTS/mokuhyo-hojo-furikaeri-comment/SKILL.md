# mokuhyo-hojo-furikaeri-comment（振り返り時・達成状況コメント・補助・１次評価者）

**`人事考課_管理シート.md`** の**最新期**について、**長谷　晃英以外**の全メンバー各枝番の **達成状況コメント(補助・１次評価者)** を**生成して反映**する。

**更新するのは次のどちらか一方**（ユーザーまたは `評価の流れ.md` で決めた半期）:

- **`##### 上期達成状況コメント(補助・１次評価者)`**
- **`##### 下期達成状況コメント(補助・１次評価者)`**

欄名の「１次**評価**者」を、設定時の「１次**調整**者」と取り違えない。

**執筆者視点**は **1 次評価者（補助・長谷）**。当該半期の実績を認定し、PL として次に期待することを短く書く。**本人の達成状況コメント**・**本人 12 項目**・**設定時コメント**・**長谷本人の枝番**は本 SKILL の対象外。

**`mokuhyo-hojo-setteiji-comment`**（設定時）・**`mokuhyo-draft`**（本人目標）・**`mokuhyo-proofread`**（校閲）とは**別 SKILL**。\
文体の細部は設定時 SKILL の「PL・PM としてのコメント」「トーンのバランス」「長谷文体・AI 痕跡の排除」に合わせる。\
**字数**と**本人記載の扱い**は**本 SKILL を正**とする（設定時の「おおむね100文字」「言い換え禁止」をそのまま適用しない）。

myrules を厳守（**スクリプト一括置換禁止**・**報告前 CursorLog**・**Markdown は編集ツールでブロック単位**）。

**最初の作業（毎回必須）**: **本ファイル `SKILL.md` を全文 Read** してから着手する。会話要約や **`AGENTS.md` のみ**を正本にしない。

- **`/mokuhyo-hojo-furikaeri-comment`**
- **設定時コメント**の依頼は **`mokuhyo-hojo-setteiji-comment`**。本 SKILL では書かない
- **長谷本人の振り返り**（達成状況コメント(本人)）は **`mokuhyo-furikaeri`**

## 対象範囲

### 期と半期

1. 管理シート内 **`## {数字}期`** の**期番号最大**を対象期とする。ユーザーが別期を明示したときだけその期にする。
2. **上期か下期か**は次の順で決める。
   - ユーザーが「上期」「下期」と明示 → それに従う
   - 未明示 → **`評価の流れ.md`** を Read し、当期の振り返り対象の半期が書いてあればそれに従う
   - それでも決まらない → **書かずに確認する**。暦の月から半期を推測しない
3. 一度の実行で更新するのは**決めた半期の補助コメント欄と補助評価欄**だけ。もう一方の半期は触らない。

### メンバー・枝番

- 対象期の **`### {期} {氏名}`** のうち、**氏名が「長谷　晃英」でないもの**をすべて対象とする。
- **`### {期} 長谷　晃英`** 配下は一切編集しない。
- ユーザーが「○さんだけ」と明示したときは当該 `###` のみ。
- 各 **`####`** の、決めた半期の **`##### {上期|下期}達成状況コメント(補助・１次評価者)`** と、対応する **`##### {上期|下期}補助評価`** を更新する。

### 触らない

本人 12 項目、**達成状況コメント(本人)**、もう一方の半期（補助評価欄を含む）、設定時コメント、目標ジャンル、メンバー行、**`<改善案>`**、**対象期より前**の `##` 配下。対象期より前は **Read のみ**。

## 事実の範囲（創作禁止）

実績・数値・評価記号の材料は次に限る。

1. **対象期・当該枝番・当該半期**の **達成状況コメント(本人)**
2. 同じ枝番の **当該半期の達成基準**（ターゲット・ミニマム）と、下期なら本人が通年実績として書いている範囲の **通期目標**
3. ユーザーが**チャットで渡した実績**（本人欄が空でも、渡した事実の範囲だけ書いてよい）

| 状態 | 対応 |
| --- | --- |
| 本人コメントがあり、基準と突合できる | 補助コメントを書く |
| 本人コメントが空で、チャットの実績もない | **その枝番はスキップ**。空欄のまま残し、報告で「本人コメント空」と出す |
| 事実が一部しかない | 分かる範囲だけ書き、**評価記号は付けない**。足りない点はチャットで確認する |

- 本人が書いていない工数・件数・◎○△× を補わない。
- 課題の推測、「おそらく達成」は書かない。
- **`課題.md`** は組織・PL の文脈の参考に限る。打ち手の復唱、課題 ID、見出しは本文に書かない。編集は **`work-kadai-update`**。

## 署名・文末

- コメントブロックの**最終行**は **`（補助・長谷）`** で終える。
- **`（長谷）`** は使わない。
- コメントは**2行構成**とし、署名は2行目の末尾に置く。

## 書き方

### 何を書くか

1. **実績の認定**（短く）。本人の報告と達成基準を突合し、達成／未達と、記号を付けられるときだけ補助評価を書く。54 期の「本人の報告の通り、…補助評価は「◎」とした。」に近い。
2. **PL としての見立て**（本人欄に無い角度を 1 点）。現場で見えた進め方、任せる範囲、次の半期や次の役割で伸ばしてほしい点。
3. **前向きな到達像**を必ず 1 文。戒めだけで終えない。

本人の文章の全文転記はしない。実績の認定に必要な数値・事実は短く触れてよい（設定時コメントの「言い換え禁止」とは違う）。

### 補助評価の定型句

過去の補助評価コメントとの文体を揃えるため、評価記号を付ける場合は、本文の1行目に次の定型句をそのまま使用する。

- ターゲット達成: `本人の報告の通り、ターゲット目標まで達成したと認識しているため、補助評価は「〇」とした。`
- ミニマム達成: `本人の報告の通り、ミニマム目標まで達成したと認識しているため、補助評価は「△」とした。`
- ミニマム未達: `本人の報告の通り、ミニマム目標未達と認識しているため、補助評価は「×」とした。`
- 本人未達報告・補助ミニマム達成: `本人はミニマム目標未達と報告しているが、補助評価ではミニマム基準を満たしていると認識しているため、補助評価は「△」とした。`

ターゲットを大きく上回る場合は既存の「ターゲット目標を大きく上回り達成したと認識しているため、補助評価は「◎」とした。」等の表現を確認し、未達なのに「未達と認定します」のような別形式へ置き換えない。

### 本人報告と補助評価が異なる場合

本人が「ミニマム未達」等と報告していても、達成基準との突合結果から補助評価では基準を満たすと判断する場合がある。この場合は「本人の報告の通り」とは書かず、上記の「本人未達報告・補助ミニマム達成」の定型句を使用する。

### 補助評価欄の同期

補助コメントの1行目に `補助評価は「◎」とした。`、`補助評価は「〇」とした。`、`補助評価は「△」とした。`、`補助評価は「×」とした。` のいずれかを記載した場合は、同じ枝番の対応する独立欄にも同じ記号を反映する。

- 上期コメント → `##### 上期補助評価`
- 下期コメント → `##### 下期補助評価`

コメントに評価記号を明記しない場合は、根拠のない評価記号を独立欄へ補わない。コメントと独立欄の記号が異なる状態を残さない。

### 字数

設定時コメントの **100 字目安は使わない**。コメント全体は**2行**とし、1行目は定型句、2行目は署名込みで**50〜100文字程度**を目安とする。2行目にはPLとしての見立てと、次の半期への期待を簡潔に含める。

### 参考の優先

1. 対象期・当該枝番の**既存**の、同じ半期の補助コメント（あれば。論点は踏まえ、現行 SKILL で再生成する）
2. 当該半期の **本人コメント** と **達成基準**
3. **N−1 期**の同欄（文体・段落・署名）。**枝番番号では突合しない**。論点は **同一目標ジャンル**を優先し、文体は **直近**を優先する
4. 任意: **`課題.md`**（セッション冒頭に 1 回 Read）

### 既存本文

- **空欄** → 事実が揃っていれば新規生成。揃っていなければスキップ。
- **本文あり** → 実行時点の本 SKILL で再生成して差し替える。無変更複写はしない。
- ユーザーが「この枝番は触らない」「既存のまま」と明示した枝番だけスキップ。

### 避ける

- 毎枝番が「本人の報告の通り。期待します。」の同型だけ
- 抽象ラベルの連打（「ポジションアップの土台」「直結します」の乱用）
- 「AI が生成」「下書きです」等のメタ文、タスク番号
- 本人の口調で書くこと

## 作業フロー

### 0. 前提

- 本 `SKILL.md` を全文 Read する。

### 1. Read

### 2. 文案

### 3. 反映

**`#####` 単位**で **`StrReplace`**（**`replace_all` 禁止**）。Work 配下なので反映前に **`work-folder-update` SKILL を全文 Read** する。

### 4. 検証

- 差分は対象期・長谷以外・決めた半期の補助コメント欄と、コメントに記載した評価記号に対応する補助評価欄だけ。
- 評価記号を記載したコメントと独立した補助評価欄の記号が一致している。
- 各ブロックの最終行が `（補助・長谷）`。
- **`markdownlint-fix`** で管理シートの lint を解消する。

### 5. 報告

対象期、半期、反映した氏名、書いた件数、スキップ（本人コメント空、ユーザー明示、長谷本人）を出す。

### 6. CSV と CursorLog
