# ojt-monthly-report-manager-comment（OJT月報・上長フォローコメント）

新人OJT月報の `上長フォローコメント` を、上長である長谷の視点で作成する。
対象は管理用Markdownノートのみとし、ExcelファイルはRead・Writeとも行わない。

## 最初の作業

1. Work配下を編集する場合は、先に `work-folder-update` SKILLを全文Readする。
2. 対象月の月報管理ノートをReadする。
3. 対象月の本人記載、OJTトレーナーコメント、既存の上長フォローコメントを確認する。
4. 同一ノートの先月以前、必要に応じて前年度以前の `### 上長フォローコメント` 本文だけをReadし、長谷の文体・語尾・段落構成を参考にする。

## コメントの作成方針

- 本人の実績・反省・次月目標を単に要約しない。
- 本人の成長を具体的に認めたうえで、次の業務・配属・役割につながる期待を1点に絞って書く。
- OJTトレーナーの見立てと**矛盾させない**。ただし**同じ方向のコメントにしてはならない**（下記「トレーナーとの視点分担」）。
- 課題だけの指摘にせず、前向きな到達像を必ず含める。
- 根拠のない実績・評価・約束を創作しない。
- 先頭は対象月の取り組みをねぎらう言葉から始める。
- やわらかい表現で、本人に語り掛けるような口調にする。命令的・評価的に断定しすぎない。
- 参考対象は、先月までの `上長フォローコメント` に限定する。同一メンバー分を優先し、なければ前年度以前の上長フォローコメントの文体を参考にする。
  文面を無変更で複写せず、対象月の内容に合わせて作成する。
  同月のトレーナーコメントは**重複回避の突合対象**であり、論点のコピー元ではない。
- 長谷の通常のです・ます調で、おおむね200〜300文字を目安にする。
  内容のまとまりに応じて改行・空行を入れ、読みやすくする。

## トレーナーとの視点分担（必須・来月以降も同じ）

月報にはトレーナーコメントと上長コメントが並ぶ。読み手に同じ話が二度出ないよう、**レイヤを分ける**。

- **先に**同月の `### OJTトレーナーより` を読み、そこで既に書かれている論点・助言・到達像・言い回しを列挙する。
- 上長コメントではそれを**繰り返さない**。同じ結論の言い換え（「大事だ」「意識して」「一つずつ」「質問して」等）での重ね書きも禁止。
- **発展は可**: トレーナーが触れた論点を、同じ文で終わらせず、上長として一段深い原則に進めてよい。
  例: 「UTで障害を見つけることは問題ではない」→「見つかることが問題なのではなく、見逃すこと、およびUTで見つけるべき障害がITで出ることが問題」。
- **トレーナー側の典型**: 研修の進め方、スキルの身につけ方、成果物の目的、日々の姿勢、質問の仕方。
- **上長側の典型**: 配属・参画時期の判断、案件での役割、期待の置き方、現場での立ち位置、品質・工程の原則。
- 本人の取り組みへのねぎらいは書いてよい。成長の具体は、トレーナーが触れていない事実に限るか、判断の根拠として一行に留める。
- 矛盾する指示は出さない。足りない点は上長レイヤで補う（育成手順の復唱ではない）。

## 生成後の自己レビュー

反映前に、作成したコメントを次の観点で自己レビューし、必要なら書き直す。

- 月報の本人記載・OJTトレーナーコメントと矛盾していないか。
- **同月トレーナーと並べて読み、同じ結論・同じ助言が二度出ていないか**（出ていれば上長側を別視点にするか、一段深い原則へ発展させる）。
- トレーナーコメントを伏せても、上長コメント単体で配属・役割・期待、または品質・工程の原則の話になっているか。
- ねぎらい、成長の認知、次への期待がやわらかく伝わるか。
- 過去の上長フォローコメントの文体と大きく乖離していないか。
- AIが生成した定型文ではなく、長谷が本人に語り掛けて書いた自然なコメントに見えるか。
- 抽象的な称賛、過度に整い過ぎた表現、同型の文末の連続がないか。

## 反映先

- コメントを作成した場合は、管理ノートの同月 `### 上長フォローコメント` を必ず更新する。
- ExcelのRead・Writeは禁止する。根拠は管理ノートに転記済みの内容に限定する。

## 確定

- ユーザーが「確定」と明示したら、当該月の上長フォローは**確定稿**とする。以後その月の文面は、ユーザー指示なく書き換えない。
- Excelへの転記はユーザーが行う。エージェントはExcelをRead・Writeしない。
- 確定時は `Work/Todo.md` に、当該月の確定稿を月報Excelへ転記する未完了タスクを載せる。
  管理ノートへの記載Todoは完了のままにする。

## 検証と報告

- コメントの根拠となった月報の記載と矛盾しないことを確認する。
- 管理ノートを更新した場合は、markdownlintを実行して同一ファイルのエラーを解消する。
- ファイルを変更した場合は、`obsidian-cursor-log` SKILLに従ってCursorLogを更新する。
- 報告では、対象月、文案または反映先、確認結果を簡潔に示す。
