# work-todo-update（Work Todo 更新・運用）

長谷が**能動的に着手しないと進まない**次アクションは、**単発と繰り返しで別ノート**にする。\
背景・業務の正本は各業務ノートとし、Todo には**期限付きの実施タスク**と、
着手時に必要なタスク単位の詳細を併記できる。\
進捗会議・定例会など**時間が来たら始まる出席・参加は載せない**（開催の正本は `Work/定例・報告/定例会.md`）。

**振り分け（必須）**:

- **単発** → `Work/Todo.md`
- **繰り返し**（週次・月次・3ヶ月次・年次等） → `Work/Todo-定例作業.md`
- 混ぜない。`/next-action-work` は**両方**を読む

**最初の作業**: 本ファイルを **Read** する。続けて対象の正本（単発なら **`Work/Todo.md`**、
繰り返しなら **`Work/Todo-定例作業.md`**。横断なら両方）を **Read** する。\
**`Work/` を編集する前**に **`work-folder-update` SKILL** も **Read** する（振り分けゲート）。

myrules を厳守する（**スクリプト一括置換禁止**・**報告前 CursorLog**）。

要約は同ディレクトリの **`AGENTS.md`** と整合させる。

## 使用タイミング（発火）

- **`Work/Todo.md`** または **`Work/Todo-定例作業.md`** の**追加・完了・期限変更・並び替え・セクション整理**を依頼されたとき
- ユーザーが「タスク追加」「完了」「Todo更新」「Work Todo」「繰り返しTodo」「定例作業」等と言ったとき
- **`work-folder-update`** の振り分けで、本人の次アクションが**新規・完了・期限変更**したとき（ユーザーが「Todo更新」と明示しなくても**同一セッションで反映**。単発／繰り返しでノートを分ける）
- **`next-action-work`** 後にユーザーが特定 Todo を完了／追加したとき

## 正本パス

| 用途 | パス |
| --- | --- |
| **単発（正本）** | `D:/OneDrive/アプリ/remotely-save/Obsidian/Work/Todo.md` |
| **繰り返し（正本）** | `D:/OneDrive/アプリ/remotely-save/Obsidian/Work/Todo-定例作業.md` |
| **繰り返しの型・写し方** | `D:/OneDrive/アプリ/remotely-save/Obsidian/Work/社内手続き/PL作業TODO.md` |

各ノート冒頭の「更新ルール」は利用者向け要約。**手順の正本は本 SKILL**（変更時はノートと整合させる）。

## 対象外

- FishTrack / MyPokedex / otayori-navi / FaiNavi 等の**副職・趣味**タスク
- **`DevProject/plans/統合作業スケジュール.md`** の計画用タスク（Fxx / Pxx 等）
- **`Work/課題.md`** の課題ブロック本体（→ **`work-kadai-update`**）。課題から生じる**実施一手**だけ Todo へ載せる
- コミット・プッシュ・PR・デプロイの案内
- **進捗会議・定例会など、時間が来たら始まる出席・参加**（正本は `Work/定例・報告/定例会.md` とカレンダー）。
  会議前の宿題案内・資料準備・招集など、長谷が先に動かないと進まない実施は載せてよい
- **長谷がオブザーバーで、実施主体がメンバーの作業**（例: 生成AIワーキングのアイデア具現化・導入）。
  正本は業務ノート。長谷が先に動かないと進まない準備・案内だけ載せる
- **単発ノートへ繰り返しを載せる**、または**繰り返しノートへ単発を載せる**（混ぜない）

## ノート構造（必須）

| 要素 | ルール |
| --- | --- |
| **大区分** | **`## 未完了`** を**上部**、**`## 完了`** を**下部** |
| **テーマ** | 各大区分の下に **`###`**（例: 最優先・直近・生成AIワーキング・財務・CS） |
| **混在禁止** | **単発**は同じ `###` 内に `[ ]` と `[x]` を**置かない**。**繰り返し**は親の下で対象月の `[ ]` と `[x]` が混在してよい |
| **完了時（単発）** | `[x]` にし、**未完了の該当行を削除**して **完了セクション**の同テーマ `###` へ移す。空になった未完了側 `###` は削除してよい。 |
| | 当該タスクの完了条件に関する**未決が正本に残っていたら完了にしない** |
| **完了時（繰り返し）** | **対象月のチェック行だけ** `[x]`。親タスクは未完了に残す。完了セクションへ移さない |
| **着手不可** | 次のいずれかならチェック行（単発ならタスク行）に **`🚫 着手不可`**。条件が無くなったら外す。 |
| | (1) **前タスク**（他の Todo）が当該対象月で未完了。Todo ID は同一対象月の `[x]` まで |
| | (2) **キック**（Todo 外の到来。例: 顧客からのメール受信）が未到来。ユーザー明示まで |
| | (3) **着手可能日**があり、今日がそれより前（例: 毎月1日まで着手できない） |
| | 前タスクとキックは別。前タスク `なし` でもキックがありうる。期限と着手可能日は別 |
| **着手推奨** | **ブロッカーではない**（`🚫 着手不可` にしない）。期限・着手可能日とは別。 |
| | 親に **着手推奨の計算**。対象月行（単発ならタスク行）に **着手推奨日** `YYYY-MM-DD`。 |
| | 例: 期限当日。期限の3営業日前（有休も考慮）。毎月5日以降。無い行は `なし`。 |
| | 3営業日前は Excel がある間は Excel で出した日付。Work 側で再計算しない。 |
| | カレンダー日（毎月5日）は対象月の日付を書いてよい。 |
| | 今日が着手推奨日より前なら `/next-action` `/next-action-work` の**優先度を落とす**（除外しない）。 |
| | 期限超過は推奨前でも上げる。印は `⏳ 推奨前`（任意。日付比較が正） |
| **新規** | **未完了**の適切な `###` へ `[ ]` で追加。無いテーマは `###` を新設してよい |
| **詳細** | 正本ノートへ背景・業務詳細を書き、Todoには期限・完了条件に加えて、着手に必要な要点をタスク配下のインデント箇条書きで記載してよい |

### 推奨テーマ例（固定ではない）

最優先（期限付き）／直近／生成AIワーキング／若手育成WG／1on1／財務・CS／育成・体制／稼働・労務。
繰り返しノートでは週次／月次／3ヶ月次／年次、または PL カテゴリ（A〜H）も可。

## タスクの書き方

| 観点 | ルール |
| --- | --- |
| **粒度** | 「〜する必要がある」は**背景**。チェックリストの動詞は**実施タスク**（例: 連絡フローを確立する）。背景と実施を混同しない。**出席・参加**だけは実施に見えても、時刻到来で始まる予定なので Todo にしない。**オブザーバーでメンバーが実施する作業**も Todo にしない |
| **期限** | 未完了には **`YYYY-MM-DD`** を必ず書く。`近日中`・`要確認`・`都度`・`継続` 等の曖昧期限は**使わない**。判断できないときは**登録前にユーザーへ確認**。 |
| | PL 繰り返しを Excel から写すときは、計算済みの日付を使う。Work 側で営業日を再計算しない。 |
| | **有休を営業日に数えるかはタスクによる**（正本は `PL作業TODO.md`）。一律に除外しない |
| **完了条件** | 各タスクに、成果物・反映先・確認状態など、完了を客観的に判定できる**完了条件**を明記する。既存タスクを更新するときも、完了条件がなければ追記する |
| **着手時の詳細** | 対象・前提・入力・手順・連絡先・参照先・判断待ちなど、実際の着手に必要な情報はタスク配下に記載してよい。正本ノートの全文複製や冗長な経緯は避ける |
| **繰り返しの定義** | **親は1タスク**。完了条件・Excel 列Dの**期限の計算**・**着手可能日の計算**・ |
| | **前タスク**・**キック**・**着手推奨の計算**は親に1回だけ書く。列F作業内容があれば親に写す。 |
| | `〃`・数式は表示結果。空の前タスク／キックは `なし`。列対応は `PL作業TODO.md` |
| | Excel 列Eはキックと前タスクに分けて写す（Todo ID→前タスク、メール等→キック） |
| | **対象月ごとにチェック行だけ**出す（`[ ] 対象月: YYYY-MM、期限: YYYY-MM-DD`）。 |
| | 着手可能日があれば `着手可能日: YYYY-MM-DD`。着手推奨があれば `着手推奨日: YYYY-MM-DD`。 |
| | 同じタスクを対象月の数だけ並列複製しない |
| | 着手不可の対象月は `、🚫 着手不可` を付ける。推奨前は `⏳ 推奨前`（任意） |
| **定例** | 宿題案内・資料準備など**能動着手が必要な実施**だけ載せる。1回完了で定例全体を完了にしない。 |
| | **出席・参加そのものは各回登録しない**。未完了は**当月を含む向こう3か月分**の対象月チェック行を常に出す。 |
| | 対象月が完了したらその行だけ `[x]`。窓の右端が3か月先になるよう不足分を足す。1回限りは `Todo.md` |
| **リンク** | 背景の正本は `[[wikilink]]`（例: `[[勤怠]]`） |
| | PL 繰り返しのマニュアルは Todo に `参照:` 名だけ。本文は写さない。 |
| | 現状の本文正本は SharePoint の公式 PDF と、保険第五担当独自の Excel。 |
| | 将来は Cursor 上にマニュアル。現状は手続きノートへ足さない |
| **完了付記** | 完了日が分かるときは括弧に `YYYY-MM-DD 完了` を付けてよい |

## 作業フロー

1. **`work-folder-update` SKILL** を Read（Work 編集ゲート）
2. **本 SKILL** を Read（未読なら）
3. 対象ノートを Read（単発は **`Work/Todo.md`**、繰り返しは **`Work/Todo-定例作業.md`**。横断なら両方）
4. 追加・完了・期限変更を **StrReplace / Write**（**`replace_all` 禁止。ブロック単位**）し、
各タスクの完了条件を明記する。繰り返しは親1つ＋対象月のチェック行。3か月窓を保つ。
   着手不可（前タスク未完了・キック未到来・着手可能日前）の対象月は `🚫 着手不可`。
   対象月を `[x]` にしたら、それを前タスクに持つ行を再判定する。
   キック到来・着手可能日到達でも再判定する。
   着手推奨日を付けたら、今日より前なら優先度を落とす印を検討する（`⏳ 推奨前`）
5. 単発は未完了／完了の混在がないことを確認。繰り返しは対象月行の `[x]` を親の下に残してよい。
   `🚫 着手不可` の付け忘れ・外れ忘れがないことを確認。
   完了にした単発の完了条件について、正本の未決が残っていないことを確認
6. **markdownlint**（当該ファイル）
7. **`obsidian-cursor-log`** でCursorLog追記
8. 報告に「CursorLogは更新しました」を含め、必要なら残作業を短く案内（コミット案内はしない）

## 他 SKILL との関係

| SKILL | 関係 |
| --- | --- |
| **`work-folder-update`** | Work 編集の入口。Todo 詳細手順は本 SKILL |
| **`work-kadai-update`** | 課題正本。Todo は課題から切った一手のみ |
| **`next-action-work`** | 次の一手の提案（原則 Read のみ）。反映依頼が出たら本 SKILL |

## 典型パターン

| パターン | 動作 |
| --- | --- |
| 「タスク追加・期限 9/14」 | 未完了の適切な `###` に `[ ]` 追加。詳細は関連正本へ |
| 「進捗会議に出席」を Todo へ | **入れない**。開催の正本は `Work/定例・報告/定例会.md` |
| 「週次の宿題案内」を `Todo.md` へ | **入れない**。周期の各回は `Todo-定例作業.md` |
| 「月次の請求署名」を `Todo.md` へ | **入れない**。繰り返しは `Todo-定例作業.md` |
| 「年次の年末年始周知」を `Todo.md` へ | **入れない**。年次も `Todo-定例作業.md` |
| 「単発の検討」を `Todo-定例作業.md` へ | **入れない**。単発は `Todo.md` |
| 「メンバーが導入する」を Todo へ | **入れない**（長谷がオブザーバー）。正本は該当業務ノート |
| 「1、完了」 | 当該行を `[x]` にし完了セクションへ移す（単発）。完了条件の未決が正本に残るときは完了にしない |
| 「1、完了」（繰り返し） | 対象月のチェック行だけ `[x]`。親は移さない。窓の右端が欠けていれば足す。 |
| | 完了した行を前タスクに持つ同一対象月から `🚫 着手不可` を外す（他条件が残れば残す） |
| 「キック来た」「前タスク完了」「着手可能日になった」 | 当該対象月の `🚫 着手不可` を外す（他条件が残れば残す）。 |
| | Todo ID は先行の `[x]` で判定。キックはユーザー明示。着手可能日は今日と比較 |
| 「着手推奨日になった」 | `⏳ 推奨前` を外す。候補から除外していたわけではない。優先度を通常へ戻す |
| 「検討は完了、実施は未完了」 | 完了側は検討だけにする。実施は未完了の別タスクにする。 |
| | **正本に当該検討の未決が残っていたら完了にしない**（未完了へ戻す） |
| 正本更新で次アクション発生 | ユーザー明示がなくても同一セッションで未完了へ追加 |
| 期限変更 | 未完了側の括弧・最優先見出しの日付を更新 |
