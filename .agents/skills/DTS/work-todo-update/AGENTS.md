# work-todo-update

**`Work/`** 配下を触るときは先に **`work-folder-update` SKILL** を Read する（チャット情報の振り分けゲート）。

**`Work/Todo.md`**（単発）と **`Work/Todo-定例作業.md`**（繰り返し。週次・月次・3ヶ月次・年次等）の
**追加・完了・期限変更・未完了／完了セクション運用**。手順は **`SKILL.md`**。混ぜない。
`/next-action-work` は両方と Asana MCP を見る（Asana 手順は `next-action-work` SKILL）。

- **正本（単発）**: `D:/OneDrive/アプリ/remotely-save/Obsidian/Work/Todo.md`
- **正本（繰り返し）**: `D:/OneDrive/アプリ/remotely-save/Obsidian/Work/Todo-定例作業.md`
- **構成**: **`## 未完了` 上部**・**`## 完了` 下部**。テーマは `###`。
  **単発**は同じ `###` に `[ ]` と `[x]` を混在させない。
  **繰り返し**は親の下で対象月の `[ ]` と `[x]` が混在してよい
- **完了時（単発）**: `[x]` にして**完了セクションへ移す**（未完了側から削除）。
  完了条件に関する未決が正本に残っていたら完了にしない
- **完了時（繰り返し）**: **対象月のチェック行だけ** `[x]`。親は未完了に残す
- **着手不可**: 次のいずれかなら対象月チェック行に `🚫 着手不可`。
  前タスク未完了。キック未到来。今日が着手可能日より前。
  Todo ID は同一対象月の `[x]` まで。キックは到来の明示まで。
  期限と着手可能日は別。キックは前タスクと別（前タスクなしでもありうる）。
  `/next-action-work` は着手不可を候補にしない。
  着手推奨はブロッカーではない。推奨日前は next-action の優先度を落とす（除外しない）。
  期限超過は推奨前でも上げる
- **期限**: 未完了は `YYYY-MM-DD` 必須。曖昧期限禁止。不明なら登録前に確認。
  PL 繰り返しの Excel 期限は計算済みの日付を使う。再計算しない。
  **有休を営業日に数えるかはタスクによる**（一律に除外しない）。
  繰り返しは**親1タスク**。定義（期限の計算・着手可能日の計算・着手推奨の計算・前タスク・キック・作業内容）は親に1回。
  **対象月ごとにチェック行だけ**出す。同じタスクを並列複製しない。
  Excel 列Eはキックと前タスクに分ける。空は `なし`。
  マニュアルは Todo の `参照:` 名だけ。本文は写さない。
  現状の本文正本は SharePoint 公式 PDF と保険第五独自 Excel。
  将来は Cursor 上にマニュアル。現状は手続きノートへ足さない
- **粒度**: 背景と実施タスクを混同しない。詳細は正本ノート、Todo はチェックリスト。
  **能動着手が必要な実施だけ**載せる。進捗会議など時間が来たら始まる出席・参加は載せない。
  長谷がオブザーバーで実施主体がメンバーの作業（具現化・導入など）も載せない
- **定例**: 宿題案内・資料準備など能動実施だけ載せる。出席・参加は登録しない。
  単発の1回限りは `Todo.md`。周期は `Todo-定例作業.md`。
  未完了は**当月を含む向こう3か月分**の対象月チェック行を常に出す。完了後は窓の右端を足す
- **編集**: **myrules**（ブロック単位の `StrReplace` / `Write`。**`replace_all` 禁止**）
- 完了後は **`obsidian-cursor-log`**。編集後は **`markdownlint-fix`**

Always respond in Japanese when using this skill.
