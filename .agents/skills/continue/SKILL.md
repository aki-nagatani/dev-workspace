# 作業継続（continue）

## 目的

直前の作業が本当に未完了かを確認し、最後に完了した手順の直後から作業を再開する。
完了済みの作業を繰り返したり、関係のない作業を始めたりしない。

## 実行手順

1. **中断状況を確認する**
   - 現在のユーザー依頼、会話要約、直前の会話履歴を確認する。
   - 開いているファイル、未完了の TODO、直近の CursorLog、ターミナルの実行状態を確認する。
   - 対象リポジトリの `git status` と `git diff` を読み取り専用で確認する。
2. **未完了の根拠を分類する**
   - 未実行の手順、失敗した検証、未反映の仕様、残っている TODO、未確認のブラウザ状態を列挙する。
   - 完了済みの項目と未完了の項目を分ける。
   - 中断の根拠がない場合は、作業を重複実行せず、確認結果だけを報告する。
3. **自然な継ぎ手を決める**
   - 最後に完了した手順の直後を次の開始点にする。
   - エラーや問題の修正が必要な場合は、修正前に `error-handling-policy` と対象言語のエラー修正 SKILL を読む。
   - 対象ファイルやプロジェクトに固有の SKILL、`AGENTS.md`、仕様書を読み、既存の手順を引き継ぐ。
4. **作業を再開する**
   - ユーザーが依頼した範囲内で、未完了部分だけを実行する。
   - 既存の変更・ログ・仕様を上書きせず、直前の状態を保全する。
   - コミット、プッシュ、PR、マージ、デプロイは、ユーザーが明示的に依頼した場合だけ実行する。
   - `git reset --hard`、`git checkout --` などの破壊的操作は実行しない。
5. **検証して引き継ぐ**
   - 実装内容に応じてテスト、Lint、仕様検査、ブラウザ確認などを実行する。
   - ワークスペース内のファイルを変更した場合は、報告前に `obsidian-cursor-log` を更新する。
   - 作業を継続できない場合は、確認済みの事実、阻害要因、次に必要な操作を明示する。

## 報告

次の順で簡潔に報告する。

1. 中断していたと判断した根拠
2. 今回再開して完了した範囲
3. 検証結果
4. 残作業または阻害要因

「続けます」だけで開始せず、どの状態から何を継続したかを示す。
