# 作業継続（continue）

## 目的

このチャットで直前に行っていた作業が本当に未完了かを確認し、
最後に完了した手順の直後から作業を再開する。
完了済みの作業を繰り返したり、関係のない作業を始めたりしない。

## 対象範囲（最重要）

- 再開対象は**このチャット（同一会話）で直前にユーザーが依頼し、エージェントが着手していた作業**だけ。
- 次は再開対象にしない: 他チャットの作業、他チャットの CursorLog の記録、このチャットと無関係な未コミット差分、リポジトリ内の古い TODO、過去のターミナル履歴。
- このチャットに直前の作業がない（新しいチャットや、まだ作業を始めていない）場合は、作業を始めず「このチャットに再開できる作業がない」と報告し、再開する内容の指示を求める。
- 直前の作業が完了している場合は、完了済みと報告し、再実行しない。

## 実行手順

1. **このチャットの直前の作業を特定する**
   - 会話履歴から、このチャットでユーザーが直前に依頼した作業と、エージェントが最後に完了した手順を特定する。
   - このチャットで変更したファイル、実行したコマンド、行ったブラウザ操作を確認対象とする。
   - 上記の確認に限り、`git status` と `git diff`、ターミナルの実行状態、このチャットの作業に対応する CursorLog エントリを読み取り専用で確認してよい。他の作業の差分やログは対象外。
2. **未完了の根拠を分類する**
   - このチャットの作業について、未実行の手順、失敗した検証、未反映の仕様、未確認のブラウザ状態を列挙する。
   - 完了済みの項目と未完了の項目を分ける。
   - 直前の作業が完了している場合や中断の根拠がない場合は、作業を重複実行せず、確認結果だけを報告する。
3. **自然な継ぎ手を決める**
   - 最後に完了した手順の直後を次の開始点にする。
   - エラーや問題の修正が必要な場合は、修正前に `error-handling-policy` と対象言語のエラー修正 SKILL を読む。
   - 対象ファイルやプロジェクトに固有の SKILL、`AGENTS.md`、仕様書を読み、既存の手順を引き継ぐ。
4. **作業を再開する**
   - このチャットでユーザーが依頼した範囲内で、未完了部分だけを実行する。他チャットの作業範囲には広げない。
   - 既存の変更・ログ・仕様を上書きせず、直前の状態を保全する。
   - コミット、プッシュ、PR、マージ、デプロイは、ユーザーが明示的に依頼した場合だけ実行する。
   - `git reset --hard`、`git checkout --` などの破壊的操作は実行しない。
5. **検証して引き継ぐ**
   - 実装内容に応じてテスト、Lint、仕様検査、ブラウザ確認などを実行する。
   - ワークスペース内のファイルを変更した場合は、報告前に `obsidian-cursor-log` を更新する。
   - 作業を継続できない場合は、確認済みの事実、阻害要因、次に必要な操作を明示する。

## 報告

次の順で簡潔に報告する。

1. このチャットで再開対象とした直前の作業と、中断していると判断した根拠
2. 今回再開して完了した範囲
3. 検証結果
4. 残作業または阻害要因

「続けます」だけで開始せず、どの状態から何を継続したかを示す。
