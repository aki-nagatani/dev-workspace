# 本職を含めない次のアクション（next-action-nowork）

`next-action` から本職を除いた候補選定。`name` は **`next-action-nowork`**。

myrules を厳守して作業してください。

## 目的

製品・個人開発の状況と**本チャットの履歴**から、**いま取るべき次の一手**を整理する。
コード変更や実行は必須ではない。

**本職は常に対象外。** 時刻が営業時間でも、当日が営業日でも同じ。
期限超過の本職も出さない。

- **本職**: `Work/` の Todo・定例・課題・手続き、Asana、株式会社DTSの業務、CursorLog の本職残作業。
- **開かない**: `next-action`、`next-action-work`、`work-folder-update`、`work-todo-update`。
  開くと本職の手順が混ざる。
- **編集しない**: Work の `🚫 着手不可` 解除、Todo の追加・完了・期限変更。
- **`/next-action-work` は本 SKILL を開かない。** 本職だけの選定はそちらが正本。

## 参照する情報

根拠のない一般論だけの提案はしない。次を同列に読む。番号は読む順であり、優先度ではない。

1. **本チャットの履歴** — 製品・個人開発の未完了の合意と進行中の作業。本職の発言は候補にしない。
2. **`D:/OneDrive/アプリ/remotely-save/Obsidian/CursorLog/`** — 当日または直近の **「残作業・課題」**。本職の残作業は読んでも候補にしない。
3. **`D:/OneDrive/アプリ/remotely-save/Obsidian/DevProject/plans/スケジュール.md`**
   - 未完了タスク・週次を読む。**今週まで（過去週を含む）の未完了を優先**。
   - **次週以降**を先に進めると判断したときは、着手内容より先に当該ファイルの変更案を示す。
4. ユーザーが **対象プロジェクト** を指定していれば、その **`AGENTS.md`** と Obsidian 側 **仕様**
   （フォルダ型は **`INDEX.md`** 起点）。

**食い違い**: チャットとログ／計画が矛盾するときは、チャット側を自動採用しない。
両方を候補にするか、依存・ブロッカー・今週タスクで選ぶ。根拠が分かれる点は **推測** と明記する。

**本依頼文**: `/next-action-nowork` と同時に書かれた制約は、履歴ではなく**今回の指示**として従う。

## 提案のルール

- **期限超過を最優先**: 製品側で期限が今日より前の、実行可能な未完了を先にする。
  保留、`🚫 着手不可`、キック待ち、着手可能日が未来のものは除く。出すときは「期限超過」と明記する。
- **残作業を新規より先**: CursorLog の製品残作業、計画の進行中、チャットの未完了合意を、未着手より先にする。
- **着手中を終えてから新規**: 着手中が未完了なら、その完了かブロッカー解除を次にする。
  判断待ちで進めない残作業だけなら、その旨を前提に書き、進められる残作業を先にする。
- **解消済みは再提案しない**。
- **件数**: 比較の価値があるとき複数。**多くても 3 件**。1 件なら 1 件。3 件に揃えない。
- **優先順位**: 依存、リスク、影響範囲、ユーザーが明示したゴール。情報源の別では並べない。
  計画は今週までを優先。次週以降を先にするときはスケジュールの変更案を先に示す。
- **各候補**: タスクID、概要、実施内容、優先理由、前提・注意。不確実な点は **推測** と明記する。
- **除外**: コミット、プッシュ、デプロイ、PR、マージ。未コミット差分を理由にした案内もしない。
- **禁止**: 根拠のない提案、Git の促し、件数合わせ、本職タスクの混入。

## 候補出力前の実行可能性ゲート

候補ごとに次を確認し、1つでも欠ければ外す。

1. **未完了**である。完了済み、保留、判断待ちだけは外す。
2. **着手可能日が今日以前**である。未来日は出さない。「明日着手」も出さない。
3. **`🚫 着手不可` が残っていない**。前タスク未完了の着手不可は外す。
4. 前タスク、キックなどの着手条件が満たされている。
5. 期限超過・当日・未来期限は、着手できることを確認したあとで区別する。

## 出力形式

- 見出しは `## 推奨`。候補ごとに `###`。
- 箇条書きで簡潔。各候補は **タスクID／概要／実施内容／優先理由／前提・注意** が分かるようにする。

## 使用タイミング

- **ユーザーが `/next-action-nowork` と明示したときだけ**本 SKILL を Read する。
- 「次のアクション」「次に何をするか」は `next-action`。本職だけは `next-action-work`。
- **通常応答では本 SKILL を Read しない。** 末尾の 1 件は myrules「残作業・次アクションの案内」。
  本 SKILL を開かないことは、その節を省く理由にしない。
