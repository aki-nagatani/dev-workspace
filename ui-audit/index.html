MED OPEN FishTrack FT-O6 — グローバルヘッダーがフラット同列でスキャンしづらい

画面: 全画面共通ヘッダー（PC 横並び／SP ドロワー）

対象箇所

  • URL／画面: ログイン後の全ページ共通 partials/site_header.html（ .ft-site-header／#ftSiteNav.ft-site-nav）
  • 位置: ブランド下のグローバルナビ一式 （ホーム〜水位・アカウント領域。管理者メニュー含む）
  • 部品: フラットな <a> 群＋ details.ft-nav-tackle。現在地用の aria-current／active クラスは無し
  • 対象外: 「タックルを探す」内のプラグ／ワーム同居は FT-O2（本 ID はヘッダー全体の IA／スキャン性）

事象

到達自体は可能だが、今の形は「使いやすい」とは言い切れない。 記録（釣果・釣行・マイ*）／探す（タックル）／参照（水位）が 同じ重みのフラット同列で並び、視線の区画がない。 現在ページの視覚的手がかりがなく、PC では折返しでアカウント行が離れ、 SP ドロワーも長い同列リストになる。 /public-fields（パブリックフィールド）はヘッダーに無く、 他画面からの到達頼み。

何が問題か

  • スキャン性: カテゴリ混在の同列リストは、目的リンクを探すコストが高い（特に SP）
  • 現在地: 「今どこにいるか」がヘッダーから読めず、迷子・重複遷移が増えやすい
  • 発見性: パブリックフィールドなど参照系の入口がヘッダーに無く、水位と並ぶ期待とずれる
  • 密度: 設定／ログアウトがコンテンツナビと同列で競合し、折返し時に階層が崩れて見える

改善策
