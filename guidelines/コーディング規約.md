# コーディング規約

## ファイルサイズ方針

### ソースコードファイル（Python）

ソースコードファイル（`src/`配下のPythonファイル）のファイルサイズは以下の基準を遵守します：

- **理想**: 500行以下
- **許容**: 1,000行以下
- **上限**: 2,000行（超過時は分割を検討）

**超過時の対応**:
- 1,000行を超える場合: 分割を検討する
- 2,000行を超える場合: 分割を推奨（機能別・責務別に分割）

**分割方針**:
1. **機能別分割**: 関連する機能ごとにファイルを分割
2. **責務別分割**: ルーティング、ビジネスロジック、バリデーションなどを分離
3. **段階的分割**: 大きな機能単位から順に分割

**決定日**: 2025-11-20

**自動チェック**:
- pre-commitフック（`.githooks/pre-commit`）で自動チェックされます
- 許容を超えた場合: 警告を表示（コミットは成功）
- 上限を超えた場合: エラーを表示（コミット失敗）
- チェックスクリプト: `scripts/check_file_size.py`

### テストコードファイル

テストコードファイル（`tests/`配下のPythonファイル）のファイルサイズは以下の基準を遵守します：

- **理想**: 500行以下
- **許容**: 1,000行以下
- **上限**: 1,500行（超過時は分割検討）

詳細は `docs/plans/completed/テストカバレッジ増強計画.md` を参照してください。

## コーディングスタイル

### Python

- **フォーマッター**: Black（行長100文字）
- **リンター**: flake8（行長100文字）
- **インポート順序**: isort（Blackプロファイル）

詳細は `pyproject.toml` を参照してください。

## 命名規則

### Python

- **クラス名**: UpperCamelCase（例: `CatchLog`, `FishingTrip`）
- **関数・メソッド・変数・属性**: snake_case（例: `get_weather_data()`, `parse_exif_data()`）
- **定数**: UPPER_CASE_SNAKE（例: `DEFAULT_TZ`）
- **モジュール/ファイル/ディレクトリ名**: snake_case（例: `photo_store.py`, `weather_service.py`）

詳細は各プロジェクトの仕様書（`docs/specifications/`）を参照してください。
