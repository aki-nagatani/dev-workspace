# ファイルサイズ規律（file-size-policy）

**myrules**「ファイルサイズ規律」と同一趣旨。**閾値表・超過時対応の正本は本 SKILL**。

## 発火条件

- **新規**に大きなモジュール・テスト・CSS/JS を追加するとき
- 既存ファイルが閾値に**近い／超過**しているとき（分割検討）
- pre-commit の **`check_file_size.py`** 失敗時

## 閾値一覧

| 種別 | 理想 | 許容 | 上限 | 備考 |
| --- | --- | --- | --- | --- |
| **`src/` Python 等** | 500行 | 1,000行 | 2,000行 | 超過時は分割を検討／推奨 |
| **`tests/`**（Python / JS 等） | 500行 | 1,000行 | 1,500行 | myrules「テスト規律」と整合 |
| **`src/` CSS** | 500行 | 1,000行 | 2,000行 | |
| **`static/` アプリ管理 CSS** | 同上 | 同上 | 同上 | `vendor` 配下は対象外 |
| **`src/`・`tests/` JS** | 500行 | 1,000行 | 2,000行 | |
| **`static/` アプリ管理 JS** | 同上 | 同上 | 同上 | `vendor` 配下は対象外 |

## 検査

- **`scripts/check_file_size.py`** および **pre-commit**（各リポの設定を正とする）
- 詳細背景: Obsidian `DevProject/guidelines/コーディング規約.md`（存在する場合）

## 超過時の対応

- **1,000行超**（src / static CSS・JS）: **分割を検討**
- **2,000行超**（src / static CSS・JS）: **分割を推奨**（機能別・責務別）
- **1,000行超**（tests）: **分割を検討**
- **1,500行超**（tests）: **分割を推奨**

分割時は既存 import・テスト実行パス・pre-commit が通る単位にする。

## テストファイル分割（Python・必須）

**pre-commit の行数上限（tests: 1,500行）や diff-cover 不足**を理由にテストを増やすときも、**本節と「分割の単位」**に従う。\
**カバレッジツール名をファイル名に出さない**（`diff_cover`・`coverage`・`uncovered` 等は禁止）。

### 禁止（アンチパターン・再発防止）

| 禁止 | 理由 |
| --- | --- |
| **`*_diff_cover.py`** / **`*_coverage*.py`** など、**計測目的だけ**の分割先 | 責務が読み手に伝わらず、理想500行の再分割が遅れる |
| **末尾だけ**を上限直前まで切り出す（例: 1,674行→1,211行+463行） | **少量移動**と同型。元ファイルの大半が欠落しうる |
| **PowerShell** の `Get-Content -TotalCount` / `Select-Object -First` 等で **行数切り詰め** | 日本語コメント・文字列の **UTF-8 破壊**（cp932 誤読）。**myrules**「ファイル修正と差分確認」と同様、**編集は `StrReplace` / `Write` のみ** |
| **一時スクリプト**でテスト `.py` を機械生成・結合・truncate（**`check_file_size.py` 等の読取専用は可**） | 差分レビュー不能・文字化けリスク |
| 分割後に **片方だけ極端に薄い**（例: 299行+803行で、元の塊が再現できない） | **機能塊ごと**に分けていない証拠。803行側はさらに分割すべき |
| diff-cover 用テストだけを **別ファイルに隔離**し、通常テストは削る | 振る舞いテストと **同一の命名・配置規則**で足す |

### 必須（正しい手順）

1. **上限失敗前**に `python scripts/check_file_size.py <path>` で行数を確認（**1,000行超**で分割**検討**、**1,500行超**で**必須**）。
2. **塊の設計**: 対象 `src` の**責務・関数名・画面機能**に合わせて分割先を決める（例: `test_reel_line_capacity_daiwa_row_td.py`・`…_spinning_split.py`・`…_merge_retain.py`）。**1ファイル理想500行以内**（超える場合のみ許容1,000行以内）。
3. **移動**: ブロック単位で **`StrReplace` / `Write`**。移動後は **両方のファイル**で pytest が通ることを確認。
4. **diff-cover**: 不足行用のテストも、**上記と同じ振る舞い名のファイル**に追加する（「diff-cover 専用ファイル」は作らない）。
5. **文字化け疑い**（`繧`・`縺`・black が日本語行でパース失敗）→ **即中断**。PowerShell 切り詰めを疑い、**git から復元**または **Cursor 編集で再構築**（`markdown-editing` SKILL の UTF-8 禁止事項を `.py` の日本語にも適用）。

### pre-commit で `check_file_size` 失敗したとき

1. **コミットを成功させない**（`--no-verify` 禁止）。
2. 本 SKILL を **Read し直し**、上表の禁止に当てはまっていないか自問。
3. **分割設計を書いてから**実装（緊急 truncate 禁止）。コミットが1回遅れても **理想分割を優先**（既存「コミット段での判断」と同じ）。

## 委譲時（Task サブエージェント・親エージェント）

**再発原因**: 親が「pre-commit の行数上限を通して」「diff-cover を足して」とだけ **Task** に渡すと、サブエージェントは **myrules・本 SKILL を Read しない**まま動き、**末尾切り出し**・**`*_diff_cover.py`**・**PowerShell 行切り詰め**を選びがち（FishTrack `test_reel_line_capacity_daiwa_*` 事例）。

### 原則（親エージェント）

- **tests/*.py の分割本体**は **親が `StrReplace` / `Write` で実施**する（myrules「ファイル修正と差分確認」）。
- **委譲してよい範囲**: ① **塊設計のみ**（ファイル名・移動する `test_*` 関数名・想定行数の一覧。**ファイル変更なし**）② **分割後の検証のみ**（`check_file_size.py`・pytest・文字化け grep。読取＋コマンド実行）。
- **`subagent_type: shell` に `.py` の分割・移動をさせない**（`Get-Content -TotalCount` 等の truncate リスクが高い）。

### 親が分割を委譲する場合の必須（prompt に含める）

1. **本 SKILL の絶対パス**と **「着手前に `Read` 全文。要約だけでは不可」**\
   例: `d:\OneDrive\git_work\dev-workspace\.cursor\skills\file-size-policy\SKILL.md`
2. **フェーズ分け**: **Phase 1** = 分割設計をテキストで返す（**この時点でファイルを書かない**）。**Phase 2** = 親が設計を承認したあとだけ実装（親が実装するのが原則。サブエージェントに Phase 2 を渡す場合は下記禁止を再掲）。
3. **禁止の明示**（prompt 内に箇条書きでコピー）:
   - `*_diff_cover.py` / `*_coverage*.py` 等の**新規ファイル名**
   - **末尾だけ**の切り出し・**上限直前までの少量移動**
   - **PowerShell / bash** による行数切り詰め・`head`/`tail` での `.py` 生成
   - **一時スクリプト**でのテスト `.py` 結合・truncate（`check_file_size.py` 等の**読取専用**は可）
   - 編集手段は **`StrReplace` / `Write` のみ**
4. **成功条件**: 各分割先 **理想500行以内**（超える場合のみ許容1,000行）。`python scripts/check_file_size.py <各パス>` が **上限1,500以下**。pytest 対象が green。

### サブエージェント側（委譲を受けたとき）

1. **最初のツール**: 上記 SKILL パスを **`Read` 全文**（AGENTS.md の要約のみで着手しない）。
2. **設計先行**: 実装前に **分割先ファイル名（振る舞い名）**・**移動するテスト関数名**・**想定行数**を返答に書く。
3. **編集**: **`StrReplace` / `Write` のみ**。Shell で `.py` を書き換えない。
4. **完了報告に含める**: 変更ファイル一覧、各ファイルの `check_file_size.py` 結果、実行した pytest コマンドと結果。

### 親の受け取りレビューゲート（採用前・必須）

サブエージェント（または自分）の分割差分を **コミット・報告の前に**親が確認する。

| 確認 | 不合格例 |
| --- | --- |
| 新規ファイル名 | `diff_cover`・`coverage`・`uncovered` を含む |
| 行数 | いずれか **1,500超**、または **極端な偏り**（例: 299行+803行で大塊が片方に残存） |
| 文字化け | `繧`・`縺`・black が日本語行でパース失敗 |
| diff の形 | 末尾数百行の単純削除＋新ファイル追記のみ（**塊移動**になっていない） |
| 検証 | `check_file_size.py` 未実行、pytest 未実行 |

**不合格時**: サブエージェント成果を**そのまま採用しない**。truncate 疑いは **git から復元**し、親が **塊設計からやり直す**。

### Task prompt 雛形（親がコピー）

```text
【必須】着手前に Read: dev-workspace/.cursor/skills/file-size-policy/SKILL.md（全文）

対象: <リポ>/tests/<元ファイル>.py（現在 N 行。上限 1,500）

Phase 1 のみ: 分割設計を返すこと（ファイル変更禁止）。
- 分割先は振る舞い名（例: test_*_daiwa_row_td.py）。diff_cover/coverage 禁止。
- 各ファイル理想500行以内。移動する test 関数名を列挙。

禁止: 末尾切り出し、PowerShell/bash による .py truncate、一時スクリプトでの .py 書換え。
編集手段は StrReplace/Write のみ（Phase 2 で実装する場合）。

Phase 1 完了後、親が承認してから Phase 2。
```

## 分割の単位（コミット時・上限超過）

**pre-commit の行数チェックで上限超過し、分割が必要なとき**は、**ギリギリ下回るだけの少量移動を禁止**する。

### 禁止（アンチパターン）

- 上限（例: 2,000行）を **1行でも下回ればよい** だけの、末尾数行〜数十行の切り出し
- 行数オーバー回避が主目的で、**機能・責務の境界と無関係**なブロックの移動
- 既存の `*_tail_*.css` 等へ **関係の薄いスタイル**を押し込むだけの対処

### 必須（正しい分割）

- **機能・画面・責務・ドメイン**など、**読み手が「なぜここに分かれたか」説明できる大きな単位**で分ける
- 分割時の**原則**: 各分割先ファイルは**理想行数（500行）以内**に収める（**半分ずつの 1,000行×2** や許容帯への「揃え」は目標にしない）
- 機能単位の都合で 500行を超える場合のみ**許容（1,000行）以内**にとどめる。**上限（2,000行）に近いファイルを残さない**（極端な 1,900行 + 100行 は避ける）
- **tests/**: 上記に加え **「テストファイル分割（Python・必須）」**（`*_diff_cover` 禁止・振る舞い名・`StrReplace`/`Write` のみ）を適用
- 分割先ファイル名・読み込み（`base.html` の link、Python の import 再エクスポート等）は**分割単位と一致**させる
- CSS: 例）テーブル共通 / モーダル / タックル一覧フィルタ など**UI 機能塊**ごと。Python: 例）ルート / ヘルパ / フォーム など**責務塊**ごと

### コミット段での判断

1. 上限超過 → **まず全体の塊（セクション・モジュール）を洗い出し**、移動候補を **理想500行以内の塊**で設計する（超える場合は許容1,000行以内）
2. **少量移動で通す案と、理想分割案**が両方ある場合は **理想分割案を採用**（コミットが 1 回遅れてもよい）
3. 分割に伴うテンプレの `<link>` 追加・import 整理・テストパスは**同一コミット**で完結させる
