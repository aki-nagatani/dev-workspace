# Obsidian InBox Summarize

## 適用条件
- 対象は `D:\OneDrive\アプリ\remotely-save\Obsidian\InBox` 配下のMarkdownファイル
- それ以外の場所ではこのSKILLを適用しない

## 処理フロー

### 1. InBoxノートの読み込み
- `D:\OneDrive\アプリ\remotely-save\Obsidian\InBox\` 配下のMarkdownファイルを確認
- 各ノートの内容を読み込む

**入力形式**:
InBoxノートには以下の3種類の形式がある：

1. **URL形式**: ノートの内容がURLのみの場合
   - 例: `https://qiita.com/degudegu2510/items/eff0f63dac99554e6439`
   - URLの内容を取得して分析する（可能な場合）

2. **WEBクリップ形式**: ObsidianのWeb Clipperで保存された形式
   - フロントマターにURLやメタデータが含まれる
   - 本文にWebページの内容がMarkdown形式で保存されている
   - 例:
     ```markdown
     ---
     url: https://example.com/article
     title: 記事タイトル
     ---
     
     # 記事タイトル
     
     記事の本文内容...
     ```

3. **手入力メモ形式**: ユーザーが手動で入力したメモ
   - フロントマターがない、または最小限のフロントマターのみ
   - 本文にユーザーが記述した内容が含まれる
   - 例:
     ```markdown
     Cursorのショートカットキーについて
     
     - Cmd+K: インライン編集
     - Cmd+L: チャット開始
     ```

### 2. 内容分析と要約
- ノートの内容を分析し、主要な情報を抽出
- **入力形式に応じた処理**:
  - **URL形式の場合**: URLの内容を取得して分析（可能な場合）
  - **WEBクリップ形式の場合**: フロントマターからURLやタイトルを抽出し、本文内容を分析
  - **手入力メモ形式の場合**: 本文内容を直接分析（フロントマターがあればメタデータも抽出）
- **ジャンルを特定**（例: Cursor、Python、AWS、Raspberry Pi など）
- 要約を作成（簡潔で要点を押さえた内容）
- 元の内容への参照を保持（URL、引用など。手入力メモの場合は参照セクションは省略可）
- キーワードやタグ候補を抽出（同ジャンルノート検索に使用）

**ジャンルの特定方法**:
- 固有名詞（ツール名、サービス名、技術名など）を抽出
- 主要トピックを特定
- 例: 「Cursor」に関する記事 → ジャンル: `Cursor`
- 例: 「Pythonのデコレータ」に関する記事 → ジャンル: `Python`
- 例: 「AWS Lambda」に関する記事 → ジャンル: `AWS`

### 3. 既存ノートの検索
`D:\OneDrive\アプリ\remotely-save\Obsidian\Notes\Knowledge\` 配下の既存ノートを検索し、同ジャンルのノートを探す。

**同ジャンルの判定基準**（優先順位順）:
1. **タグの一致**: 抽出したタグ候補と既存ノートのタグが一致または類似
2. **キーワードの一致**: 主要キーワードが既存ノートのタイトルや内容に含まれる
3. **タイトルの類似性**: タイトルが同じトピックを扱っている
4. **内容の関連性**: 内容が同じ分野・トピックを扱っている

**検索方法**:
- `Notes/Knowledge/` 配下の全Markdownファイルを確認
- 各ファイルのタイトル、タグ、主要キーワードを抽出
- InBoxノートの内容と比較して関連性を判定

### 4. ノートの作成または更新

#### 既存ノートが見つかった場合（追記・更新）
既存ノートに追記する形式で更新する：

```markdown
## [日付 YYYY-MM-DD] 追記

### 要約
[今回のInBoxノートの要約内容]

### 詳細
[必要に応じて詳細情報]

### 参照
[元の内容への参照、URLなど]

---
```

**追記時の注意事項**:
- 既存の構造を維持し、新しいセクションとして追記
- 日付セクションで時系列を明確にする
- 既存のタグは維持し、必要に応じて新しいタグを追加
- 既存の参照セクションがあれば、そこに追加するか新しい参照セクションを作成

#### 既存ノートが見つからなかった場合（新規作成）

**ファイル名**:
- **ジャンル名をファイル名にする**（例: `Cursor.md`、`Python.md`、`AWS.md`）
- ジャンルが特定できない場合は、主要キーワードから適切な名前を決定
- 既存ファイルと重複しないようにする（重複する場合は、ジャンル名に番号や日付を追加しない。既存ノートに追記する）

**ノート構造**:
```markdown
---
created: YYYY-MM-DD
source: InBox/YYYY-MM-DD.md
---

# [ノートタイトル]

## 要約
[ノートの要約内容]

## 詳細
[必要に応じて詳細情報]

## 参照
[元の内容への参照、URLなど]

## 関連リンク
[関連するノートへのWikiリンク]
```

### 5. タグとリンクの付与
`obsidian-update-rules` のルールに従って：

- 重要語（固有名詞、システム名、機器名、手順名、プロジェクト名）が出たら、可能なら `[[既存ノート名]]` へのWikiリンクを優先
- 該当ノートが存在しない場合は、タグ `#keyword` を付与（英小文字・ハイフン推奨）
- 既存タグ体系がある場合はそれに合わせる（例: `#infra/raspi` のような階層タグ）
- 1ノート内のタグは過剰にならない範囲で付与（目安: 3〜8個）

### 6. 元のInBoxノートの処理
- 要約ノート作成・更新が完了したら、**そのノートの処理が完了した時点で**元のInBoxノートを削除
- 削除前に要約ノートへの参照を確認
- **重要**: 1件ずつ処理し、処理完了したノートは即座にInBoxから削除する

## 実行手順

1. **InBox全体の確認**
   - `D:\OneDrive\アプリ\remotely-save\Obsidian\InBox\` 配下のファイル一覧を取得
   - 処理対象のノート数を確認

2. **各ノートを1件ずつ処理**（全ノートが処理されるまで繰り返し）
   
   各ノートに対して以下を実行：
   
   a. **ノートの読み込み**
      - 1件のノートファイルを読み込む
   
   b. **内容分析**
      - 内容を分析し、ジャンル、要約、キーワードを抽出
      - 入力形式を判定（URL形式、WEBクリップ形式、手入力メモ形式）
   
   c. **既存ノートの検索**
      - ジャンル名で既存ノートを検索（例: ジャンルが「Cursor」の場合、`Notes/Knowledge/Cursor.md` を検索）
      - `Notes/Knowledge/` 配下で既存の同ジャンルノートを検索
   
   d. **ノートの作成または更新**
      - **既存ノートが見つかった場合**: 既存ノートに追記・更新
      - **既存ノートが見つからなかった場合**: ジャンル名をファイル名として新規ノートを作成（例: `Notes/Knowledge/Cursor.md`）
   
   e. **タグとリンクの付与**
      - タグとリンクを付与（既存ノートの場合は既存タグを維持）
   
   f. **InBoxノートの削除**
      - **処理が完了したら、そのノートをInBoxから即座に削除**
      - 削除前に要約ノートへの参照を確認
   
   g. **処理結果の報告**（1件ずつ）
      - 処理したノートのファイル名
      - 新規作成したノートの場所、または更新した既存ノートの場所
      - 付与したタグやリンク
      - ジャンル名

## 注意事項

- 既存のMarkdown構造・見出し階層を維持
- 既存のリンク形式（Wikiリンク `[[...]]` / Markdownリンク `[text](url)`）を尊重
- ノートの文脈を壊さない最小限の編集で完結
- ファイルの改行は既存に合わせる（不用意に整形しない）
- 既存の関連リンクがあるか確認し、重複追加しない
- 既存タグを再利用し、必要に応じて最小限の追加
