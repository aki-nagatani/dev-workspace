# Obsidian InBox Summarize

## 適用条件
- 対象は `D:\OneDrive\アプリ\remotely-save\Obsidian\InBox` 配下のMarkdownファイルおよびPDFファイル
- それ以外の場所ではこのSKILLを適用しない

## 処理フロー

### 1. InBoxノートの読み込み
- `D:\OneDrive\アプリ\remotely-save\Obsidian\InBox\` 配下のMarkdownファイルおよびPDFファイルを確認
- 各ノートの内容を読み込む
  - **Markdownファイルの場合**: ファイルの内容を直接読み込む
  - **PDFファイルの場合**: PDFからテキストを抽出して読み込む（Pythonの`pypdf`または`pdfplumber`ライブラリを使用）
- **重要**: 1つのノートに複数の項目が含まれている場合、1つの項目だけを処理対象とする

**入力形式**:
InBoxノートには以下の4種類の形式がある：

1. **URL形式**: ノートの内容がURLのみの場合
   - 例: `https://qiita.com/degudegu2510/items/eff0f63dac99554e6439`
   - URLの内容を取得して分析する（可能な場合）
   - **URLの内容を取得できない場合（タイムアウト、エラー、アクセス不可等）**: 処理を中断する
   - **複数URLがある場合**: 1つのURLだけを処理対象とする（先頭のURL、または最初に見つかったURL）

2. **WEBクリップ形式**: ObsidianのWeb Clipperで保存された形式
   - フロントマターにURLやメタデータが含まれる
   - 本文にWebページの内容がMarkdown形式で保存されている
   - 例:
     ```markdown
     ---
     url: https://example.com/article
     title: 記事タイトル
     ---
     
     # 記事タイトル
     
     記事の本文内容...
     ```
   - **複数のWEBクリップがある場合**: 1つのクリップだけを処理対象とする（先頭のセクション）

3. **PDF形式**: InBoxにPDFファイルが直接配置されている場合
   - PDFファイルが `D:\OneDrive\アプリ\remotely-save\Obsidian\InBox\` 配下に直接配置されている
   - PDFからテキストを抽出して分析する
   - **PDFの読み込み方法**: Pythonの`pypdf`または`pdfplumber`ライブラリを使用してPDFからテキストを抽出
   - **PDFの読み込みに失敗した場合（ファイル破損、暗号化、アクセス不可等）**: 処理を中断する
   - **複数PDFがある場合**: 1つのPDFだけを処理対象とする（先頭のPDF、または最初に見つかったPDF）
   - **PDFファイルの処理後**: テキスト抽出が完了したら、PDFファイルを削除する（または処理済みフォルダに移動）

4. **手入力メモ形式**: ユーザーが手動で入力したメモ
   - フロントマターがない、または最小限のフロントマターのみ
   - 本文にユーザーが記述した内容が含まれる
   - 例:
     ```markdown
     Cursorのショートカットキーについて
     
     - Cmd+K: インライン編集
     - Cmd+L: チャット開始
     ```
   - **複数のメモ項目がある場合**: 1つの項目だけを処理対象とする（先頭のセクション、または明確に区切られた最初の項目）

### 2. 内容分析とKnowledge抽出
- ノートの内容を分析し、記事から得られるKnowledge（知識・知見・実用的な情報）を抽出
- **入力形式に応じた処理**:
  - **URL形式の場合**: 
    - URLの内容を取得して分析（可能な場合）
    - **重要**: URLの内容を取得できない場合（タイムアウト、エラー、アクセス不可等）は、処理を中断する
    - URL取得に失敗した場合は、InBoxノートを削除せず、エラーメッセージと共に処理中断の旨を報告する
  - **WEBクリップ形式の場合**: フロントマターからURLやタイトルを抽出し、本文内容を分析（本文が存在する場合は本文を分析）
  - **PDF形式の場合**: 
    - PDFファイルからテキストを抽出して分析
    - **PDFの読み込み方法**: Pythonの`pypdf`または`pdfplumber`ライブラリを使用
      - `pypdf`を使用する場合: `PyPDF2`または`pypdf`ライブラリでPDFを読み込み、各ページからテキストを抽出
      - `pdfplumber`を使用する場合: より高度なレイアウト解析が可能で、表や図の処理にも対応
    - **PDFの読み込みに失敗した場合（ファイル破損、暗号化、アクセス不可等）**: 処理を中断する
    - PDFファイルを削除せず、エラーメッセージと共に処理中断の旨を報告する
    - テキスト抽出が成功したら、抽出したテキストを分析してKnowledgeを抽出
  - **手入力メモ形式の場合**: 本文内容を直接分析（フロントマターがあればメタデータも抽出）
- **ジャンルを特定**（例: Cursor、Python、AWS、Raspberry Pi など）
- **Knowledge（知識）を抽出・整理**:
  - 記事の要約ではなく、記事から得られる実用的な知識・知見・ノウハウを抽出
  - 具体的な手順、ベストプラクティス、注意点、使用例、テンプレート、設定方法など、実際に活用できる情報を整理
  - 単なる記事の要約ではなく、自分が今後参照・活用するための知識として構造化
- 元の内容への参照を保持（URL、引用など。手入力メモの場合は参照セクションは省略可）
- キーワードやタグ候補を抽出（同ジャンルノート検索に使用）

**ジャンルの特定方法**:
- 固有名詞（ツール名、サービス名、技術名など）を抽出
- 主要トピックを特定
- 例: 「Cursor」に関する記事 → ジャンル: `Cursor`
- 例: 「Pythonのデコレータ」に関する記事 → ジャンル: `Python`
- 例: 「AWS Lambda」に関する記事 → ジャンル: `AWS`

### 3. 既存ノートの検索
`D:\OneDrive\アプリ\remotely-save\Obsidian\Notes\Knowledge\` 配下の既存ノートを検索し、同ジャンルのノートを探す。

**同ジャンルの判定基準**（優先順位順）:
1. **タグの一致**: 抽出したタグ候補と既存ノートのタグが一致または類似
2. **キーワードの一致**: 主要キーワードが既存ノートのタイトルや内容に含まれる
3. **タイトルの類似性**: タイトルが同じトピックを扱っている
4. **内容の関連性**: 内容が同じ分野・トピックを扱っている

**検索方法**:
- `Notes/Knowledge/` 配下の全Markdownファイルを確認
- 各ファイルのタイトル、タグ、主要キーワードを抽出
- InBoxノートの内容と比較して関連性を判定

### 4. ノートの作成または更新

#### 既存ノートが見つかった場合（追記・更新）
**重要**: 既存ノートの内容を読み込み、新しい情報を既存の文章構造に統合する形で追記する。

**追記方法**:
1. **既存ノートの内容を完全に読み込む**
   - 既存ノートの全体構造を把握
   - 既存のセクション、見出し、内容を理解
   - 既存の文章スタイルや記述方法を確認

2. **既存のセクションに統合**
   - **既存のセクションが存在する場合**: そのセクションに新しい情報を自然に追加
     - 例: 「使い方」セクションが既にある場合、新しい使い方の情報をそのセクションに追加
     - 例: 「特徴」セクションが既にある場合、新しい特徴をそのセクションに追加
   - **既存のセクションがない場合**: 適切な場所に新しいセクションを追加
     - 既存の構造に合わせて、適切な見出しレベルで追加
     - 既存のセクションの順序や階層を尊重

3. **参照セクションの更新**
   - 既存の参照セクションがあれば、そこに新しい参照を追加
   - 既存の参照セクションがない場合は、適切な場所に参照セクションを追加

4. **フロントマターの更新**
   - `updated`フィールドがあれば、現在の日付に更新
   - `updated`フィールドがない場合は追加

**追記時の注意事項**:
- **既存の文章構造を維持**: 既存の見出し階層、セクション構成を壊さない
- **既存の文章スタイルに合わせる**: 既存の記述方法や文体に合わせて新しい情報を追加
- **重複を避ける**: 既存の内容と重複する情報は追加しない（必要に応じて既存の内容を更新）
- **自然な統合**: 新しい情報が既存の文章に自然に統合されるようにする
- **既存のタグは維持**: 既存のタグは維持し、必要に応じて新しいタグを追加
- **既存のリンクを尊重**: 既存のWikiリンクやMarkdownリンクを維持

#### 既存ノートが見つからなかった場合（新規作成）

**ファイル名**:
- **ジャンル名をファイル名にする**（例: `Cursor.md`、`Python.md`、`AWS.md`）
- ジャンルが特定できない場合は、主要キーワードから適切な名前を決定
- 既存ファイルと重複しないようにする（重複する場合は、ジャンル名に番号や日付を追加しない。既存ノートに追記する）

**ノート構造**:
```markdown
---
created: YYYY-MM-DD
source: InBox/YYYY-MM-DD.md
---

# [ノートタイトル]

## Knowledge
[記事から得られる知識・知見・実用的な情報]
- 具体的な手順、ベストプラクティス、注意点、使用例、テンプレート、設定方法など
- 単なる記事の要約ではなく、実際に活用できる知識として整理

## 詳細
[必要に応じて詳細情報]

## 参照
[元の内容への参照、URLなど]

## 関連リンク
[関連するノートへのWikiリンク]
```

### 5. タグとリンクの付与
`obsidian-update-rules` のルールに従って：

- 重要語（固有名詞、システム名、機器名、手順名、プロジェクト名）が出たら、可能なら `[[既存ノート名]]` へのWikiリンクを優先
- 該当ノートが存在しない場合は、タグ `#keyword` を付与（英小文字・ハイフン推奨）
- 既存タグ体系がある場合はそれに合わせる（例: `#infra/raspi` のような階層タグ）
- 1ノート内のタグは過剰にならない範囲で付与（目安: 3〜8個）

### 6. 元のInBoxノートの処理
- 要約ノート作成・更新が完了したら、処理した項目をInBoxノートから削除
- **重要**: 1つのノートに複数の項目がある場合、処理した項目だけを削除し、残りの項目はノートに残す
- ノート内のすべての項目を処理した場合のみ、ノートファイル全体を削除する
- 削除前に要約ノートへの参照を確認
- **重要**: 1件処理したら作業を中断する（次のノートまたは次の項目は別の実行で処理）

## 実行手順

1. **InBox全体の確認**
   - `D:\OneDrive\アプリ\remotely-save\Obsidian\InBox\` 配下のMarkdownファイルおよびPDFファイルの一覧を取得
   - 処理対象のノート数を確認

2. **1件だけ処理する**（この実行では1件のみ）
   
   InBoxから未処理のノートを1つ選び、以下を実行：
   
   a. **ノートの読み込み**
      - 1件のノートファイル（MarkdownまたはPDF）を読み込む（先頭のノート、または日付が古い順など、1件に限定）
      - **Markdownファイルの場合**: ファイルの内容を直接読み込む
      - **PDFファイルの場合**: Pythonの`pypdf`または`pdfplumber`ライブラリを使用してPDFからテキストを抽出
      - ノート内に複数の項目があるか確認（Markdownファイルの場合）
      - 複数の項目がある場合、1つの項目だけを処理対象とする（先頭の項目、または最初に見つかった項目）
   
   b. **内容分析**
      - 処理対象の項目の内容を分析し、ジャンル、Knowledge（知識）、キーワードを抽出
      - 入力形式を判定（URL形式、WEBクリップ形式、PDF形式、手入力メモ形式）
      - **URL形式の場合**: 
        - URLの内容を取得して分析を試みる
        - **URLの内容を取得できない場合（タイムアウト、エラー、アクセス不可等）**: 処理を中断する
        - InBoxノートを削除せず、エラーメッセージと共に処理中断の旨を報告する
        - 次のステップ（既存ノートの検索、ノートの作成または更新等）には進まない
      - **PDF形式の場合**: 
        - PDFファイルからテキストを抽出する
        - Pythonの`pypdf`または`pdfplumber`ライブラリを使用してPDFを読み込み、テキストを抽出
        - **PDFの読み込みに失敗した場合（ファイル破損、暗号化、アクセス不可等）**: 処理を中断する
        - PDFファイルを削除せず、エラーメッセージと共に処理中断の旨を報告する
        - 次のステップ（既存ノートの検索、ノートの作成または更新等）には進まない
        - テキスト抽出が成功したら、抽出したテキストを分析してKnowledgeを抽出
   
   c. **既存ノートの検索**
      - ジャンル名で既存ノートを検索（例: ジャンルが「Cursor」の場合、`Notes/Knowledge/Cursor.md` を検索）
      - `Notes/Knowledge/` 配下で既存の同ジャンルノートを検索
   
   d. **ノートの作成または更新**
      - **既存ノートが見つかった場合**: 
        1. 既存ノートの内容を完全に読み込む
        2. 既存の文章構造を理解し、新しい情報を既存のセクションに統合する形で追記
        3. 既存のセクションがない場合は、適切な場所に新しいセクションを追加
        4. 既存の参照セクションに新しい参照を追加、または参照セクションを作成
        5. フロントマターの`updated`フィールドを現在の日付に更新
      - **既存ノートが見つからなかった場合**: ジャンル名をファイル名として新規ノートを作成（例: `Notes/Knowledge/Cursor.md`）
   
   e. **タグとリンクの付与**
      - タグとリンクを付与（既存ノートの場合は既存タグを維持）
   
   f. **InBoxノートの処理**
      - **処理が完了したら、処理した項目をInBoxノートから削除**
      - **Markdownファイルの場合**: 
        - **1つのノートに複数の項目がある場合**: 処理した項目だけを削除し、残りの項目はノートに残す
        - **ノート内のすべての項目を処理した場合**: ノートファイル全体を削除する
      - **PDFファイルの場合**: 
        - テキスト抽出とKnowledge抽出が完了したら、PDFファイルを削除する
        - 削除前に要約ノートへの参照を確認
      - 削除前に要約ノートへの参照を確認
   
   g. **処理結果の報告**
      - 処理したノートのファイル名（MarkdownファイルまたはPDFファイル）
      - 処理した項目の内容（URL、メモの内容、PDFの内容など）
      - 抽出したKnowledge（知識）の概要
      - 新規作成したノートの場所、または更新した既存ノートの場所
      - 付与したタグやリンク
      - ジャンル名
      - ノートに残りの項目がある場合は、その旨を報告（Markdownファイルの場合）

3. **作業の中断**
   - **1件処理したら、ここで作業を中断する**
   - InBoxに未処理のノートが残っていても、続けて処理しない
   - 次のノートは、このコマンドを再実行して処理する

## 注意事項

- 既存のMarkdown構造・見出し階層を維持
- 既存のリンク形式（Wikiリンク `[[...]]` / Markdownリンク `[text](url)`）を尊重
- ノートの文脈を壊さない最小限の編集で完結
- ファイルの改行は既存に合わせる（不用意に整形しない）
- 既存の関連リンクがあるか確認し、重複追加しない
- 既存タグを再利用し、必要に応じて最小限の追加
- **既存ノートに追記する場合**: 単純にKnowledgeの内容を追記するのではなく、既存のノートの内容を読み込み、その文章にマージするように追記すること
  - 既存のセクションが存在する場合は、そのセクションに新しい知識を自然に追加
  - 既存のセクションがない場合は、適切な場所に新しいセクションを追加
  - 既存の文章構造・スタイルを維持し、新しい知識を自然に統合
  - 既存の内容と重複する情報は追加しない（必要に応じて既存の内容を更新）
  - **既存ノートに「要約」セクションがある場合**: 「Knowledge」セクションに統合するか、既存の「要約」セクションを「Knowledge」に変更することを検討
- **URLの取得に失敗した場合**: URL形式のノートでURLの内容を取得できない場合（タイムアウト、エラー、アクセス不可等）は、処理を中断する
  - InBoxノートを削除しない
  - エラーメッセージと共に処理中断の旨を報告する
  - 次のステップ（既存ノートの検索、ノートの作成または更新等）には進まない
- **PDFの読み込みに失敗した場合**: PDF形式のファイルでPDFの読み込みに失敗した場合（ファイル破損、暗号化、アクセス不可等）は、処理を中断する
  - PDFファイルを削除しない
  - エラーメッセージと共に処理中断の旨を報告する
  - 次のステップ（既存ノートの検索、ノートの作成または更新等）には進まない
- **PDFのテキスト抽出**: PDFからテキストを抽出する際は、可能な限り正確にテキストを抽出する
  - 表や図が含まれるPDFの場合は、`pdfplumber`ライブラリの使用を推奨（より高度なレイアウト解析が可能）
  - テキスト抽出が不完全な場合でも、抽出できた部分からKnowledgeを抽出する

## 例

### 例1: URL形式（既存ノートへの追記）

**入力**: InBoxに `2026-01-27.md` があり、内容が `https://azukiazusa.dev/blog/new-design-tool-pencil`

**既存ノート**: `Notes/Knowledge/Pencil.md` が既に存在し、以下のような構造になっている：
```markdown
# Pencil

## Knowledge
Pencilは、AIがUIデザインを生成できるデザインツール...

## 使い方
### Pencil(アプリ) x Claude Code(CLI)
1. 公式サイトからアプリをインストール
...

## 参照
- [Pencil公式サイト](https://www.pencil.dev/)
```

**処理**:
1. URL形式であることを認識
2. URLの内容を取得して分析
3. 内容を分析してジャンル、Knowledge（知識）、キーワードを抽出
   - ジャンル: 「Pencil」
   - Knowledge: インストール手順、プロンプトでのデザイン生成方法、MCPでのコード書き出し手順など、実際に活用できる知識
4. 既存ノート `Notes/Knowledge/Pencil.md` を発見
5. **既存ノートの内容を完全に読み込む**
6. **既存の文章構造に統合する形で追記**:
   - 「使い方」セクションが既にあるため、新しい使い方の知識（プロンプトでのデザイン生成、MCPでのコード書き出し）をそのセクションに追加
   - 「インストールとセットアップ」という新しいサブセクションを「使い方」セクション内に追加（既存の構造に合わせて）
   - 参照セクションに新しいURLを追加
7. フロントマターの`updated`フィールドを`2026-01-27`に更新
8. タグやリンクを付与（既存のタグは維持）
9. 処理した項目をInBoxノートから削除

**追記後の例**:
```markdown
## 使い方
```

### 例2: WEBクリップ形式（既存ノートへの追記）

**入力**: InBoxに `2026-01-26.md` があり、内容が：
```markdown
---
url: https://example.com/python-decorator
title: Pythonデコレータの使い方
---

# Pythonデコレータの使い方

デコレータは関数を拡張するための機能です...
```

**既存ノート**: `Notes/Knowledge/Python.md` が既に存在し、以下のような構造になっている：
```markdown
# Python

## Knowledge
Pythonは高水準プログラミング言語...

## 基本的な構文
[既存の内容]
```

**処理**:
1. WEBクリップ形式であることを認識
2. フロントマターからURLとタイトルを抽出
3. 本文内容を分析してジャンル、Knowledge（知識）、キーワードを抽出
   - ジャンル: 「Python」
   - Knowledge: デコレータの使い方、実用的なパターン、ベストプラクティスなど
4. 既存ノート `Notes/Knowledge/Python.md` を発見
5. **既存ノートの内容を完全に読み込む**
6. **既存の文章構造に統合する形で追記**:
   - 「基本的な構文」セクションの後に「デコレータ」という新しいセクションを追加
   - または、既存の「高度な機能」セクションがあれば、そこにデコレータの知識を追加
   - 参照セクションに新しいURLを追加
7. フロントマターの`updated`フィールドを更新
8. タグやリンクを付与（既存のタグは維持）
9. 処理した項目をInBoxノートから削除

### 例3: 手入力メモ形式（既存ノートへの追記）

**入力**: InBoxに `2026-01-26.md` があり、内容が：
```markdown
Cursorのショートカットキーについて

- Cmd+K: インライン編集
- Cmd+L: チャット開始
- Cmd+I: インライン補完
```

**既存ノート**: `Notes/Knowledge/Cursor.md` が既に存在し、以下のような構造になっている：
```markdown
# Cursor

## Knowledge
CursorはAI駆動のコードエディタ...

## 使い方
[既存の使い方の内容]
```

**処理**:
1. 手入力メモ形式であることを認識（フロントマターなし、URLなし）
2. 本文内容を直接分析
3. 内容を分析してジャンル、Knowledge（知識）、キーワードを抽出
   - ジャンル: 「Cursor」
   - Knowledge: ショートカットキーの使い方、効率的な操作方法など
4. 既存ノート `Notes/Knowledge/Cursor.md` を発見
5. **既存ノートの内容を完全に読み込む**
6. **既存の文章構造に統合する形で追記**:
   - 「使い方」セクションが既にあるため、そのセクション内に「ショートカットキー」というサブセクションを追加
   - または、既存の「ショートカットキー」セクションがあれば、そこに新しいショートカットキーの知識を追加
   - 参照セクションは省略（手入力メモのため）
7. フロントマターの`updated`フィールドを更新
8. タグやリンクを付与（既存のタグは維持）
9. 処理した項目をInBoxノートから削除

### 例4: PDF形式（新規ノート作成）

**入力**: InBoxに `Python入門ガイド.pdf` というPDFファイルが配置されている

**処理**:
1. PDF形式であることを認識（`.pdf`拡張子のファイル）
2. Pythonの`pypdf`または`pdfplumber`ライブラリを使用してPDFからテキストを抽出
   - 例: `pypdf`を使用する場合
     ```python
     from pypdf import PdfReader
     reader = PdfReader("Python入門ガイド.pdf")
     text = ""
     for page in reader.pages:
         text += page.extract_text()
     ```
   - 例: `pdfplumber`を使用する場合
     ```python
     import pdfplumber
     with pdfplumber.open("Python入門ガイド.pdf") as pdf:
         text = ""
         for page in pdf.pages:
             text += page.extract_text()
     ```
3. 抽出したテキストを分析してジャンル、Knowledge（知識）、キーワードを抽出
   - ジャンル: 「Python」
   - Knowledge: Pythonの基本的な構文、実用的なコード例、ベストプラクティスなど
4. 既存ノート `Notes/Knowledge/Python.md` を検索
   - **既存ノートが見つかった場合**: 既存ノートに追記（例2と同様の処理）
   - **既存ノートが見つからなかった場合**: 新規ノートを作成
5. **新規ノート作成の場合**:
   - `Notes/Knowledge/Python.md` を新規作成
   - 抽出したKnowledgeを構造化して記述
   - フロントマターに`created`フィールドと`source`フィールドを追加
   - タグやリンクを付与
6. PDFファイルを削除
7. 処理結果を報告
