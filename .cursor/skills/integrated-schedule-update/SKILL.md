# 統合作業スケジュールの更新

**対象**: `DevProject/plans/統合作業スケジュール.md`（タスクID プレフィックス **F**／**P**／**I**／**T**・週次・ガント。いわゆる「統合」計画の正本）。**T**＝`personal-tools` 全体（みてねキーパー含む）。

## 適用タイミング

- **`統合作業スケジュール.md` を編集するとき**（タスク新設・完了・週移動・前倒し・削除・ガント変更）— **本 SKILL を編集前に Read すること**（計画書冒頭に記載）
- **実装完了やマイルストーン達成**に合わせ計画側の進捗を載せ替えるとき（myrules「計画書の進捗状況の反映」と併用）
- **週次だけ／一覧だけ**を直す依頼があったとき → **三本柱**まで含めて整合させる
- **詳細節の大きな見出し移動・統合**（低頻度）→ 下記 **「タスク詳細・横断節の再編」** の3項目のみ確認する

### スケジュール全体の見直し（必須トリガー）

以下のいずれかに該当する変更を行ったときは、**同一作業セッション／同一作業単位**で **スケジュール全体の見直し** を実行する。**局所の1行だけ差し替え**で完了としない。

- **[[#タスク一覧]]** の **優先度**（2列目）を変えたとき
- **タスクのリスケ**（ユーザーが週の移動・前倒し・後ろ倒しを指示したとき、または週次表で当該タスクの週を変えたとき）
- **タスクを新規追加**したとき（一覧への行追加）
- **前タスク** 列を変えたとき（依存が週の前後関係に影響するため）

**全体見直し**で行うこと: 本 SKILL **「計画書ルールの本文」** の **優先度と週次**・**週次配分の原則**・**ゼロベース再配置**に照らし、\
**同一プレフィックス**（**F**／**P**／**I**／**T**。**統合**の [[#タスク一覧]] に存在するもの）ごとに優先度と週の単調性を**全週の週次表**で確認し、**三本柱**（一覧・週次・ガント）を矛盾なく揃える。\
手順は上記 **「作業前（必須）」**・**三本柱**・週次スケジュール節の **週次配分の原則** と同じ。

**補足**: 進捗の記載のみ・ステータスを「完了」にしただけなど、**週・優先度・依存に触れない**変更は、**全体見直し**を省略してよい（ただし**三本柱**の整合は維持する）。

## 計画書ルールの本文（詳細・SKILL正）

計画書 **`統合作業スケジュール.md`** の **`## 優先度と週次の関係`**・**ゼロベース**・**週次配分の原則**に相当する**全文**をここに置く。計画書側は**要点と本節への参照**に簡素化する。

### 優先度と週次の関係（詳細）

[[#タスク一覧]] は各プロジェクト内でタスクID（番号）順の1表（優先度見出しで分割しない）。いつ何をやるかの主たる正は [[#週次スケジュール]] と [[#ガントチャート]]。\
[[#週次スケジュール]] に載った週は、そのタスクをその週の着手対象として扱う。到来週のタスクを「一覧の並びが後ろだから」と読み替えて後回しにしない。\
**優先度**（[[#タスク一覧]] 2列目）は **5**（高）〜 **1**（低）。**数字が大きいほど優先度は高い**。\
**製品横断の扱い**: 週の割当で **別製品**（タスクID の **先頭1文字**が異なる **F**／**P**／**I**／**T**）どうしの**優先度の数値**は**比較しない**。\
例として **FishTrack** の優先度5より**先の週**に **MyPokedex** の優先度1を置いても**問題ない**。\
（統合スケジュール上の**早い週から埋める**は、**各製品の一覧内**で優先度の高いタスクから週へ載せる、という意味で足りる。）

#### 厳密ルール（優先度週単調性・製品内）

[[#タスク一覧]] に **数値優先度（1〜5）** が付き、かつ **未完了**（着手対象）であるタスクを **比較対象**とする。**優先度 —**（完了・着手順不要など）は**本ルールの比較対象外**とする。

**比較対象は、タスクID の先頭1文字が同一のグループ内に限る**（**F**／**P**／**I**／**T**。以下 **同一プレフィックス**）。**異なるプレフィックス**のタスク同士には本ルールを**適用しない**。

同一プレフィックスの比較対象 **T1**・**T2** について、**T1 の優先度が T2 より高い**（数値が大きい）とき、**T1 が載る週は T2 が載る週より遅くならない**（**同週**も可）。\
**週**の前後は、各タスクが [[#週次スケジュール]] に配置された **ISO 8601 週（Wnn）** を、**その週の月曜日**で比較する（同じ Wnn なら等しい）。

**検証の落とし穴**: 上記は **T2 がより早い ISO 週**にある場合も含む（**同一プレフィックス内**）。\
例として **F** の **T2**（優先度3）が **W16** にあり **F** の **T1**（優先度4）を **W22** に置くと、週が逆転する（**W22** は **W16** より後）。\
**同一プレフィックス**で、**より高い優先度**のタスクは、**そのプレフィックス内の**より低い優先度のタスクより**後の週にだけ**載せない（当該プレフィックスの行を **全週**の週次表で突き合わせる）。

**検証の落とし穴（続き）**: **同一プレフィックス**で **T1**（優先度5）が **W17** にあり **T2**（優先度4）を **W16** に置くと、**T1 の週が T2 より後**になり **week(T1) ≤ week(T2)** に反する。\
**優先度の高い方が、低い方より前の週にだけ載らない**（**そのプレフィックス**について一覧と全週を見る）。

**単調性の含意（週の前後・製品内）**: 各 **プレフィックス**（**F**／**P**／**I**／**T**。統合の [[#タスク一覧]]）ごとに、当該 ID だけを週次表から集める。\
**Wa < Wb**（より早い ISO 週）のとき **max(Wb) ≤ min(Wa)**（そのプレフィックスに載る優先度**数値**の max / min）を満たすか確認してよい。\
**プレフィックスが異なる**タスク同士の**週の比較**は不要。

**同一週内の実行順**（未完了どうし）: **優先度の数値が大きいタスクを先に実行**する。**[[#タスク一覧]] の前タスク**・依存がこれに**優先**する（前を完了してから後続）。**—**（完了など）は着手順が不要な行としてその週の**末尾付近**にまとめてよい。

#### 厳密ルールと他原則の優先順位

次の **1 → 2** を満たしたうえで、**可能な限り**上記 **厳密ルール（優先度週単調性・製品内）** を満たす。

1. **前タスク**（[[#タスク一覧]]）— 後続タスクの週は、前タスクより**前**の週に置かない（週をまたぐ依存を壊さない）。
2. **週次配分の原則**（下記 **「週次配分の原則（4項目・全文）」**）— **件数**・**横断バランス（統合では主に F・P）** 等。

**1・2 と厳密ルールが両立しない**ときは、**週次表・一覧の優先度・依存の見直し**で両立を目指す。

**厳密ルール（優先度週単調性）を満たさなくてよい**のは、**同一プレフィックス内**で、**先行タスクの優先度が後続より低い**（数値が小さい）とき**に限る**。\
例：**優先度4**のタスクの**先行**が**優先度3**——先行は**重要性が低い**が、**前タスク**により先に着手する。\
このとき**ISO週**の並びが単調性と両立しないことがある。**件数・F/P 横断**だけを理由に単調性を**捨てない**（**上記の依存パターン**がないのに単調性を外す割当は置かない）。\
**やむを得ず**厳密ルールを満たせない割当が残る場合は、当該タスク行の**メモ**に**理由**を1行残す。

**週への配分**の運用（件数・横断バランス・前タスク・上記）の詳細は、**「週次配分の原則（4項目・全文）」**に集約する。\
**週次表の行順**は、読みやすさ・**前タスク**・（補助として）**同一優先度**で **F→P→I→T** などで決めてよい。**表の上から下＝実行順ではない**（実行順は **前タスク → 優先度**）。\
タスク間の依存は [[#タスク一覧]] の前タスク列を正とする。親子の階層（エピック／子タスクの包含）は持たない。\
転用・着手時の短い補足は [[#タスク詳細]] に置けるが、**定着させるナレッジは仕様書へ**（計画書に長文化しない）。\
MyPokedex の `P38`／`P40`／`P41`／`P42` は相互に親子の階層を持たない（各タスクの完了条件は一覧の 前タスク 列を正とする）。

### ゼロベース再配置（手順と監査）

**ゼロベース**とは、既存の週次表に引きずられず、**未完了タスク**と [[#タスク一覧]]・本節の **「優先度と週次の関係（詳細）」** だけから **週を再割当**すること。

1. **対象**: [[#タスク一覧]] の **未完了**（**優先度 —** の完了行は週次の件数に含めない運用は **週次配分の原則** の注記どおり）。
2. **依存**: **前タスク** 列で **先行週 ≦ 後続週**（同週可）になるよう制約を付ける。
3. **割当の順序**: **各プレフィックス（F／P／I／T）ごとに**（**統合**の [[#タスク一覧]]）、その一覧で**優先度の高いタスクから**週へ載せる。**同週に複数優先度**を混在してよい（**厳密ルール（製品内）** は **ISO 週の前後**で**同一プレフィックス内**満たす）。
4. **各週**: **週次配分の原則**（件数・**F・P を中心とする横断**・同一週内の実行順）に従う。
5. **検証**: **同一プレフィックス**の未完了 **T1, T2** について **優先度(T1) > 優先度(T2)** なら **week(T1) ≦ week(T2)**（同週可）を **一覧と週次**で突き合わせる。\
    **T2 がより早い週**にあるペアと、**T1 がより後の週**にあるペアの両方を見落とさない（**「優先度と週次の関係（詳細）」** の **検証の落とし穴**・**検証の落とし穴（続き）**）。**プレフィックスが異なる** **T1, T2** は**週番号で突き合わせない**。\
    **例外**: **後続**の優先度が**先行**より高く、**前タスク**のため単調性と両立しないペアは、**「厳密ルールと他原則の優先順位」**どおり。
6. **三本柱**（**統合**）: **F・P** がそれぞれ **2 未満**の週が残る場合は、**週次配分の原則** の **原則2の例外**（**未掲載の残がない**ときは **各2** 不要）に該当するか確認する。該当しないなら **理由をメモ**するか **再配分**する。
7. **ガント**: [[#ガントチャート]] を **同一作業単位**で更新する。

### 週次配分の原則（4項目・全文）

> #### 週次配分の原則
>
> リスケ・新規割当のとき、次を**同時に**満たす（本節の **「優先度と週次の関係（詳細）」**・三本柱・**[[#タスク一覧]]** と整合）。
>
> 1. **件数**: **最大 5 タスク／週（絶対条件）**（`#` 列のデータ行。**`-` 行は数えない**）。**6 件以上への増加は禁止**。割り切れない端数は **翌週へのリスケ**・**接尾辞付き ID**・**週次表の行追加（W29 など）**で吸収する（**週を 6 件で埋めない**）。
> 2. **横断バランス（`統合作業スケジュール.md`）**: **FishTrack（`F…`）・MyPokedex（`P…`）を、それぞれ最低 2 タスク／週**（接尾辞付き ID はベース ID のプレフィックスで数える）。\
> **単一製品の `#` だけで週を埋める**割当は行わない。\
> **例外**（**統合**）: **当該週の時点**で、**まだいずれの週次にも載せていない**未完了の **F**／**P**（**一覧に残る**）が**ない**ときは、**その製品について**「最低2」**は求めない**。\
> （**その週時点で未到来の残タスクがない**場合に、**F/P 各2** は適用しない。）\
> **両立の限界**: **前タスク**・**厳密ルール**・**件数**と**両立しない**ときは、**F・P 各2** を**優先できない週**が出る。\
> （例: 早期週に **F** が集中し **P** が **1** のみ。）**理由**を当該週の**メモ**に1行残すか、**未掲載の P** を**前の週へ**寄せる**再配分**で解消する。
> 3. **優先度と週の対応・同一週内の実行順**: **「厳密ルール（優先度週単調性・製品内）」** を正とする（**前タスク**・**件数・F/P 横断**と**両立**する割当を目指す）。\
> **同一プレフィックス**では、**高い優先度**のタスクが**より低い優先度**のタスクより**遅い ISO 週にだけ**載らない（例: **FishTrack** 内で **F49（4）** の週は **F29（2）** の週より**後**にできない。**別製品**の **P…** 等とは**比較しない**）。\
> **単調性の例外**は、**先行の優先度が後続より低い**（**前タスク**で後続の方が重要）とき**のみ**（**「厳密ルールと他原則の優先順位」**）。\
> **同一週内**の**実行順**（未完了どうし）は **優先度の数値が大きい順**を先にする。**前タスク**が定める順序・依存はこれに**優先**する。**—**（完了など）は一覧どおり週次にも載せ、着手順不要な行として扱う。
> 4. **前タスク**: [[#タスク一覧]] の **前タスク** 列を正とする。**前タスクがあるタスク**は、**前タスクを優先**する（前が完了してから後続。同一週に両方ある場合は **前タスクを先に完了**できるようメモ・行順で示す）。週をまたぐ配置と矛盾させない。
>
> 列・**#**・**優先度**・接尾辞付きID・`-` 行の扱い等の詳細は本 SKILL **「週次スケジュール（[[#週次スケジュール]]）」** の補足を参照（本 blockquote では繰り返さない）。\
> 週次表の **優先度**列は **[[#タスク一覧]]** と同一（**5**〜**1**。**完了**・着手順不要は **—**）。\
> 週次表に**埋め専用の行や週は置かない**。某一週にタスクが無い場合は**後続の週次を前倒し**してリスケし、[[#ガントチャート]]と同一編集で揃える。\
> **タスク間の依存**の補足は [[#タスク詳細]] にもよい。**週次の入れ替え**は **[[#タスク一覧]]・[[#ガントチャート]]** と**同一作業単位**（例: **`F23` と `F22`**・**`F47` と `P47`（前タスク列）**）。\
> **総数・週数の組み合わせは時期により変わる**ため、**件数の固定式は上記に拘束しない**。**埋め専用の空行**・**ダミー行**は置かない。\
> 制約を満たす割当の**試算**に **dev-workspace** の `temp/pack_mins_first.py`・`temp/week_assignment.tsv` を使ってよいが、**表の正本は常に計画書**。
>
> **2026-04-16 再配分**: **完了**行は **W16** に集約したまま、週の件数は **`#` 列の未完了行のみ**で数える（**完了行は含めない**）。

## 本 SKILL の記載方針

- **具体的なタスク番号（プレフィックス＋番号の実例）を本 SKILL に書かない**。例示は **`Fxx`** 等の**形式**・**計画書の該当節**への参照に留める。**個別IDの正**は **`統合作業スケジュール.md`**。

## 計画書メタ行（冒頭）

- **`作成日`** / **`最終更新日`**: **`YYYY-MM-DD` のみ**（例: `2026-04-08`）。**括弧・同じ行への追記で変更内容・差分・タスクID・週番号・リスケ理由を書かない**（変更履歴は **CursorLog** に記録する）。
- **`最終更新日` を直す作業**でも、**日付1行のみ**。「（〇〇を反映）」のような**括弧注記を誤って足さない**こと。
- **`最終更新日` に書く日付の正本**: **当該編集で計画書を保存した日**の **日本標準時（JST）** 暦日。**推測**・**会話の雰囲気だけ**・**別スレッド・別ファイルの日付**・**テンプレのコピー**で決めない。
- **AI（Cursor）が `最終更新日` を更新するとき（必須）**:
  1. チャットに付与されている **Today's date**（ユーザー情報の **Today's date:** 行）を読み、その **YYYY-MM-DD** と**一致**させる。
  2. **Today's date** が無い・信頼できないときは、保存直前に **JST** を取得してから記入する（**`obsidian-cursor-log` SKILL** のタイムスタンプ手順の **東京タイムゾーン**と同様でよい）。
  3. **禁止**: ユーザーや自分の推定で「たぶん翌日」「会話サマリの日付」だけを根拠にすること。
- **人間が手で直すとき**: PC の**今日**（運用上 **JST** に合わせる）と一致させる。

## 三本柱（必須）

- **タスク追加時の絶対規則（厳格）**: **[[#タスク一覧]]** に**新規行（新しいタスクID）を追加した場合**、**同一作業単位**で必ず次を満たすこと。**いずれかが欠けた状態で完了としない**。
  - **[[#週次スケジュール]]**: 当該タスクIDを、計画する週の表に**必ず1行以上**載せる（接尾辞付きIDの週次分割は既存ルールどおり）。
  - **[[#ガントチャート]]**: 当該タスクに対応する **mermaid バーを必ず追加**する（掲載月・開始日/終了日は週次見出しと整合。月跨ぎは開始月に1本のルールどおり）。
  - **解釈**: 「あとで週次だけ追記する」「ガントは次回」は**禁止**。追加作業は**一覧＋週次＋ガント**までを**一連の必須セット**とみなす。
- **タスク一覧**・**週次スケジュール**（`## スケジュール` 内）・**ガントチャート**の**いずれかを変えたら、同一作業単位で他の2つも更新**する。片方だけで終了しない。
- 整合の観点: **タスクID**、**ステータス（完了）**、**週の配置**、**ガントの期間と `done` / `active`** に矛盾がないこと。
- **ガントと週次の日付整合（必須）**: 週次見出しの **月曜〜日曜**（`#### YYYY-Wnn:` ＋当該週の月〜日）を**正**とする。\
    見出しの **Wnn** は **ISO 8601 週番号**（その週の**月曜**の `isocalendar().week`。**YYYY** は `isocalendar().year`＝ISO **週暦年**。12月・1月は暦年とずれることがある）。\
    同じ **ベースID**（接尾辞なし）を表す **1本のバー**は、週次で当該ID（または同一ベースに紐づく週次分割の接尾辞 `a/b/c…`）が**並ぶ全週**をカバーするよう、\
    **開始日＝その最初の週の月曜**・**終了日＝その最後の週の日曜**（必要なら翌週への僅かな越えは週次メモと矛盾しなければ可）に合わせる。\
    **週次に無いのにバーだけが長い**・**週次より著しく短い**状態を残さない。
- **月別ガントとの兼ね合い**: 上記で決めた開始日の**暦月**が「掲載する月のブロック」になる（`## ガントチャート（mermaid）` の**月をまたぐタスクは開始月に1回**と同じ運用）。並び替え・追加時は**週次→日付→掲載ブロック**の順で決める。
- **ロードマップ級の粗いバー**: 週次に細分化されていない **まとめ用バー**だけを置く場合は、対応する **[[#タスク一覧]]** または **[[#タスク詳細]]** に「週次のどの枠に対応するか」を短く書き、週次側に出てくるIDと**矛盾しない日付**にする。
- 完了の反映（ステータス・`done`・週次メモ）でも**三本柱**の整合は同様。**ユーザーが明示的に削除を指示するまで**、一覧・週次・ガントから**該当タスクの行を削除しない**（下記「完了タスクの行の扱い」）。

## 完了表記・その他の表

- 完了は **ステータス** 列に `✅ 完了` 等。
- **[[#概要]]** の索引・各 **[[#タスク詳細]]** など他表は、当該表ヘッダの **ステータス** 列へ。未完了・予定は `-`。
- **完了タスクの行の扱い（厳格）**: タスクが完了しても、**ユーザーが明示的に「削除」「一覧から落とす」等を指示するまで**、\
    **[[#タスク一覧]]**・**[[#週次スケジュール]]**・**[[#ガントチャート]]** から**該当行・該当バーを削除しない**。\
    完了は **ステータス**・**ガントの `done`**・週次メモ等で示す。作業履歴の詳細は CursorLog。\
    整理で行を消す場合も**三本柱**を同一編集で揃えるが、**削除はユーザーの明示指示があるときのみ**。

## タスク一覧（[[#タスク一覧]]）

### タスク間の関係（原則）

- **持たせる**: **依存関係**および**着手の前後制約**は **前タスク** 列（および週次・ガント上の配置）で表す。
- **持たせない**: **親子の階層**（エピック／ストーリー／サブタスクの包含関係）。WBS 型の親子分解を計画書の構造として持たない。
- **週をまたぐ接尾辞**（ベースIDに `a`／`b` 等を付した週次分割用ID）: 同一タスクを複数週にまたいで週次表に載せるための**表記上の分割**であり、親子関係ではない。ガントの **1本のバー**と **接尾辞なしID**（ベースID）の対応は、**週次スケジュール** 節のルールに従う。

- 列順: **#｜優先度｜ステータス｜タスク｜前タスク｜内容概要**。**優先度**（2列目）は **5**（最優先）〜 **1**（最低）の **5 段階**（数字1桁）。**完了済み**など着手順付けが不要な行は **—**（計画書 [[#タスク一覧]] の冒頭説明と整合）。
- **粒度**: **1タスク = 1つの作業成果**を原則とする。1行に「A・B・C」や「設計＋実装＋検証＋仕上げ」を詰め込まない。複数の成果物・画面・データモデル・運用手順が含まれる場合は、連番タスクに分割し、依存は **前タスク** 列で表す。
- **前タスク**: **タスク間の依存関係の正本**。**主な**着手ブロッカー・直前に完了しておきたいタスクID。**単一・複数**の依存はともに **[[#タスク一覧]]** の表に集約する。\
  **前タスク** 列を主とし、**複数 ID** が列に収まらないときは**同一行**の **内容概要** に短く併記してよい。該当なしは **—**。\
  **[[#タスク詳細]]** に依存の重複を書かない。プロジェクト固有の「相互依存なし」「収益モデル周辺タスクの関係」等は **`統合作業スケジュール.md`** の **タスク一覧・該当詳細節**を正とし、本 SKILL では列挙しない。
- **構成**: プロジェクトごとに **優先度見出しで分割しない**。**タスクID（番号）順**で **1表**（**同一プレフィックス内は番号の昇順**）。
    **I**・**T**（`personal-tools` 全体。みてねキーパー含む）も同様に1表（横断は既存の節どおり）。
- **内容概要**に、着手時期・週番号・目安日など**いつやるか**を書かない（時期・週次は週次表のみ）。
- **1行目安（必須）**: 各タスクは **1表行に1マークダウン行**（内容概要は **1物理行** を目安）。**続き行（同タスクの追記行）を置かない**。長文・リンク列挙・手順メモは **`[[#タスク詳細]]`** 側に移す。
- **補足の置き場所**: 当該プロジェクトの **`[[#タスク詳細]]`** 内の **`### 【詳細】〈製品名〉`** 以下に **`#### … タスク一覧補足（…）`**（または既存見出し直下の **タスクID 別箇条書き**）を置く。
    一覧の **内容概要** は **短く要約**し **`§2.1` 等**または **wiki リンク**で指す。**I** は **`[[#【詳細】共通インフラ]]`**、**T**（みてねキーパー・クレカ明細集約等）は **`[[#【詳細】みてねキーパー]]`**・各製品の詳細節（例: **`[[#【詳細】クレジットカード明細集約]]`**）へ集約する。
- **補足と仕様書の役割分担**: 手順・設計の**永続記述**は**仕様書**へ。**計画書の補足**は着手前後のメモ・依存の補助に留め、長文化したら仕様書へ移す（`specification-update` SKILL と整合）。
- **[[#タスク詳細]] の記載範囲**: **タスクに紐づく情報のみ**（[[#タスク一覧]] の ID 別補足・転用・同一リリース整合など）。タスクに紐づかない内容は仕様書へ（計画書「タスク詳細」冒頭の blockquote を正とする）。
- 週次用 **接尾辞付きID**を使う場合、**一覧側でベースIDとの対応**（続行・注記）を残す（ただし **続き行で長文を書かず**、詳細節に書く）。
- **新規追加時の順序（優先度・影響）**: **現在のタスク群の末尾**へ **無思考で足す**（一覧の最終行だけ・詳細補足の最後だけ・週次の最遠の空き週だけ、に寄せる）のではなく、**優先度・事業／UX への影響・依存関係・ブロッカー**を踏まえて **どこに載せるか** を検討する。
  - **[[#タスク一覧]] の行位置**: 表内の並びは **タスクID（番号）順**が正。新規は **採番ルール**に従い、**ID を途中に挿入して並べ替えない**（一覧の並びそのもので優先度を表すのではない）。
  - **着手の前後関係（週次・ガント）**: **いつ着手するか**は上記を踏まえ、**適切な週**に載せる（**三本柱**で週次・ガントを整合）。単に「表の下に行が増えたから最遠週へ」に寄せない。
  - **[[#タスク詳細]] の補足**: **`- **Fxx**:` 等のブロックの並び**は、**関連する既存タスクの近く**に置くなど、読み手が文脈を追える順を検討する（**常にセクション末尾への追記だけ**にしない）。
  - **複数タスクを一括で追加する場合**（例: **`ux_ideation`** コマンド）も同様。チャットで示した **優先の目安**と、計画書上の **週・詳細の位置づけ**を揃える。

## 週次スケジュール（[[#週次スケジュール]]）

- **週番号**: メモ・本文・ガントで用いる **Wnn** は **ISO 8601**（「三本柱」の見出しルールと同じ）。見出しをリスケしたら **月曜の日付から Wnn（と必要なら週暦年）を再計算**し、表内の週番号表記と矛盾がないようにする。
- **週次配分の原則（正本）**: 本 SKILL **「週次配分の原則（4項目・全文）」**。計画書の [[#週次スケジュール]] 見出し直下は**要点の blockquote**のみ（全文の重複は載せない）。
- 列: **#｜優先度｜ステータス｜タスク内容｜メモ**（**優先度**は [[#タスク一覧]] の2列目と同一。**5**〜**1**・**完了**等で着手順が不要な行は **—**）
- **[[#タスク一覧]]** の **優先度**（2列目）を**変更**したら、該当タスクが載る **週次表の行の優先度**を**同一作業単位**で直す（一覧と週次で数値が食い違わないようにする）。\
    **あわせて**、本 SKILL **「優先度と週次の関係（詳細）」** の**厳密ルール**・**前タスク**・件数・**F/P 横断**に照らし、**週の配置**と**[[#ガントチャート]]** を**同一作業単位**で見直す（**優先度だけ**差し替えて週・ガントを置いたままにしない）。
- **埋め専用の行・週は置かない**。某一週にタスクが無い場合は**後続週を前倒し**してリスケし、[[#ガントチャート]]と同一編集で揃える。
- **同一週・同一ベースIDの作業が複数行**になる場合は **ベースIDの1行**にまとめる（枝番の扱い・**#** 列に付けない形式は **計画書の週次表**を参照。内訳は **タスク内容** で読点・括弧に列挙）。**週をまたぐ**表記の分割だけ `…a` / `…b` や `…-2` を使う。
- **#** は **先に [[#タスク一覧]] に行を追加し、付与したタスクID** を記載する（週次用接尾辞付きIDは一覧にベースID・注記で対応付ける）。
- **`-`** は当該週の完了サマリなど、**一覧に紐づけない記録のみ**。
- **タスク内容**はその週の作業の要約（4月以降ブロックは `プロジェクト — 内容`）。
- 週次分割の一部が完了したときは **ベースIDの週次行・一覧・ガント**と揃える（メモで「ベースに包含済」可）。
- **週あたりの件数・横断バランス（統合では F・P 中心）**: 上記 **週次配分の原則**および計画書 [[#週次スケジュール]] の要点 blockquote と整合。\
  **一覧の総数・週あたり配分は時期により変わる**ため、具体件数や固定の数式は本 SKILL に書かない。[[#タスク一覧]] と週次表で都度確認し、**計画書を正**とする。
- **割当の試算**: `dev-workspace/temp/pack_mins_first.py`（出力 `temp/week_assignment.tsv`）を参照してよいが、**優先度・依存・同週制約の最終判断は人手**。三本柱更新時は**常に計画書の表**を正とする。

## ガントチャート（mermaid）

- **月ごとの記載**: ガントは **カレンダー月ごと**に `### YYYY年M月` と **mermaid 1本**で記載する（複数月を1図に併記しない）。
- **月をまたぐタスクの掲載月**: 開始日と終了日が異なる月にまたがるタスクは、**開始日が属する月**のチャートに **1回だけ** 記載する（終了側の月に同じバーを繰り返さない）。いわゆる「前月側」＝タイムライン上の **早い月＝開始月**。
- **スケジュールとの粒度の違い**: 週次（**Wnn**、いずれも **ISO 8601 週**）は **1タスク最長1週間**。ガントは上記の **月単位の図**で、**1タスク＝1本のバー**（終了日が翌月でもその1本に含め、翌月の図では重ねない）。
- **ガントチャート更新時のルール**: 完了しても**開始・終了は予定日のまま**。完了は **`done`**（キーワード）のみ。実績日へ差し替えない。
- **週次との対応**: 同一タスクは **[[#タスク一覧]] の ID**（**#** 列と一致）で突き合わせる。バーの日程は前節 **三本柱**の「週次の月曜〜日曜と整合」と**セット**で見る。
- **mermaid のタスクID**: コロン直後は **[[#タスク一覧]] と同じ ID**（例 `:Fxx,`・`:done, Pxx,`。**F** / **P** / **T** / **I** ＋番号）。\
    **ft** / **mp** / 小文字 **o** / **infra** / **mk** は使わない。**一覧に無い ID のバーはガントに載せない**（整理時は削除）。
- **接尾辞付きID**が **ベースID**（接尾辞なし）の **1本のバー**に集約される場合、完了時は **ベースIDの週次行・一覧ステータス・ガントの `done`** を揃える（分割行は「ベースに包含済」をメモで明示してよい）。
- **週次のみ**の完了（緊急対応など）をガントに載せる場合は **[[#タスク一覧]] の既存ID**に紐づける。**該当月**に短いバーを追加し **`done`** を付けて週次と併記する（**一覧に無いIDのバーは置かない**）。

## タスク詳細・横断節の再編（低頻度）

**日常更新では不要**。`## タスク詳細` で**見出しの統合・大移動**をするときのみ参照する。

- **置き場所**: 製品ごと **`### 【詳細】…`**。全プロダクト共通は **`【詳細】共通インフラ`** の横断見出しへ。
- **同一作業単位**: **`[[#…]]` の置換**、**目次・冒頭・[[#タスク一覧]]** の整合、**表行欠落**の有無（大きな切り貼り後）。必要なら計画書外の Obsidian を検索（過去 CursorLog は残してよい）。
- 終了時は下記 **「編集後（必須）」**。

## スケジュール前倒しメモ

- 計画書上部の **スケジュール前倒し**・日付注記がある。**既存注記を壊さない**。**Wnn** の意味は **ISO 8601**（上記）— 歴史注記と見出しが食い違う場合は **月曜〜日付を正**として **YYYY-Wnn** と表内の **Wnn** を揃える。

## 編集後（必須）

1. **`markdownlint-cli`**（`dev-workspace/.markdownlint.json`）で当該 `.md` を検証し、**エラーゼロ**にする。
2. **`最終更新日`** を変更した場合: **冒頭の当該行が `YYYY-MM-DD` のみ**であること（**括弧・変更内容の追記が付いていないこと**）を確認する。**日付の値**が **Today's date（JST）** または取得した **JST 暦日**と一致していること（**推測日付でないこと**）を確認する。
3. **ファイルを変えた作業の完了報告前**に、myrules 通り **`obsidian-cursor-log` SKILL** で CursorLog を追記する（JST の実時刻）。

## 仕様書との役割分担

- **プロダクトの振る舞い・API・DB の正**は仕様書（`DevProject/specifications/`）。**タスクID・週・ガント**は本計画書。
- 仕様書更新の手順は **`specification-update` SKILL**。計画書だけ触る変更と、実装に伴う仕様＋計画の**両方**が必要な場合は**両 SKILL** を満たす。

## 同種作業の横断知見転用（計画書内）

- **スケジュール上で別プロダクトに性質が近い作業**（例: 認証・同意取得・セッション周り）がある場合、**各タスクの週の遠近や前後関係にかかわらず**、計画書に置いた **横断転用の節**（見出し名・対象テーマは計画書で定義）を**正**として知見を転用する。
- **いずれかのプロダクトで先に**実装がマージ・収束したタイミングで、当該節の **転用メモ**（手順・落とし穴・参照先）を更新する。**他プロダクトの担当**は、着手前・着手中を問わず必要に応じて同節を参照する（**先行・後発・週が離れていても**可）。
- **同週に寄せるか**・**週番号**は、転用ルールとは別に **計画書の週次表**だけで管理する。本 SKILL に**具体的なタスク番号や週番号を固定で列挙しない**（リスケで陳腐化させない）。
