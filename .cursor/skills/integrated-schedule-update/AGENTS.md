# integrated-schedule-update

Obsidian `DevProject/plans/統合作業スケジュール.md` の更新（タスク一覧・週次・ガント・三本柱。詳細節の大移動は SKILL 内の低頻度ノート）は `SKILL.md` に従う。

**厳格**: タスク一覧に**新規タスクを追加したら**、**週次スケジュール**と**ガントチャート**への記載は**必須**（一覧のみで終了禁止）。詳細は `SKILL.md` の三本柱・絶対規則。

**完了タスクの削除**: ユーザーが明示的に削除を指示するまで、一覧・週次・ガントから**行を削除しない**（完了はステータス等。`SKILL.md`「完了表記・その他の表」）。

**新規追加の順序**: 末尾への機械的追記だけにせず、`SKILL.md`「タスク一覧」の **新規追加時の順序（優先度・影響）** に従う。

**メタ行**: 冒頭 **`最終更新日`** は **`YYYY-MM-DD` のみ**（括弧に変更内容を書かない）。`SKILL.md`「計画書メタ行」。

**タスクの関係**: **依存・前後**は **前タスク** 列と週次・ガントで表す。**親子階層**（エピック／子の包含）は持たない。週またぎの **接尾辞付きID** は表記上の分割（`SKILL.md`「タスク間の関係（原則）」）。

**SKILL 本文**: **具体的なタスク番号は書かない**（`SKILL.md`「本 SKILL の記載方針」）。個別IDは **統合作業スケジュール.md** が正。

**`DevProject/` の正本**: 計画用タスク番号を**記載してよい**のは **`plans/統合作業スケジュール.md`** **のみ**（myrules「タスク番号の正本」）。

**ナレッジの置き場所**: 永続的な設計・手順は**仕様書**（`DevProject/specifications/`）。計画書はタスク中心・補足は一時メモに留める（`SKILL.md`「正のドキュメント」）。

**タスク詳細節**: **タスクに紐づく情報のみ**を書く。非紐づけは仕様書へ（計画書 `## タスク詳細` 直下の blockquote）。
