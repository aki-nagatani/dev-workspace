## 3.1. `dump_spec_import_preview.py` CLI 早見・0 件切り分け

- `--kind` … `success`（既定）＝`プレビュー結果:` 行のみ。`failure` ＝`プレビュー失敗:` 行のみ
- `--count` … ヒット件数のみ表示
- `--list --limit N` … 成功時は `[index] timestamp  category=...  rows=...  url=...`。
  **失敗時**は `code` / `jobId` / `requestId` / `url`（`sourceUrl`）/ `message` 先頭。
  **「新しい」順**は既定で `--order time`（各ログ行先頭の
  `[YYYY-MM-DD HH:MM:SS]` を**記録日時**として比較し、**新しい順＝降順**）。
  `grep` のファイル順混在に依存しない
- `--order file` … 従来どおり、入力テキスト上の**出現の逆順**（特殊用途）
- 0 件だった場合の切り分け:
  - **`--kind success` で 0 件・UI は失敗表示** → `--kind failure` と
    `プレビュー失敗:` の grep を試す（**失敗行**は別コードパス。未デプロイ・無効環境変数では両方 0 件になり得る）
  - 環境変数 2 つ（`FISHTRACK_STANDALONE`, `FISHTRACK_SPEC_IMPORT_DEBUG_LOG`）
    が当該環境（本番 `.env` / ローカル compose）で有効か（**成功プレビュー行**の出力条件。**失敗行**は WARNING で別経路）
  - ファイルに出ておらず **stdout** のみの可能性 → **各入口 SKILL §0** の取得元 (2) を参照
  - ローテーション後で別ファイルに移っている（ローカル `docker` 経路）
    → `--include-rotated` を付けて再実行、または本番 EC2 側で連結してから `--stdin`
  - まだ 1 度も**当該環境**でプレビューを実行していない → ユーザーの合意のもと UI で再現依頼

**ローカル Docker（FishTrack）で `src/` を同一セッションで変更したあとにログを読むとき**:

## 6A. ロッド検証（5 観点）

`category = "rod"` の場合に適用。差異があれば観点ごとに一覧化する。

- **A. 件数**
  - `rowsCount` が本家製品スペック表の行数と一致するか
  - 過不足があれば該当 row と model を列挙
- **B. 数値の原文一致**
  - `lureWeightMinOz` / `lureWeightMaxOz`, `lengthFt` / `lengthIn` が本家の数値表記と一致するか
  - **DAIWA 製品スペック表にルアー重量が複数列ある場合**（**ルアー重量（ｇ）**・**ルアー重量（ｇ）（ジグ）**・**ルアー重量（oz）** が**いずれも存在**）: 照合・正本は **（oz）列のみ**とし、**g の 2 列は無視**する（LLM 入力・サーバ抽出・`ai_spec_check_report.md` の本家値列を揃える）。
  - **帯分数と小数は同値なら一致**: 例として本家が `1 1/2oz` / `1-1/2 oz` /
    `1+1/2oz` 等、AI が `1.5oz` に**小数化**している場合は、数値として等しければ
    **差分ではなく一致**と判定する（逆も同様。単位 `oz` の有無・スペースの差は
    表記揺れとして許容し、**数値の等価性**で見る）
  - `約` / `〜` / `前後` / `程度` / `MAX` 等の**近似語混入**がないか
  - `1/7` のような分数が勝手に `約9/64` 等へ**別の分数へ近似変換**されていないか
    （上記の**同値な帯分数→小数**とは別問題）
  - **生ログ `rows[]` の文字列**と**管理画面の入力欄表示**:
    プレビュー HTML 表では `routes_master` → `_format_fractional_ounce` により、AI が小数
    文字列で返しても**画面上は分数など読み取りやすい表記**に揃う（実装: FishTrack
    `routes_helpers._format_fractional_ounce`）。**本家の分数と数値等価**で、**画面表記が
    本家と突き合わせ可能**なら、**dump JSON だけ**が小数でも **🔴（原文の不一致）とはしない**
    （人間向けの再確認は**画面**、または同じ整形をログ値に**一度**当ててから本家と比較する）。
  - **全長（`lengthFt` / `lengthIn`）と本家 全長（m）**:
    本家製品スペック表が **全長（m）** 列のみ（ft/in 列が無い）場合、プレビュー整数
    **`lengthFt`・`lengthIn`** から **再構成**する全長（メートル）は\
    **`(lengthFt * 12 + lengthIn) * 0.0254`**（**インチの SI 換算**）とする。\
    本家 **m** が **小数第 2 位まで**しか無いページでは、再構成 m を **小数第 2 位で四捨五入**し、\
    **本家の数値と等しければ一致**（**同一行のモデル**と突き合わせる）。\
    **差の絶対値が 0.02 m（2 cm）超**、または **本家に全長があるのに `lengthFt` / `lengthIn` が欠損**（null 等）\
    は **🔴**。レポート **`ai_spec_check_report.md`** では **ロッド成功プレビューごとに本照合を表で必須**
    （**`ai-local-spec-check` / `ai-spec-check` 共通**。省略禁止）。
  - **本家「テーパー」列とプレビュー `action`（DAIWA ロッド）**:
    本家製品スペック表に **テーパー**（またはアクション相当）列があるページでは、FishTrack が **`rows[].action`** に正規化した値と **同一 `modelName` 行の本家セル**を**行別に**照合する（**`XF→S` / `R→S` 等は原文どおり**で比較）。**省略禁止**。
    **本家と異なる**（例: 本家 **`F`** に対し **`FR`** — 型番サフィックスとの混淆）は **🔴**。
    **テーパー列が無い**ページでは、アイテム紹介の **7：3** 等の**比率 prose**は **`action` の正本ではない**。\
    プレビューは **型番 Pattern** 由来の **S/R/F/X（または RF/RS 等）**で出る想定のため、**本家紹介の比率文と `rows[].action` の見た目差**単体では **🔴** にしない（仕様 `05_ai_spec_import.md` と整合。照合表では **本家（紹介・比率）**列と **`action`（略号）**列を分けて書く）。
    **Obsidian 正本 `ai_spec_check_report.md`（テーパー／アクション・DAIWA ロッド）**: `category = "rod"` かつ**プレビュー成功**の照合では、\
    **本家製品スペック表に「テーパー」列**（または**アクション相当の単名列**）があるとき、**本家テーパー（原文）** と **`rows[].action`** の**行別照合表**を**必ず**書く（**`##` 見出し**のみの節でもよい）。**省略禁止**（**「未実施」一言**は不可）。\
    **判定**は **`XF→S` / `R→S` 等は本家表記どおり**で比較し、**本家と異なる**値は **🔴**（例: 本家 **`F`**、プレビュー **`FR`**）。\

3. **`resolvedUrl` が前回と同一**の場合:
   - 上書き前に、**旧ファイルの本文**（フロントマター直下から EOF まで）を読み、比較材料にする。
   - 新しい本文に **「## 前回からの変化」** を**必ず**含め、次を箇条書きで書く（該当なしなら「差分なし（主要観点ともに同等）」と明示）:
     - **改善**: 前回 🔴/🟡 だった事象が今回解消・緩和した具体（row / modelName / 観点）
     - **後退**: 前回は問題なし・軽微だったが今回 🔴/🟡 が増えた具体
     - **継続課題**: 前回から変わらない 🔴/🟡（行・項目を列挙）
   - 同一 URL の**連続実行**では、レポートは**最新 1 回分のフル内容**を本文に含め、**「前回からの変化」**で差分を吸収する（旧レポート全文をファイル末尾に無制限に積まない）。

### 9.3 本文の構成
