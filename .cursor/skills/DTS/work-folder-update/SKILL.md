# work-folder-update（Work フォルダ更新ゲート）

**`Obsidian/Work/`** は、**株式会社DTSにおける本職**（いわゆる「仕事」）に関する情報を集約する正本領域である。\
AI がこの配下を修正するときは、**チャットだけで収束させず**、**ユーザーから得た情報を適宜相応のノートに記録として残す**。

## 適用範囲（本職と副職の区別）

| 区分 | 内容 | 本 SKILL |
| --- | --- | --- |
| **本職** | **株式会社DTS** の業務（PL としての体制・メンバー・顧客案件・人事考課・社内手続き等） | **対象**（`Obsidian/Work/`） |
| **副職・趣味** | **FishTrack**・**MyPokedex**・**おたよりナビ** 等の個人プロダクト開発 | **対象外** |
| **副職・趣味** | **`Obsidian/DevProject/`**（仕様書・計画・ai_spec_check_report 等） | **対象外** |
| **副職・趣味** | 各プロダクトの **git リポジトリ**（`FishTrack/`・`MyPokedex/`・`otayori-navi/` 等） | **対象外** |

副職・趣味側の編集は、各リポの **`AGENTS.md`**・**`specification-update`**・製品別 SKILL を正とする。**本 SKILL は Read しない**（Work 配下に触れない限り）。

myrules を厳守する（**スクリプト一括置換禁止**・**報告前 CursorLog**・**document-creation-policy**）。

**最初の作業**: 本ファイルを **Read** する。続けて **当該セッションのチャット**から、ユーザーが提供した**業務上の事実・合意・方針・状況変化**を棚卸しする。

要約は同ディレクトリの **`AGENTS.md`** と整合させる。

## 位置づけ（他 SKILL との関係）

| SKILL | 役割 |
| --- | --- |
| **本 SKILL** | **Work 配下を触るすべての作業の入口**。チャット情報の振り分け・記録漏れ防止 |
| **`work-kadai-update`** | **`Work/課題.md`** の書き方・統合・カテゴリ（課題ブロックの正本） |
| **`mokuhyo-*`** | **人事考課_管理シート**・目標・校閲・Excel/CSV 同期 |
| **`work-knowledge-deepen`** | **暗黙知の深掘り**専用セッション（質問→回答ループ）。本 SKILL の記録義務と併用可 |
| **`markdown-editing`** / **`markdownlint-fix`** | Work 内 `.md` の体裁 |
| **`obsidian-cursor-log`** | Work 変更後の CursorLog（myrules 必須） |

**専用 SKILL がある領域**では、本 SKILL で振り分けたあと**必ず該当 SKILL も Read**して書き方に従う。

## 発火条件（必須）

次のいずれかに当てはまるとき、**ファイル編集の前に**本 SKILL を Read する。

- **`D:/OneDrive/アプリ/remotely-save/Obsidian/Work/`** 配下の **`.md` / `.csv`** を **作成・更新・削除**する
- ユーザーが **`@Obsidian/Work`** または Work 内のパスを指定して依頼した
- **`mokuhyo-*`**・**`work-kadai-update`**・**`work-knowledge-deepen`** のいずれかが発火し、Work 配下を変更する

**対象外**:

- **`CursorLog/`** のみの追記（Work 本体に触れない場合）
- **副職・趣味**（上記「適用範囲」）。`DevProject/`・製品リポのみの作業では本 SKILL は発火しない

## Work フォルダの原則

- **会社規約・正式文書（SharePoint 等）の写し**は載せない。正本は社内公式。**参照一行**で足りる（**`work-knowledge-deepen`**「記載不要なもの」と同一）。
- **1 回限り・記録不要**とユーザーが明示した情報は、依頼ファイルへの最小反映に留め、他ノートへ広げない。
- **機密**: Work は社外秘。会話・ログへの要約は最小限。外部検索・外部ツールへ送らない。

## 作業フロー（省略禁止）

### 1. チャット情報の棚卸し

当該セッションでユーザーから得た次を列挙する（依頼ファイル以外も含む）。

- **事実**（体制変更・メンバー属性・顧客 FB・数値・日程）
- **合意・方針**（打ち手・優先度・エスカレーション）
- **状況変化**（課題の進捗・解決・新規課題・役割変更）

**ユーザーが「記録しないで」「チャットだけで」**と明示した項目は除外する。

### 2. 記録先の振り分け

下表に従い、**記録すべき情報ごと**に正本ノートを決める。複数ノートに跨る場合は**同一セッション内**ですべて反映する。

| 情報の種類 | 記録先（正本） | 併用 SKILL |
| --- | --- | --- |
| **配下メンバー・客員**（属性・配置・経歴・通勤等） | `Work/メンバー/配下メンバー.md`（個人が大きい場合は `Work/メンバー/` 配下の個別ノート）。**プロパーメンバー**は**社員番号（BF6）昇順** | — |
| **体制・役割・プロジェクト概要・ステークホルダ・DoD・エスカレーション・情報共有範囲・開発ルール** | `Work/体制・プロジェクト/` の該当ノート | — |
| **継続・未解決の業務課題**（財務・CS・育成・稼働・体制等） | `Work/課題.md` | **`work-kadai-update`** |
| **人事考課・目標・達成基準・設定時コメント・管理シート** | `Work/社内業務/人事考課/` | **`mokuhyo-*`**（用途に応じて draft / proofread / excel-to-markdown / hojo-setteiji-comment / kanri-sheet-csv） |
| **社内手続き**（勤怠・経費・休日出勤・オンボーディング等） | `Work/社内手続き/` | — |
| **顧客対応**（打合せ・障害報告・コミュニケーション） | `Work/顧客対応/` | — |
| **定例・報告・振り返り** | `Work/定例・報告/` | — |
| **社内コミュニケーション**（連絡手段等） | `Work/社内コミュニケーション/` | — |
| **社内業務**（新卒採用・面接メモ等） | `Work/社内業務/{テーマ}/` | — |
| **用語・言い回し・社内の意味** | `Work/その他/用語集.md` | — |
| **暗黙知の体系化・深掘り**（依頼が深掘り系のとき） | テーマフォルダ内ノート | **`work-knowledge-deepen`** |
| **後で深掘りしたいネタ**（今回は未整理） | `Work/ネタ帳.md` | — |
| **記録先が一意に決まらない** | ユーザーに確認。暫定は `Work/その他/` | — |

**依頼で指定されたファイル**への反映に加え、上表の**別ノートにも書くべき情報があれば必ず追記**する（記録漏れ防止）。

### 3. ノート分割・新規作成

- 新規ノート・分割の前に **`Work/その他/ノート分割の基準.md`** を Read する。
- **既存ノートへの追記で足りるか**を先に検討する（**document-creation-policy**: ユーザー意図なく新規 `.md` を増やさない）。
- 新規ノートが必要なときは、**テーマに応じたサブフォルダ**に作成する。

### 4. 編集の実施

- **myrules**: `StrReplace` / `Write` で**ブロック単位**。`replace_all` 禁止。
- **開示範囲**（単価・個人情報・評価・顧客非開示の障害等）に触れるときは、ノート内に **開示範囲** を明記する（**`work-knowledge-deepen`** と同趣旨）。
- **日付**: 新規記載は **`datetime-jst`** で JST 実日付を取得する。課題ブロックの **最終更新** 等は各専用 SKILL に従う。

### 5. 検証とログ

1. Work 内 `.md` を編集したら **`markdownlint-fix` SKILL** で当該ファイルの lint を解消する。
2. **`obsidian-cursor-log` SKILL** で CursorLog を更新する（変更ファイル・記録したノート一覧を含める）。
3. ユーザー報告に **「CursorLogは更新しました」** を含める。

## 報告時に含めること（推奨）

- **記録したノート**のパス（依頼先以外に追記した場合は**明示**）
- **記録しなかった**チャット情報があり、理由（ユーザー明示・規約正本・重複・要確認）

## 典型パターン

| パターン | 動作 |
| --- | --- |
| ユーザーがメンバーの異動を伝えつつ `課題.md` 更新を依頼 | `課題.md` は **`work-kadai-update`**。あわせて **`配下メンバー.md`**（または体制ノート）へ異動を記録 |
| 定例会のメモ整理依頼＋チャットで顧客 FB | `定例・報告/` にメモ。未解決課題は **`課題.md`** へ **`work-kadai-update`** |
| 目標下書きセッション | **`mokuhyo-draft`** が主。確定した課題は **`work-kadai-update`** で `課題.md` へ**報告前**同期 |
| 規約に既にある手順の確認 | Work へ写さない。参照のみ |

## 注意事項

- **チャットにだけ残す**のは禁止（ユーザーが記録不要と明示した場合を除く）。
- **推測で補完しない**。ユーザー発言・既存ノート・Read した正本だけを根拠にする。
- **CSV 併設**: 人事考課管理シートを触ったときは **`mokuhyo-kanri-sheet-csv` SKILL** に従い **`.md` と `.csv` を同一セッションで同期**する。
