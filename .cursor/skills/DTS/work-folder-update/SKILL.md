# work-folder-update（Work フォルダ更新ゲート）

## 必須の最初アクション（省略禁止）

**`Obsidian/Work/`** 配下の **`.md` / `.csv`** を **作成・更新・削除**しようとするときは、\
**`StrReplace` / `Write` / `Delete` 等の編集ツールを呼ぶ前に**、必ず **`SKILL.md`（本ファイル）を Read ツールで全文読む**。

- **Read せず編集しない**（チャット要約・`AGENTS.md` のみ・前ターンで Read 済みでも**当該セッションの Work 編集ごとに再 Read**）
- Read 後、**§ 作業フロー**に従い振り分け・記録漏れ防止を行う
- **専用 SKILL**（`work-kadai-update`・`mokuhyo-*` 等）が発火する領域では、本 SKILL の Read **のあと**に該当 SKILL も Read する

**`Obsidian/Work/`** は、**株式会社DTSにおける本職**（いわゆる「仕事」）に関する情報を集約する正本領域である。\
AI がこの配下を修正するときは、**チャットだけで収束させず**、**ユーザーから得た情報を適宜相応のノートに記録として残す**。

**本 SKILL の目的**: Work に関する**ありとあらゆる業務情報**を、依頼の主題以外からも**能動的に拾い**、正本へ**漏れなく**載せる。依頼は「1ファイルの修正」でも、セッション全体のチャットは**収集対象**とする。

## 収集対象（情報の種類）

チャット・依頼・添付・ユーザー訂正から、次に当てはまるものは**すべて記録候補**とする（**記録不要**の明示がある場合を除く）。

| 大分類 | 含むもの（例） |
| --- | --- |
| **人・体制** | 配下・客員の属性・配置・異動・休職・通勤・役割・後任・兼任・1on1 の論点 |
| **資格・認定** | 資格試験・取得日・有効期限・プロ認定グレード・育成カルテと Work の差分 |
| **プロジェクト・案件** | 概要・期間・契約・体制表・DoD・リリース・変更管理・ツール・ドキュメント管理 |
| **ステークホルダ** | 顧客・社内関係者・エスカレーション先・情報共有の範囲 |
| **課題・リスク** | 継続課題・未決・打ち手・進捗・解決（解決時は `課題.md` から整理） |
| **人事・評価** | 目標・達成基準・考課・面談・設定時コメント・評価の流れ |
| **社内手続き** | 勤怠・経費・休出・備品・セキュリティ・コンプライアンス・オンボーディング |
| **社内業務** | 採用・面接・プロ認定・研修・社内制度の**運用上のメモ**（正式規約の写しは除く） |
| **顧客対応** | 打合せ・障害・遅延報告・コミュニケーションの型・顧客 FB |
| **定例・報告** | 定例会・振り返り・報告メモ・決定事項 |
| **コミュニケーション** | 連絡手段の使い分け・社内の言い回し |
| **用語・暗黙知** | 社内特有の意味・判断基準・「こういうときはこうする」 |
| **数値・日程** | 売上・稼働・期限・締切・期（◯◯期）・四半期表記 |
| **合意・方針** | PL としての決めごと・優先度・エスカレーション方針・ユーザー訂正 |
| **未整理** | 深掘り前・記録先未定 → **`Work/ネタ帳.md`**（後でテーマフォルダへ） |

**載せないもの**: 会社規約・SharePoint 正式文書の**全文写し**、副職（FishTrack 等）の開発情報、ユーザーが**記録不要**と明示したもの（**`work-knowledge-deepen`**「記載不要なもの」と同一）。

**新テーマ**: 既存フォルダに足せない場合のみ **`社内業務/{テーマ}/`** または該当トップフォルダを新設（**`ノート分割の基準.md`** 参照）。

## 記録の横断ルール

- **1 つの事実が複数ノートに関係**する場合、**同一セッション内**ですべて更新する（例: 異動 → **`{フルネーム}.md`** ＋ 体制ノート ＋ 必要なら `課題.md`）。
- **正本は1箇所**、他は **`[[wikilink]]` 参照**で二重管理を避ける（例: 本人の資格・プロ認定 → **`Work/メンバー情報/長谷晃英.md`**、プロ認定申請資料はリンクのみ）。
- **訂正・撤回**があったら、Work 内の**古い記述も同セッションで整合**する（推測で残さない）。
- 記録先が不明なときは **`ネタ帳.md`** に日付付きで仮置きし、報告でユーザーに確認してもよい。

## 適用範囲（本職と副職の区別）

| 区分 | 内容 | 本 SKILL |
| --- | --- | --- |
| **本職** | **株式会社DTS** の業務（PL としての体制・メンバー・顧客案件・人事考課・社内手続き等） | **対象**（`Obsidian/Work/`） |
| **副職・趣味** | **FishTrack**・**MyPokedex**・**おたよりナビ** 等の個人プロダクト開発 | **対象外** |
| **副職・趣味** | **`Obsidian/DevProject/`**（仕様書・計画・ai_spec_check_report 等） | **対象外** |
| **副職・趣味** | 各プロダクトの **git リポジトリ**（`FishTrack/`・`MyPokedex/`・`otayori-navi/` 等） | **対象外** |

副職・趣味側の編集は、各リポの **`AGENTS.md`**・**`specification-update`**・製品別 SKILL を正とする。**本 SKILL は Read しない**（Work 配下に触れない限り）。

myrules を厳守する（**スクリプト一括置換禁止**・**報告前 CursorLog**・**document-creation-policy**）。

要約は同ディレクトリの **`AGENTS.md`** と整合させる（**`AGENTS.md` は Read の代替にならない**）。

## 発火条件（必須）

次のいずれかに当てはまるとき、**上記「必須の最初アクション」**（**`SKILL.md` を Read → 作業フロー）を実行する。

- **`D:/OneDrive/アプリ/remotely-save/Obsidian/Work/`** 配下の **`.md` / `.csv`** を **作成・更新・削除**する
- ユーザーが **`@Obsidian/Work`** または Work 内のパスを指定して依頼した
- **`mokuhyo-*`**・**`work-kadai-update`**・**`work-knowledge-deepen`** のいずれかが発火し、Work 配下を変更する

**対象外**（本 SKILL を Read しない）:

- **`CursorLog/`** のみの追記（Work 本体に触れない場合）
- **副職・趣味**（上記「適用範囲」）。`DevProject/`・製品リポのみの作業では本 SKILL は発火しない

## Work フォルダの原則

- **会社規約・正式文書（SharePoint 等）の写し**は載せない。正本は社内公式。**参照一行**で足りる（**`work-knowledge-deepen`**「記載不要なもの」と同一）。
- **1 回限り・記録不要**とユーザーが明示した情報は、依頼ファイルへの最小反映に留め、他ノートへ広げない。
- **機密**: Work は社外秘。会話・ログへの要約は最小限。外部検索・外部ツールへ送らない。

## 作業フロー（省略禁止）

### 0. 本 SKILL を Read（ゲート）

- **`SKILL.md` 全文**を Read してから次へ進む（**§ 必須の最初アクション**）

### 1. チャット情報の棚卸し

当該セッションでユーザーから得た次を**網羅的に**列挙する（依頼ファイル以外も含む）。**§ 収集対象**の大分類をチェックリストとして使う。

- **事実**（人・体制・数値・日程・資格・案件属性・顧客 FB・障害・異動）
- **合意・方針**（打ち手・優先度・エスカレーション・PL 決定・ユーザー訂正）
- **状況変化**（課題の進捗・解決・新規課題・役割変更・認定・採用）
- **手順・暗黙知**（「こう運用している」・用語の意味・連絡の型）
- **未整理**（記録先未定 → ネタ帳候補）

**ユーザーが「記録しないで」「チャットだけで」**と明示した項目は除外する。

### 1.5. 既存ノートの探索（推奨・記録漏れ防止）

依頼テーマに関連する Work 内ノートを **Glob / Grep / Read** で確認する。\
**同名・類似トピックの正本**が既にあれば追記先をそちらに寄せ、**新規ノートは最後の手段**とする。

### 2. 記録先の振り分け

下表に従い、**記録すべき情報ごと**に正本ノートを決める。複数ノートに跨る場合は**同一セッション内**ですべて反映する。

| 情報の種類 | 記録先（正本） | 併用 SKILL |
| --- | --- | --- |
| **本人（PL・長谷）**の属性・資格・認定・本人に紐づくメモ | **`Work/メンバー情報/長谷晃英.md`** | — |
| **配下プロパーメンバー**（属性・配置・経歴・通勤・休職・異動等） | **`Work/メンバー情報/{フルネーム}.md`**（正本）。**社員番号昇順**でノートを揃える | — |
| **客員（協力会社社員）** | **`Work/メンバー情報/{会社名}.md`**（正本。社内に配置されている者を会社ノート内に記載） | — |
| **資格取得・プロ認定**（各員） | **`Work/メンバー情報/{フルネーム}.md`** の当該節（本人は **`長谷晃英.md`**）。索引ファイルは持たない | — |
| **1on1**（実施記録・課題進捗等） | **Excel**（正本。パスは **[[1on1]]** に追記可） | — |
| **1on1・定例・振り返り**（運用方針・決定・Work 上のメモ） | `Work/定例・報告/` の該当ノート | — |
| **体制・役割・プロジェクト概要・ステークホルダ・DoD・エスカレーション・情報共有・開発ルール・変更管理** | `Work/体制・プロジェクト/` の該当ノート | — |
| **継続・未解決の業務課題**（財務・CS・育成・稼働・体制等） | `Work/課題.md` | **`work-kadai-update`** |
| **人事考課・目標・達成基準・設定時コメント・管理シート** | `Work/社内業務/人事考課/` | **`mokuhyo-*`** |
| **プロ認定・DCP・申請文案**（制度整理・転記ガイド・下書き） | `Work/社内業務/プロ認定/`（本人の資格**事実**は **`[[長谷晃英]]`**） | — |
| **採用・面接** | `Work/社内業務/{採用テーマ}/` | — |
| **社内手続き**（勤怠・経費・休出・備品・セキュリティ・オンボーディング等） | `Work/社内手続き/` | — |
| **顧客対応**（打合せ・障害・遅延・コミュニケーション） | `Work/顧客対応/` | — |
| **社内コミュニケーション**（連絡手段・チャネル使い分け） | `Work/社内コミュニケーション/` | — |
| **その他の社内業務**（上記に当てはまらないテーマ） | `Work/社内業務/{テーマ}/` | — |
| **用語・言い回し・社内の意味** | `Work/その他/用語集.md` | — |
| **暗黙知の体系化・深掘り**（依頼が深掘り系のとき） | テーマフォルダ内ノート | **`work-knowledge-deepen`** |
| **後で深掘りしたいネタ**（今回は未整理） | `Work/ネタ帳.md` | — |
| **記録先が一意に決まらない** | ユーザーに確認。暫定は `Work/ネタ帳.md` または `Work/その他/` | — |

**依頼で指定されたファイル**への反映に加え、上表の**別ノートにも書くべき情報があれば必ず追記**する（記録漏れ防止）。

### 3. ノート分割・新規作成

- 新規ノート・分割の前に **`Work/その他/ノート分割の基準.md`** を Read する。
- **既存ノートへの追記で足りるか**を先に検討する（**document-creation-policy**: ユーザー意図なく新規 `.md` を増やさない）。
- 新規ノートが必要なときは、**テーマに応じたサブフォルダ**に作成する。
- **`Work/メンバー情報/`**: **本人**は **`長谷晃英.md`**。**プロパー**は **`{フルネーム}.md`** が正本（**スペースなし**。例: `桐山光城.md`。**社員番号はノート内**）。**客員**は **`{会社名}.md`** が正本（個人別ノートは作らない）。**一覧用索引ファイルは持たない**（人数・構成の集計は **`所属・役割・プロジェクト概要`**）。

### 4. 編集の実施

- **myrules**: `StrReplace` / `Write` で**ブロック単位**。`replace_all` 禁止。
- **開示範囲**（単価・個人情報・評価・顧客非開示の障害等）に触れるときは、ノート内に **開示範囲** を明記する（**`work-knowledge-deepen`** と同趣旨）。
- **日付**: 新規記載は **`datetime-jst`** で JST 実日付を取得する。課題ブロックの **最終更新** 等は各専用 SKILL に従う。

### 5. 検証とログ

1. Work 内 `.md` を編集したら **`markdownlint-fix` SKILL** で当該ファイルの lint を解消する。
2. **`obsidian-cursor-log` SKILL** で CursorLog を更新する（変更ファイル・記録したノート一覧を含める）。
3. ユーザー報告に **「CursorLogは更新しました」** を含める。

## 報告時に含めること（推奨）

- **記録したノート**のパス（依頼先以外に追記した場合は**明示**）
- **記録しなかった**チャット情報があり、理由（ユーザー明示・規約正本・重複・要確認）

## 典型パターン

| パターン | 動作 |
| --- | --- |
| ユーザーがメンバーの異動を伝えつつ `課題.md` 更新を依頼 | `課題.md` は **`work-kadai-update`**。あわせて **`Work/メンバー情報/{フルネーム}.md`**（または体制ノート）へ異動を記録 |
| 定例会のメモ整理依頼＋チャットで顧客 FB | `定例・報告/` にメモ。未解決課題は **`課題.md`** へ **`work-kadai-update`** |
| 目標下書きセッション | **`mokuhyo-draft`** が主。確定した課題は **`work-kadai-update`** で `課題.md` へ**報告前**同期 |
| プロ認定・本人／配下の資格・認定の事実 | **本人** → **`Work/メンバー情報/長谷晃英.md`**。**配下** → **`{フルネーム}.md`**（未作成時は新規作成）。`プロ認定_参考資料_*` 等は **[[長谷晃英]] 参照**。申請用下書きだけに書いて終えない |
| ユーザーが Work 以外の話も混ぜて業務情報を伝えた | **依頼の主題に限らず § 収集対象**を棚卸しし、該当する正本へ追記 |
| チャットで訂正（「以前の記載は誤り」） | **正本＋参照している依頼ファイル**を同セッションで整合 |
| 規約に既にある手順の確認 | Work へ写さない。参照のみ |

## 注意事項

- **Read 省略**は**記録漏れ・振り分け誤り**の典型原因。ユーザーが「Work 編集時は必ず Read」と指示した場合は **§ 必須の最初アクション** を同一セッションで再確認する
- **チャットにだけ残す**のは禁止（ユーザーが記録不要と明示した場合を除く）。
- **推測で補完しない**。ユーザー発言・既存ノート・Read した正本だけを根拠にする。
- **メンバー資格表**: **取得済み・申請予定・取得目標**のみ記載。**未保有**の資格行は書かない（ユーザー明示時を除く）。登録正本の注記は **育成カルテ・Accel-Mart** のみ（**RinG** は記載しない）。
