# mokuhyo-hojo-setteiji-comment（設定時コメント・補助・１次調整者）

**`人事考課_管理シート.md`** の**最新期**について、**長谷　晃英以外**の全メンバー各枝番の **`##### 設定時コメント(補助・１次調整者)`** 本文を**生成して反映**する。

**執筆者視点**は **1 次調整者（補助・長谷）**。本人目標・設定理由への**補足・期待・留意点**を書く。**本人が書く 12 項目**（通期目標等）・**達成状況コメント**・**長谷本人の枝番**は本 SKILL の対象外。

**執筆者の立場（プロジェクトリーダー・PM）**: 長谷は **2021 年にプロジェクトリーダー（PL）就任**したプロジェクトマネージャー。弊社では PM を **プロジェクトリーダー（PL）** と呼称する。設定時コメントは **1 次調整者**としての補助であると同時に、**PL としての立場・経験・知識**に基づく見立てを意識して書く（詳細は下記「**PL・PM としてのコメント**」）。

**`mokuhyo-draft`**（本人目標下書き）・**`mokuhyo-proofread`**（校閲・`<改善案>`）・**`mokuhyo-excel-to-markdown`**（Excel 同期）とは**別 SKILL**。

myrules を厳守（**スクリプト一括置換禁止**・**報告前 CursorLog**・**Markdown は編集ツールでブロック単位**）。

**最初の作業（毎回必須）**: **本ファイル `SKILL.md` を全文 Read** してから着手する。\
会話要約・過去セッションの生成結果・**`AGENTS.md` のみ**を SKILL の代わりにしない（**SKILL は更新されうる**ため、**実行時点の本文が正本**）。

## 対象範囲（必須）

1. 管理シート内 **`## {数字}期`** の**期番号最大**を対象期とする（例: `## 55期`）。
2. ユーザーが**別期を明示**したときのみ、その期を対象とする。

### メンバー

- 対象期の **`### {期} {氏名}`** のうち、**氏名が「長谷　晃英」でないもの**を**すべて**対象とする。

## 文体・内容（生成方針）

### PL・PM としてのコメント（必須・執筆者の専門性）

**長谷（補助・１次調整者）** は、日々 **プロジェクトリーダー（PL）** として案件を牽引する立場にある。コメントは **人事の総論**や **本人目標の要約**ではなく、**PL が現場で見ている観点**から付加価値を出す。

| PL・PM として意識する観点 | コメントに活かし方（例。写しではない） |
| --- | --- |
| **プロジェクト全体** | 個別作業の先に、**案件の状況把握**・**全体の流れ**・**目的の置き方**（「〇〇作業そのもの」ではなく「プロジェクト全体の把握」等、54 期長谷の論点） |
| **役割・引継ぎ・負荷** | 上位者業務の引継ぎ、見える化、**独力で回す**ためのスキル（コミュニケーション、判断の背景の共有） |
| **進捗・品質・リスク** | 遅延の兆候、確認のタイミング、**試すだけで終わらせない**、一覧化と**実際の運用**の差 |
| **ステークホルダ・周囲** | チーム内だけでなく **組織横断**の共有、顧客・他チームへの報告・障害・納品物の文脈 |
| **育成・任せ方** | 同行・フィードバックの順序、**任される範囲の広げ方**（キャリア接続と整合） |

- **目標ジャンル**（案件管理・品質・育成・組織貢献 等）に応じ、上表のうち **当該目標に関係する 1〜2 観点**を選んで書く（**全観点を毎枝番で列挙しない**）。
- **創作禁止**は維持する。案件名・数値・手順は **当該枝番の本人目標・設定理由・達成基準・N−1 期コメント**、および **`課題.md` に記載の事実**（当該枝番と**関連が取れる**ブロックに限る）から導ける範囲に限る。
- **本人記載の繰り返し禁止**と両立: PL 視点は **本人欄に無い角度**（全体像、つまずきやすい運用、引継ぎの意図）で示す。**本人の行動リストの復唱**はしない。
- **アドバイス要素**を書くときは、**PL としての進め方・順序・つまずき**を優先する（**SKILL**「アドバイス要素」）。
- **文案作成時の自問**: 「**PL ではなく、誰が書ってもよい一般論**になっていないか？」→ なっていれば、**プロジェクト・組織・昨期事実**に寄せて差し替える。

### 参考に Read するもの（優先順）

1. **対象期・当該枝番**に**既存**の **設定時コメント(補助・１次調整者)** 全文（**あれば最優先で Read**。意図・論点・言い回しを踏まえつつ、本 SKILL に沿って**再生成**）
2. **対象期・当該枝番**の **通期目標**・**上期目標**・**設定理由（本人）**・**目標ジャンル**（`####` 直下）— 過去コメントとの突合の**基準**
3. **対象期より前**の **設定時コメント(補助・１次調整者)** 全文（**同一メンバーに限定しない**。他メンバー・他目標ブロックも Read してよい。直前期（N−1 期）だけに限定しない）
   - **枝番番号は記載順のラベル**（`#### … 1` `2` …）であり、過去コメントとの**突合・優先付けに一切用いない**（期をまたいで枝番が入れ替わることもある）
   - **論点・内容**を活かすときの優先（**Read は広く実施**し、文案では次の重み付け）:
     1. **同一メンバー**かつ **同一目標ジャンル** — 当該目標と目標ジャンルが一致する過去の目標ブロック（**期は新しい順**）
     2. **他メンバー**でも **同一目標ジャンル**（**期は新しい順**）
     3. **目標ジャンル・通期目標のテーマが近い**目標ブロック
   - **文体・段落構成・署名形式**は **直近を優先** — **対象期の N−1 期**の **`（補助・長谷）` 付き**記載を第一に Read し、なければ管理シート上**期番号が最大**の長谷記載を正とする（**同一メンバーでなくてもよい**）
4. 任意: **当該メンバー**の**対象期より前**各期の **上期達成状況コメント(本人)**（背景・課題の把握。**本人目標の理解用**。直前期に限定しない）
5. **推奨**: **`Work/課題.md`**（**セッション冒頭で Read**。空でも確認。詳細は下記「**`課題.md`（参照のみ）**」）

## `課題.md`（参照のみ）

**`Work/課題.md`** は**現時点の継続・未解決業務課題**の管理正本（**`work-kadai-update` SKILL**）。**本 SKILL**では、設定時コメントの**組織・プロジェクト・PL 文脈**を補う**参考資料**として **Read してよい**（ユーザーが `@課題.md` を示した場合も同様）。

| 項目 | ルール |
| --- | --- |
| **Read** | **セッション冒頭**に **1 回** Read する（**推奨**。枝番ごとに毎回全文 Read は不要） |
| **突合** | 各枝番で **目標ジャンル**・**通期目標のテーマ**・**氏名**（次期案件L・次期L育成等）と、`課題.md` の **`### {カテゴリ}-…`** を対応づける（**課題正本に枝番紐づけは載せない**ため、**エージェントが判断**） |
| **活かし方** | **PL 視点**で、当該目標が**組織課題のどこに効くか**・**未解決の文脈で何を意識すべきか**を **1 フレーズ程度**で織り込む（**打ち手・数値の復唱**はしない） |
| **優先** | **対象期の本人目標・設定理由**と矛盾する場合は**目標を正**とし、矛盾が大きいときは**ユーザーに確認** |
| **管理シート** | 設定時コメント本文に **課題 ID**（`財務-01` 等）や **`課題.md` の見出し**は**書かない** |
| **編集** | **`課題.md` の追記・更新・削除は禁止**（**`work-kadai-update` SKILL** が正本） |

- **`mokuhyo-draft`** と同様、課題は**目標の材料**であり、設定時コメントは**長谷の見立て**である。課題ブロックの**要約だけ**を書くのは**本人記載の繰り返し禁止**に近いため避ける。
- **一括生成・報告**時、関連が明確な枝番があれば、チャットで **「参照した課題ブロック（タイトルのみ）」** を**任意で**短く示してよい（**必須ではない**）。

### 書き方

- **長谷（1 次調整者）の口調**に合わせる（**です／ます**・**してください／お願いします／努めてください／意識してください** 等）。**文体・段落構成**は **直近期**（優先: 対象期 N−1 期）の **`（補助・長谷）` 付き**記載を正とする（**同一メンバーでなくてもよい**）。
- **過去コメントのベースライン**: **対象期より前**の設定時コメント（**同一メンバーに限らない**。論点は **同一目標ジャンル**優先、文体は **直近**優先）は、**論点・構成・PL 視点の土台**として**積極的に参照してよい**。
- **対象期への更新は必須**: ベースラインを使っても、**対象期の通期目標・設定理由・体制変化・各期実績**に合わせ**文言・具体を書き換える**。**前年文・他メンバー文の無変更複写**はしない。
- **既存本文の再生成**: 対象期に**既に設定時コメントがある**枝番も**省略せず再生成して差し替える**。既存文も**ベースラインの一つ**として読み、**そのまま残す・無変更複写はしない**。
- **最新 SKILL の反映（再生成時必須）**: 既存コメントは**以前の生成時点の SKILL** で書かれていることがある。**再生成の合否は実行時点の本 `SKILL.md` の規定**で判断する。既存文の形式・署名・段落数・禁止事項が現行 SKILL と食い違う場合は、**既存に合わせず SKILL に合わせて書き直す**。
  - 末尾 **`（補助・長谷）`**（旧 **`（長谷）`**・**`[氏名]`** 等は **`（補助・長谷）`** に統一）
  - 当該枝番の**最新**の通期目標・設定理由との整合
  - **本 SKILL 現行版**の「署名・文末」「書き方」「禁止事項」（54 期以降の長谷口調・**字数目安**を含む）
- **字数（目安）**: **`（補助・長谷）` を含むコメント全体**を**おおむね100文字程度**とする。**1段落**が基本（54期長谷記載に準拠）。重要度に応じて**80〜120文字**程度まで可。**150文字を大幅に超える冗長文**は避け、論点は絞る。
- **内容**: 目標の背景、**PL としての**プロジェクト／組織上の文脈、期待する姿勢、昨期からの継続・変化、本人目標への補足（**「PL・PM としてのコメント」**参照）。
- **禁止**: 「AI が生成」「下書きです」等のメタ文、本人の口調での記載、**タスク番号**（Fxx 等）。

### トーンのバランス（必須・成長・ポジションアップ）

**現状の課題への改善期待だけ**に偏ったコメントは**不可**。各枝番に**ポジティブな要素**（**将来の成長**・**担える役割**・**ポジションアップ／等級に見合った期待**）を**必ず**含める。

| 要素 | 書き方 |
| --- | --- |
| **肯定・期待** | 目標の意義、組織・プロジェクト上の位置づけ、**この取り組みで身につく力・経験** |
| **留意・具体** | 達成のために意識してほしい行動・プロセス（**戒め・欠点の指摘だけ**にしない） |
| **アドバイス**（適宜） | 内容に応じて、長谷としての**進め方・コツ・順序・つまずきやすい点**を書いてよい。目標・達成基準・設定理由から取れる**具体**に限定（創作しない）。**毎枝番で無理に入れない** |
| **キャリア接続**（推奨） | 今期の達成が**次の役割・業務範囲・信頼**につながるイメージ（**断定しすぎない**。「〜の土台になる」「〜を任せられる状態を目指してほしい」程度） |

- **`###` 直下の等級（G1〜G4）**と**通期目標・設定理由**を Read し、**今期目標が本人のキャリア上どうつながるか**を**1文以上**で示す（例: G1→自律遂行の確立、G2→サブリーダー／リーダー候補、G3→案件・チームを牽引する側）。
- **昨期の事象・課題**に触れるときは、**改善の指示だけで終えない**。同じコメント内で**前向きな到達像**（信頼の積み上げ、任される範囲の拡大、スキルの定着）を**必ず**書く。
- **避ける偏り**: 失敗・欠点・注意喚起**のみ**の段落構成。「〜しなかった」「〜を防ぐ」だけが並ぶ文（**対置**として**何を伸ばすか**を書く）。
- **54期・他メンバー過去コメント**が戒め調に偏っていても、**口調・段落構成は直近長谷記載**に合わせつつ、**内容のポジティブ比率**は**本節を優先**する。
- **文案作成時の自問**: 「このコメントだけ読むと、**課題の改善を求めているだけ**に見えないか？」→ そうなら**成長・ポジションアップ**の一文を足す。

### アドバイス要素（適宜・1 次調整者としての助言）

**必須ではない**。期待・文脈・留意だけで足りる枝番では**書かなくてよい**。書くときは、**PL としてどう進めるとよいか**を長谷の **PM／PL 経験**・案件文脈から**短く**示す（**54 期長谷**の「〜するとよい」「〜から始める」「〜も意識してみてください」等に近い言い方）。

| 含めるとよいアドバイス | 例（目標に合わせて言い換え。写しではない） |
| --- | --- |
| **進め方・順序** | 「まずチーム内の表から」「研修と過去案件の分析をセットで」 |
| **運用のコツ** | 「担当未設定はその場で決め切る」「更新タイミングを固定する」 |
| **つまずきやすい点** | 「一覧に載せるだけでは進まない」「試すだけで終わらせない」 |
| **相談・確認のタイミング** | 「遅延の兆候が見えたら対応案を添えて早めに」「実装前に確認」 |

- **目標・設定理由・達成基準**に無い手順や数値は**書かない**（**創作禁止**）。**N−1 期の長谷コメント**や**当該枝番の本人目標**から導ける範囲に留める。
- **アドバイスを書く場合**、戒めの言い換えだけにしない（「〜しないこと」だけなら、**前向きな進め方**を足す）。
- **文案作成時の自問**: 助言を入れるなら、**本人の目標欄の繰り返しになっていないか**？ 入れないなら、**期待・文脈・成長**だけで足りているか？

### 本人記載の繰り返し禁止（必須）

**通期目標・上期目標・達成基準・設定理由（本人）・行動内容**に書いてあることを、**言い換えて要約し直すだけ**の文は**不要**（読者にとって**付加価値がない**）。

| 避ける | 代わりに書く |
| --- | --- |
| 本人の**行動・達成基準・数値**の言い換え（「週次棚卸」「日次記録」「〇件以上」等） | **PL としての**見立て・経験・案件文脈、**進め方のアドバイス**、**つまずきやすい点** |
| 本人の**設定理由の再掲**（「〜のため設定」→「〜が重要」） | **昨期・組織・プロジェクト**側の文脈、**なぜその目標に期待するか**（本人文と**別角度**） |
| **通期目標の手順の復唱**（「ヒアリング→確認→展開」を並べるだけ） | 手順の**どこで詰まりやすいか**、**コツ・順序の助言** |

- **触れてよい**: 本人文に**無い**具体（例: 昨期の**ST検知**、**RVで詰まった論点**、**個人情報の確認**）— **創作禁止**。目標・達成状況・N−1 期コメント、および**当該枝番と関連する `課題.md` の記載**から**導ける事実**に限る。
- **短く触れる程度は可**: 昨期事象を**1 フレーズ**だけ参照し、直後は**付加価値のある一文**（必要なら助言）に移る（事象の説明を**伸ばさない**）。
- **文案作成時の自問**: 「設定時コメントを読まなくても、**本人の目標欄だけで同じことが分かる**文になっていないか？」→ なっていれば**削るか差し替え**。

### 長谷文体・AI 痕跡の排除（必須）

**第三者（本人・人事）が読んでも、長谷が書いた補助コメント**に見えること。**生成 AI の定型・テンプレ感**は禁止（**`mokuhyo-draft` SKILL**「本人の文体・AI 痕跡の禁止」の趣旨を、**長谷（1 次調整者）の過去記載**に当てはめる）。

| 揃える（正本） | 具体 |
| --- | --- |
| **文体** | **対象期 N−1 期**の **`（補助・長谷）` 付き**設定時コメント（**同一メンバーでなくても可**）。「〜と思います」「〜かと思います」「〜と考えています」等、**長谷に既にある**言い回し |
| **文脈** | **案件名・チーム・昨期の事実**など、目標・設定理由から取れる**具体**（創作しない） |
| **段落** | **1段落**を基本（**字数目安**参照）。過去が**2 段落**の長谷記載のみ、改行を入れてよい。**箇条書き・番号リストの新設**はしない |

**避ける表現（AI っぽさ・17 件で同型になりやすいもの）**:

- **毎枝番同型の二文構造**（「〜です／ます。〜してください。」の機械的な連続だけ）
- **抽象ラベルの連打**（「G1 として」「G3 像」「ポジションアップの土台」「組織貢献度」「差別化」「直結します」「〜につながります」の**乱用**）
- **説教・総論調**（「〜が重要です」「本質的に」「フォーカス領域として期待が高く」）
- **等級を本文に明示しすぎる**（必要なら「リーダー」「サブリーダー」等、**54 期長谷記載に合わせた**言い方）
- **接続詞・文末の統一しすぎ**（全件「取り組んでください」で終わる等）

**自然さの確認（各枝番・反映前）**:

1. **N−1 期の長谷設定時コメント**（可能なら**同一目標ジャンル**）と並べ、**同一人物の続き**に見えるか
2. **字数**が**おおむね100文字程度**（**80〜120文字**）に収まっているか（**150文字超**なら削る・論点を絞る）
3. **ポジティブ要素**は残しつつ、**キャリア接続は断定しすぎない**（「〜かもしれません」「〜と思います」は長谷文体として可）
4. **「PL・PM としてのコメント」**・**「トーンのバランス」**・**「アドバイス要素」**・**本節**の自問を満たすか

### 既存本文がある場合（既定）

- **空欄**（見出し直下が空）→ **新規生成して反映**。
- **既に本文あり**→ **既存内容を Read したうえで、実行時点の最新 SKILL に沿った形で再生成し、当該 `#####` 本文を差し替える**（**上書き省略は禁止**）。
- 再生成で**意図・論点は可能な限り継承**し、**形式・署名・段落・禁止事項・目標との整合・表現の陳腐化**は**現行 SKILL に従い**必ず更新する。
- **既存文が現行 SKILL と矛盾**していても、**既存を正としない**（例: 旧署名 `（長谷）`、段落構成の逸脱、メタ文）。**SKILL 更新後の初回再生成**も同じ扱い。

### 再生成しない例外

- ユーザーが **「この枝番は触らない」「既存のまま」** と**明示**した枝番のみスキップ。
- **`### … 長谷　晃英`** 配下は従来どおり対象外。

## 作業フロー

### 0. 前提確認

- **本 `SKILL.md` を全文 Read**（再生成・新規いずれも。SKILL 更新反映のため**毎セッション必須**）。
- 対象期・**長谷以外**のメンバー一覧（`###`）と各枝番数を確定する。
- **`Work/課題.md`** を **Read**（**推奨**・空でも確認。本 SKILL「**`課題.md`（参照のみ）**」）。

### 1. Read

- 対象期・各メンバー各枝番の **通期目標**・**設定理由（本人）**・**目標ジャンル**。
- **`課題.md`** を Read 済みなら、枝番ごとに**関連ブロック**を意識して突合する（**丸写ししない**）。
- 各 **メンバー × 枝番** について:
  - **対象期の既存設定時コメント**（あれば・**論点参考のみ**）
  - **対象期より前**の **設定時コメント(補助・１次調整者)**（**同一メンバーに限定しない**。**枝番番号は突合に使わない**。論点は **同一目標ジャンル**優先、**文体・構成は直近**（N−1 期等）の長谷記載を優先）
- 過去コメントを Read したら、**現行 SKILL のチェック**（署名・**字数目安**・禁止事項）に照らし、**差分があれば SKILL 側に合わせて再生成**する。

### 2. 文案作成（メモ）

- 枝番ごとにコメント案を作成。**最終行が `（補助・長谷）` で終わる**こと、**全体がおおむね100文字程度**であることを確認。
- **「PL・PM としてのコメント」**・**「トーンのバランス」**・**「アドバイス要素」**・**「本人記載の繰り返し禁止」**・**「長谷文体・AI 痕跡の排除」**の自問を**各枝番で実施**する。
- チャットで一覧提示してよい（ユーザー確認を求める場合）。

### 3. 反映

- **`##### 設定時コメント(補助・１次調整者) — {対象期} …`** 単位で **`StrReplace` / `Write`**（**`replace_all` 禁止**）。
- 追記順序: **ファイル末尾のメンバーから逆順**、または **枝番・項目の出現順**（衝突回避）。

### 4. 検証

- 対象期・**長谷以外**のみ diff があること。
- 更新した各ブロックの**最終行**が **`（補助・長谷）`** で終わること。
- 各コメントが**字数目安**（**おおむね100文字**・**150文字超**は要見直し）を満たすこと。
- **`markdownlint-fix` SKILL** に従い **`人事考課_管理シート.md`** の lint を解消。

### 5. 報告（チャット）

| 項目 | 内容 |
| --- | --- |
| 対象期 | 期番号 |
| メンバー | 反映した氏名一覧（**長谷は対象外**と明記） |
| 枝番数 | 反映（新規／再生成）した **設定時コメント** 件数 |
| スキップ | ユーザー明示で触らない枝番、**長谷本人** のみ |

### 6. CursorLog

- **`obsidian-cursor-log` SKILL** に従い追記。

## 禁止事項

- **長谷　晃英** の **設定時コメント** の生成・編集
- **本人 12 項目**・**達成状況コメント**・**`<改善案>`** の変更
- **対象期より前**の期の編集
- 署名 **`（長谷）`** の使用（**`（補助・長谷）`** に統一）
- **スクリプト**による一括置換・一括生成
- **過去の設定時コメント**または**対象期既存文**の**無変更複写**（**ベースラインとして参照は可**。対象期への更新・再生成は必須）
- **枝番番号**による過去コメントの選別・優先付け（**記載順ラベル**であり突合基準にしない）
- **以前の生成結果・既存文の形式**を理由に、**現行 SKILL の署名・文体・禁止事項を省略**すること
- **課題改善・戒めのみ**で終わるコメント（**成長・ポジションアップ・ポジティブ要素**が無いもの）
- **AI 定型・テンプレ感**のコメント（**本 SKILL「長谷文体・AI 痕跡の排除」**に反するもの）
- **字数目安の大幅超過**（**150文字超**の冗長文。**おおむね100文字**を目安に論点を絞る）
- **本人目標の言い換え・要約だけ**のコメント（**本 SKILL「本人記載の繰り返し禁止」**に反するもの）
- **PL・PM 視点のない一般論だけ**のコメント（**本 SKILL「PL・PM としてのコメント」**に反するもの）
- **`課題.md`** の編集（**`work-kadai-update` SKILL** に委ねる）
- **`課題.md` ブロックの打ち手・本文の復唱だけ**のコメント（**PL 視点の付加価値**が無いもの）
