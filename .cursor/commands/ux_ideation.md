# UX 改善アイデア検討

myrules を厳守して作業してください。**品質メトリクス（テスト・カバレッジ等）は対象外**。

## 目的（ビジネス寄りのゴール）

本コマンドで扱うアイデアの**主目的**は次の連鎖を狙うことである。

1. **プロジェクトの価値向上**（ユーザーにとっての有用性・信頼・継続利用のしやすさなど）
2. それに伴う **アクセス数・会員数（利用者数）の向上**
3. さらに **利益の拡大**（収益モデルに照らし、売上・LTV・コスト構造などへの効き方を意識する）

体験・画面の快適さだけでなく、**上記にどう効くか**を返信で意識して書く。数値目標の捏造はしない（**仮説・要確認**で足りない情報を明示する）。

**正本は本コマンド（このファイル）のみ。** 個別スクリプトは置かない。

## 全プロダクトを参考にする（必須）

アイデア出しでは、次の **3 プロダクトすべて**の仕様と `AGENTS.md` を **読んだうえで**考察する（myrules **「仕様書探索の既定パス」** に準拠）。\
フォルダ型は **`INDEX.md`** を起点にし、必要に応じて概要・機能・UI 等の分割ファイルを読む。

| **MyPokedex** | `D:/OneDrive/アプリ/remotely-save/Obsidian/DevProject/specifications/MyPokedex/INDEX.md` | `D:/OneDrive/git_work/MyPokedex/AGENTS.md` |

- **検討対象が一つに絞られていても**、他 2 つから **転用できる UX・獲得・収益・信頼の示唆**を返信に含める（無理な横並びはしない）。
- ユーザーが **特定プロダクトのみ**と明示した場合は **主軸をそこ**に置き、他 2 つは **簡潔に参考**として触れる。
- 返信の **根拠** に、参照した仕様パスに加え、**どのプロダクトの知見をどう活かしたか**が分かるようにする。

## 出力の場所（必須）

**内容は必ずこのチャットの返信として書く。**\
**固定の出力テンプレや章立ては定めない**（体裁はエージェントが読みやすく選ぶ）。\
ツールでワークスペースに `.md` を新規作成したり、ファイルへ追記したりしない。

## エージェント向け手順（仕様・実装に基づき単独で検討）

**ユーザーに箇条書きで聞き取りするのではなく、AI が仕様とコードを読み、アイデアを具体化してから返す。**\
不足は推測では補わず、**仕様・実装に根拠が薄い箇所は「仮説」「要確認」と明記**する。

1. **対象の把握**\
   会話・開いているファイル・`@` 参照から **検討対象**を決める。**プロダクト名に限定しない**（機能・導線・画面群・リポジトリ・複数プロダクト横断など、文脈で定める）。\
   判別できないときだけ、**1 行で**ユーザーに確認する。

2. **根拠の収集（必須・Read / 検索）**\
   上記 **「全プロダクトを参考にする」** を先に満たす。\
   続けて **検討対象**に応じた **実装**を追う（**ルート・画面テンプレ・フロントの JS・フォーム** など。**SemanticSearch** や **Read** を使う）。\
   検討対象が横断や未指定のときは、三リポジトリのうち **文脈に効く箇所**に絞ってコードを読んでもよい。

3. **単独で返信にまとめる**\
   **チャット返信 1 本**で、仕様・実装に基づく UX 改善の考察を書く。**空枠や「後で埋める」だけの返答はしない。**\
   次は **内容として含める**（見出し名・順序・表の有無は自由）:
   - **根拠**: 読んだ **仕様・`AGENTS.md`・コード**（パスやファイル名を簡潔に）
   - **ユーザー文脈・摩擦**: 仕様・実装から読み取れる困り・機会
   - **改善案**: 具体性のあるアイデア（抽象一行で終わらせない）。**価値向上・流入・会員獲得・収益**のどこに効きうかを、無理のない範囲で一行添える
   - **優先の目安**: 手堅く試せそうなもの、**事業インパクト**が大きそうなものなど、**主観でよい**が理由を一言添える
   - **仮説・要確認**: 根拠が薄い点

4. **禁止・注意**\
   **断定やデータの捏造はしない。** アクセスログや利用実態が無い数値は書かない。\
   **勝手にプロジェクト配下へ新規ドキュメントを作らない**（myrules「ドキュメント作成規律」）。\
   チャット外への保存はユーザーに委ねる。

## Cursorログ更新（必須）

**dev-workspace の本コマンド定義を変更した場合**も CursorLog を更新する（タグ例: `#ux-ideation` `#dev-workspace`）。
