## 📋 概要

FishTrackとMyPokedexの両方に、新規ユーザー数（日次通知）とアクティブユーザー数（週次通知）を管理者宛にメール通知する機能を実装します。既存のエラーログ通知機能（`error_notifier.py`）と同様のAWS SNS経由の仕組みを活用します。

## 🎯 実装範囲

| 項目 | 内容 |
|------|------|
| **対象プロジェクト** | FishTrack、MyPokedex |
| **通知頻度** | 新規ユーザー数: 日次（毎日朝10時）<br>アクティブユーザー数: 週次（毎週月曜日朝10時） |
| **通知内容** | 新規ユーザー数: 直近30日間の日次推移を含む<br>アクティブユーザー数: 直近12週間の週次推移を含む |
| **データ保存** | 統計履歴テーブル（`user_statistics_daily`, `user_statistics_weekly`）に全量データを保持 |

### フェーズ3: 通知機能実装

#### 3-1: 統計集計ロジック実装 ✅

**状態**: 完了  
**対象**: MyPokedex、FishTrack  
**依存**: 1-3  
**優先度**: 中

**方針**:
- 初回の実行から定時実行と同じロジックを使用
- 日次・週次の集計メソッドを定時実行から呼び出す

**実装内容**:
- ✅ **MyPokedex**: `src/mypokedex/utils/user_statistics.py`を作成
- ✅ **FishTrack**: `src/fishtrack/utils/user_statistics.py`を作成

**主要関数**:
- `update_daily_statistics(target_date)`: 日次統計を更新（前日または指定日）
- `update_weekly_statistics(target_week_start)`: 週次統計を更新（前週または指定週）
- `get_daily_statistics_history(days)`: 日次統計の履歴を取得（通知メッセージ用）
- `get_weekly_statistics_history(weeks)`: 週次統計の履歴を取得（通知メッセージ用）
- `get_week_start(d)`: 週の開始日（月曜日）を計算

**特徴**:
- 既存レコードが存在する場合はスキップ（重複投入を防止）
- 0件でも記録（統計の完全性を保つため）
- タイムゾーン処理: JST（UTC+9）を使用
- トランザクション内で実行（エラー時はロールバック）

## 🔧 技術的な考慮事項

### スケジューラーの実装方法

- **BackgroundScheduler**: gunicornワーカー内でバックグラウンドスレッドとして動作
- **タイムゾーン**: JST（Asia/Tokyo）を使用
- **重複実行防止**: 複数ワーカーで実行される可能性があるため、通知頻度制御（同一日/同一週に1回のみ）を実装

### データベースクエリ

**新規ユーザー数（現在値）**:
- `user_statistics_daily`テーブルから最新の1日のデータを取得
- または、ユーザーテーブルからリアルタイム集計

**新規ユーザー数（推移）**:
- `user_statistics_daily`テーブルから全期間のデータを取得
- 通知メッセージ用: 直近30日間のみフィルタリング

**アクティブユーザー数（現在値）**:
- ユーザーテーブルから`WHERE last_login_at >= CURRENT_DATE - INTERVAL '7 days'`で集計
- `COUNT(DISTINCT user_id)`で集計

**アクティブユーザー数（推移）**:
- `user_statistics_weekly`テーブルから全期間のデータを取得
- 通知メッセージ用: 直近12週間のみフィルタリング

### 統計データ更新ロジック

**日次統計の更新**:
- 毎日指定時刻（デフォルト: 午前10時 JST）に実行
- 前日の新規ユーザー数を集計: `COUNT(*) WHERE DATE(created_at) = CURRENT_DATE - INTERVAL '1 day'`
- `user_statistics_daily`テーブルに保存（既に存在する場合はスキップ）

**週次統計の更新**:
- 毎週月曜日指定時刻（デフォルト: 午前10時 JST）に実行
- 前週（月曜日〜日曜日）のアクティブユーザー数を集計: `COUNT(DISTINCT user_id) WHERE last_login_at >= week_start AND last_login_at < week_start + INTERVAL '7 days'`
- `user_statistics_weekly`テーブルに保存（既に存在する場合はスキップ）

### 週の開始日（week_start）の計算ロジック

**PostgreSQL**: `DATE_TRUNC('week', date)`は月曜日を週の開始日とする

**Python**:
```python
from datetime import date, timedelta

def get_week_start(d: date) -> date:
    # 月曜日=0, 日曜日=6
    days_since_monday = d.weekday()
    return d - timedelta(days=days_since_monday)
```

### エラーハンドリング

- SNS送信失敗時はログに記録するが、アプリケーションの動作には影響を与えない
- 統計集計時のデータベースエラーも同様に処理
- 集計ジョブが失敗した場合でも、次回実行時に再集計可能
